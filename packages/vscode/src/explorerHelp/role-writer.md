# Writer workflow

Use source-grounded evidence to explain behavior, update documentation or compare specifications. Search Only suits exact text and quotation lookup. Choose Agent Lean or richer detail when you need requirement, decision, acceptance, section or table facts; consider Rich Structure for broader inventories. Use the Document types guide before trusting PDF/Office extraction.

## Steps

1. Identify the audience, purpose and source formats. Separate current implementation from proposals, historical release notes and superseded decisions; an indexed document is not proof that a feature shipped.
2. Check the project publication and extraction coverage. Search exact terminology lexically; try vector/hybrid for related concepts only when the local model and selected vectors are ready.
3. Use Documents > Facts to locate headings, requirements, decisions or table records. Verify original page, slide, worksheet/row and source hash. OCR-derived text and spreadsheet caches need explicit limitations.
4. Cross-check claims about behavior with Code > Symbols, Outline and cited implementation excerpts. Native syntax facts and candidate relationships do not provide complete language understanding.
5. Use a currently Runnable component-explanation strategy, or prepare a manual Planner task with audience, outline, evidence, terminology and acceptance checks. Review the full prompt before sharing it; source text can contain confidential data or hostile instructions.
6. Run the agent in its own environment. Check returned path:line citations with Evidence > Checker and inspect the originals. The user reviews prose, preserves source attributions and decides when to save or publish.

## Limits

AIRK does not write or publish documentation automatically. Similarity is a discovery aid, not factual support. A complete quotation must retain its original document location; extracted line numbers must not be presented as printed page line numbers.
