# Strategy Planner

Strategies › Planner combines Studio snapshots and manual tasks into one Markdown plan with YAML front matter (schema airk.explorer.plan/1). A coding agent follows it one task at a time; the Explorer never runs the agent.

Task states are Draft, Ready, Exported, Review, Needs work and Completed. Blocked is derived from incomplete predecessors and Stale from evidence on an older publication; neither can be chosen by hand. Copying a handoff prompt marks a task Exported, never Completed, and Completed asks for confirmation.

## Steps

1. Choose **New plan**, or **Add to Planner** in Studio to add the current strategy and its prompt as a task.
2. Add manual tasks, edit instructions and tick dependencies. Cycles are refused.
3. Choose **Save in workspace…**. The save dialog opens in the airk.explorer.planner.directory folder (default .airk/plans) and is the consent to write; the file must stay inside the workspace folder, unsaved editor copies are never overwritten and replacing an existing file asks first.
4. After the save is confirmed, pick a task and choose **Copy handoff prompt**.
5. Or choose **Share snapshot with agent** for that eligible task, confirm the complete text and give its expiring token to the agent. The task instructions accompany the handoff prompt; no task execution or completion is implied. Read Share a reviewed snapshot for expiry, revocation and byte limits.
6. When the agent reports back, paste the report into **Completion check**, review the citation results and set the task to Review, Needs work or Completed.

**Open as draft** opens the Markdown as an untitled document without saving it. Editing the plan after saving requires saving again before the next handoff.

Guarded saving supports local filesystem folders only. Redirected directories, linked targets, changed targets and unsaved editor copies are refused. For remote folders use Open as draft and the editor Save command. Studio snapshots must fit 8,000 characters in full; reduce evidence explicitly if needed. Nothing is silently truncated. Plans from another project and tasks with stale evidence cannot be handed off.

## Load and resume a local plan

**Load plan…** opens the file picker in .airk/plans (or the configured Planner directory). You can select another explicit local or editor-provider file. It accepts validated AIRK plan JSON or Markdown generated by AIRK Planner, at most 256 KiB. Loading never executes task instructions and asks before replacing an existing draft. A changed draft/project during the picker or confirmation is kept instead.

**Export plan JSON…** preserves complete task states and evidence metadata for an exact round trip. AIRK Markdown contains abbreviated evidence summaries, so loading Markdown resets tasks to Draft and omits verified evidence metadata with a visible notice. Review/rebuild that evidence before handing it off. Arbitrary Markdown, ambiguous task headings, conflicting dependencies and oversized instructions are refused instead of guessed or clipped.

After loading, save the plan again before a file-based handoff. Foreign project ownership is retained and prevents saving/handoff in the wrong project. The file you loaded stays unchanged.

## Saved-plan library

The Saved plans browser lists the configured plan folder, normally .airk/plans. Choose a workspace folder, open subfolders, use breadcrumbs or Up one folder, and choose Load or double-click a file. Refresh files rereads the directory; Next files and First page navigate bounded pages. Browsing never creates folders or changes files. Loading uses the same validation and draft-replacement confirmation as the file picker. Linked/redirected paths and files outside this library are refused; use Load plan for another explicitly selected file.
