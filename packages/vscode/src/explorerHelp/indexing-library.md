# Index library

Sources offers permanent trim of an exact file or subtree under a native source root. Review its canonical target, affected Projects, overlap limitations and unknown counts, then explicitly apply. This Index's exclusion affects every member Project; source files and other indexes remain unchanged. Unblock selects a returned trim rule and restores eligibility without indexing automatically.

Read permanent-exclusion status retains the policy, complete job, removal publication and dated cleanup observation. Entire-index imported analysis/cache retirement is disclosed without automatic regeneration. Logical removal and physical reclamation finish separately. Explicit continuation handles failed/canceled work or remaining physical cleanup; uncertainty requires the exact request receipt, without automatic replay. Delivered results, exports and backups cannot be recalled; reclamation is not secure erasure.

Refresh reads up to sixteen native entries within 48 KiB. Next page preserves the native continuation and revision. Filtering searches only the displayed page.

Inspect an index to read its complete definition, Sources and paged Project memberships. Source IDs and canonical locations remain attached. Metadata listing grants no evidence access. Rename uses an exact native preview followed by an explicit Apply reviewed changes action. A changed client, trust state, namespace or revision invalidates stale reviews.

Set up a new index accepts an explicit primary source location, index-storage location, collection and up to sixteen additional source aliases. Prepare native setup review lets the native service resolve canonical locations and describe whether storage will be created, claimed or reused. Preparing a review performs no setup. Apply reviewed index setup persists the exact native draft before submitting it once. Setup does not grant evidence access or select a session. Reserved and prepared receipts are incomplete; Check native receipts retains the original request and never repeats setup automatically.

Resume saved native setup is a separate explicit recovery action. It is available only after this connected client has just read a matching native reserved or prepared receipt. Review the saved draft and receipt first. Resume sends the original immutable draft, key and digest. An interrupted Resume or a missing receipt disables the action until another matching native receipt is read; no startup or polling path repeats it. A retired setup stays tracked until matching native terminal proof can settle it. Missing receipts do not prove retirement, and choosing a new key is not recovery.

Opening folders, reconnecting and installing do not restore indexes. Existing registrations can be adopted. Management's Set up index and the historical storage command open this explicit review flow.

Explicit Use Grant selects the reviewed Workbench session and offers its first opening. If opening fails, the next explicit selection can retry; a successful first opening preserves a subsequently hidden Workbench during later selections or reconnects. A newly ready index does not trigger this opening before Use Grant. Existing legacy connections retain their first opening only after native compatibility is positively confirmed.

After setup, create a Project in Projects, inspect it, assign the index using its native Source IDs and exact scope rows, then review a grant in This window. Explicit Use Grant selects the index and Project subset; none of the preceding metadata actions selects evidence access. Usage history and shared data-root totals belong to the entire Index. A selected Project session offers only an explicit Open Index administration action; its normal Usage surface cannot read or write whole-index history.

Inspect an index to prepare native add-source, remove-source or retirement reviews. The forms accept only an alias and location, an alias to remove, or an explicit retirement choice. Native supplies every source identity, canonical location, configuration, revision and policy value in the complete review. Apply begins the recorded native configuration operation. If accepted jobs are queued or running, the native busy response reports their counts; finish or explicitly cancel them in Management. This screen never cancels or reorders jobs automatically.

Read native source-change observation uses the returned begin operation ID and performs no mutation. The complete response retains the original begin proof, configuration job, configuration result and metadata completion. A failed job stays failed even if explicit Resolve failed source metadata natively proves and records the desired configuration. The form accepts no filesystem proof. An uncertain resolution is durably tracked and reconciled by observation only, including after restart; it is never automatically repeated. Retirement requires the complete captured worker/provider obligation and every native reap confirmation, including an explicit empty worker census. Scope acknowledgments alone cannot complete it.

After reopening, inspect the index and choose Read pending source change for this index. The native service resolves the linked current operation in one consistent bounded metadata read; the frontend never walks receipts or invents an operation ID. The complete response supplies its original begin identity. A null observation is neutral: it establishes neither readiness nor completion and cannot clear any journal. The historical read form remains available for an already-known native operation ID.

Complete response, Copy complete JSON and Export JSON retain complete native results for the currently retained pages, detail, preview and outcome. Grant rows preserve their native grant/provenance wrapper. Each new page replaces the old displayed page. An unconfirmed apply is saved in the existing native control intent journal; Check native receipts never repeats it. Complete native fence observations remain in the bounded journal and copied details; pending or crossed proof cannot be reported as complete. Missing receipts remain unresolved. Catalog activation and access-changing operations can be unavailable; native failure codes are shown without simulated success.

Native reconciliation can separately prove that an exact retained catalog request was not prepared. This response must match the original full request, caller, key and native request digest, plus the same namespace and a current catalog clock at least as new as the review. It retires only local uncertain tracking, is not a completed mutation receipt, and never submits another Apply or replacement key. A generic missing receipt cannot establish non-preparation.

For a partial setup or uncertain failed-source resolution superseded by retirement, choose Read native retirement evidence beside its saved request. Native returns the complete current index and retirement fence, including the captured worker/provider obligation and actual confirmations. Historical pending import metadata can remain on a retired index. A missing result or a tombstone alone cannot settle tracking. After reviewing matching native proof, Stop local tracking after verified retirement removes only that original local request. It issues no native work, does not clean up files, and reports neither setup nor source resolution as successful. Full proof remains available in the current view and complete JSON export.

An explicit separate retirement review can proceed while matching setup or source-resolution requests for that same index remain tracked. Add/remove source changes, unrelated pending authority changes, and an earlier uncertain retirement remain blocked. The native service still decides admission; this action never retries the original request or replaces an uncertain retirement key.
