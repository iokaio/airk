# Split review and recovery

Split review requires explicit native policy contract 2. Read the complete native source baseline before choosing exact files or subtrees, a separate destination storage location, each affected Project membership, and funded growth, temporary, rewrite and cleanup ceilings. Recommendations open this review only. Ancestor ignore controls can be required outside the selected document paths; permanent exclusions still apply. Preparing a split performs no indexing or grant change.

Apply submits the exact reviewed native draft once. Before submission, local tracking reserves 192 KiB for that split within the shared 2 MiB and 64-entry journal limits; insufficient tracking capacity refuses submission. Check native receipts performs read-only reconciliation after a lost response or restart. Missing or expired evidence does not erase the last known accepted snapshot or authorize replay. Explicit recovery requires a fresh native status read. Cancel before the original fence can require destination cleanup; after the fence it requires restrictive completion rather than restoring previously excluded evidence.

Details and JSON/Markdown copies retain complete native drafts, capabilities, snapshots and future fields. Historical recovery acknowledgments, the last known full accepted snapshot and the latest current-state lookup have separate labels. Physical cleanup and funded allocation release must finish before completion; a successful logical cutover alone does not establish reclaimed bytes.

A metadata continuation acknowledgment preserves the recorded phase, proofs and existing job history. It returns an active operation to pending, or preserves canceled destination cleanup while clearing its exact attention latch. It does not report a new worker job. The complete native acknowledgment remains separate from later operation snapshots.

Original remainder verification is a bounded, read-only native worker job. Its witness retains original publication, path, expected hash and observation interval without source text. Source verification does not transfer evidence before the fence. Frozen terminal publication and funding acknowledgments have their own revision, progress and attention latch. A completed logical receipt with unfinished finalization stays tracked; explicit Resume binds the reviewed envelope revision. A historical accepted acknowledgment cannot clear a later finalization failure.

Native wire budgets are separate: each operation receipt is at most 14 KiB, a complete split snapshot is at most 46 KiB, and a recovery acknowledgment is at most 16 KiB inside the 64 KiB response frame. Oversized data is refused without silent truncation.
