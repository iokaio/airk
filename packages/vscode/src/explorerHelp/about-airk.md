# About AIRK

**AIRK** means **Artifact Indexing and Retrieval Kernel**. It gives MCP-capable coding agents a local index of code and documents, returning bounded passages and facts with original locations, content hashes and indexed revision identities. The agent does the reasoning; people can inspect its evidence and review its work.

## Who builds it

AIRK is an open-source project by **Ioka LLC**, published under the iokaio identity. Ioka describes its development as coding agents assisting implementation under human design, verification and release authority. The original source and documentation use the Apache 2.0 license; dependencies retain their own license notices.

## Origins and history

AIRK's design grew from work around the Munarium Governance Platform and the VCP (Vibe Code Pro) experiment. Munarium's explicit extraction status, original-document provenance and independently usable file artifacts informed AIRK's evidence model. VCP explored coding-agent workflows, local retrieval and bounded context.

Ioka's public history records that VCP was paused on October 6, 2026 as its scope became too extensive alongside Munarium. The useful question remained: how could an existing coding agent find relevant code, requirements and decisions without repeatedly reading an entire repository? AIRK focuses on that local indexing and retrieval problem.

AIRK is independently implemented and builds independently. Munarium and VCP are acknowledged design inspiration; their source and orchestration stacks are not incorporated into AIRK. The inspiration record and NOTICE preserve this distinction and do not imply endorsement.

The project has evolved into a native per-user service, isolated project collections, local inference, read-only evidence MCP tools and the AIRK Explorer. Version 1.5 adds the Explorer workbench, role journeys and Strategies/Planner. Version 1.5.7 unifies indexed evidence, help and reviewed UI drafts under one AIRK MCP connection. The version shown in this Help screen identifies the bundled extension; Overview and Management > Service report observed runtime identities separately.
