# Arbiter asset transaction contract

Store owns the separate private `arbiter-v2/assets/<manifest>/` tree under an actual retained ServiceLease. Opening, absent inspection and disabled startup perform no writes. Paths come only from validated Core Profile asset names and compiled manifest identity; no caller directory/URL is accepted. Product service validates release qualification before supplying a profile; the separate typed private evaluation fixture supplies an opaque evaluation capability and never product qualification. No index/I4/configuration bytes change.

Explicit provisioning takes an actual descriptor-relative per-profile writer lock, writes a canonical installation/catalog/profile/configuration-revision-bound receipt, and streams data into a fresh stage generation. Each logical asset has an exact length and full SHA-256. Only complete verified files publish with no replacement. The Ready receipt publishes only after the complete approved closure verifies. Publication and receipt writes retain actual descriptors, sync bytes/directories, and compare prior receipt identity before replacement. A same-name foreign/linked/mismatched file is preserved and refused.

The private receipt schema `airk.arbiter.assets/2` binds installation/catalog/manifest, monotonic asset revision, originating configuration revision, phase and complete Core asset roster. A crash or canceled provisioning never becomes Ready from its filename or mere existence. Explicit recovery uses the same compiled profile, verifies any already-published files, and creates a new stage generation for remaining assets. Interrupted stage directories are retained as recovery evidence, never executed, used as a download authority or silently deleted. Ready logical files are read through retained descriptors and rehashed; pins retain the actual service lease. Removal refuses live pins, deletes only verified declared final files and publishes an exact Removed receipt; retained intent metadata and recovery evidence are disclosed and preserved.

Downloads are a service adapter responsibility. Core's optional AssetDownload/AssetPart list is compiled authority: every asset has one ordered part roster, each part <=1GiB with exact SHA/length and an exact official iokaio/airk GitHub release URL. Full logical concatenation length/hash must still match Asset. Legacy profiles omit the list unchanged; product provisioning requires complete qualified closure. No downloaded manifest, teacher label, candidate artifact or filesystem path can mint release qualification.

Partial settlement uses private `airk.arbiter.partial/2` receipts: the exact original canonical operation, logical Asset declaration, actual written length/SHA and native file identity are sealed while the descriptor remains owned. Explicit removal may delete only matching declared final files and these proven partial bytes, under real writer/reader locks. Intent metadata and interrupted receipt stages remain retained. A hard crash before partial sealing, a changed file/receipt, unknown entry or foreign identity preserves the bytes and leaves Removing/refusal; it is never manufactured into successful cleanup.

Explicit Remove may also clean a withdrawn profile using only a valid installation/catalog/manifest-bound owned receipt in this fixed content-addressed root, exact safe native filenames, actual bytes/hash/identity and no-follow/pin checks. That cleanup observation is neither an execution capability nor a replacement catalog. It cannot warm, download, enroll or promote a model. A matching unfinished removal is rediscovered only for its original configuration revision and remains a removal.

Windows removal reuses Process opened-directory pins and verifies their actual identities against the retained Store root and each directory. Its existing remove_file_if adapter opens one unredirected single-linked READ|DELETE file with shareREAD only, rejects extra streams through the one shared guard, hashes default bytes and applies disposition on that same handle. No separate unlink can race the proof, and an existing writer, changed bytes, hardlink or alternate stream refuses with foreign content preserved. The reviewed Windows-only Store→Process foundation edge adds no service or execution policy to Process. Unix retains its existing descriptor-relative behavior and does not claim Windows share exclusion.


The approved version 2 private asset receipt also records each final file's original native object identity. Custody is durably recorded while the completed staged writer is still held, BEFORE no-replace publication. Ready, pinning, reuse and removal require that identity as well as complete bytes/hash; same-byte replacement is foreign and preserved. Phase settlement carries the custody map forward after interruption. A version 1 receipt cannot mint missing object ownership and is refused/preserved; no product profile, I4 or source index format changes. Partial version 2 embeds the exact version 2 original operation, retaining original staged identity for interrupted pre-publication cleanup.
