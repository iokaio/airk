# Predecessor orphan roster

Owner: `airk-service::setup_role::predecessor_roster`; discovery/reporting for
split-plan §9.3 and codex-plan §5.1, independent of install-root existence.

Names locate candidates only. This module never executes an old image, deletes
an artifact, changes PATH/shell/OS registration/trust, opens an index, or adopts
old state. Known-root retirement remains the existing installer replacement
owner. Original receipts stay intact for that owner's explicit recovery.

The roster covers both default layout families/channels, surviving launcher and
extension-uninstall receipts, saved service definitions and 1.3 receipts, native
OS registration observations, standalone/uninstall/PATH remnants, native editor
helper/CLI locations and profiles, shell markers, old registry/custom-data and
user-trust receipt locations. Existing Rust owners provide user paths, verified
custom-root discovery and native editor storage roots; no receipt format is
mirrored here. Unauthenticated custom data/ownership remains unknown, never an
absence or permission to remove sources. U72 stays exclusively with the existing
verified macOS unregister owner.

`unproven_preserved`, `inspection_refused` and `discovery_unknown` are distinct
Leftover reasons. Unsafe links, reparse points, foreign-writable parents,
unreadable objects, incomplete OS observations and enumeration bounds preserve
the artifact and disclose uncertainty. Directory observations use shared native
pins and bounded direct names; Unix names/read handles stay descriptor-relative.
Shell reads are bounded by the existing 128-KiB native configuration limit and
report only marker presence and location, never profile contents. Native command
input/output/deadline bounds remain those of `airk-process::bounded_command`.

Core's existing 256-Leftover bound is unchanged. Bounded merging prioritizes known
restart risks and retains an explicit conservative omission marker at the known
setup receipt/pointer context on overflow. It says at least one observed item was
omitted; it never invents an exact total or claims omitted reports were retained.
Physical artifacts and historical receipts remain untouched. An incomplete
predecessor-cleanup step must not report that every predecessor was retired.

Injected OS cases and isolated native file cases prove disclosure and preservation
at their exercised seams. Actual Windows/macOS/Linux registration, live remnant,
and installed setup journeys remain separate platform qualification.
