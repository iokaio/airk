Private preparation only. Root must record and freeze this proof decision and
Rust-emitted refusal cases before consumers mount. There is no new crate,
runtime operation, persisted installation format or downloadable authority.

The existing Rust publication owner reads the actual Rust-emitted candidate
Profile bytes, exact asset maps and SHA-pinned final evidence. Python never
constructs, modifies or validates a Profile. Existing experimental staging remains
evaluation-only and cannot supply final release authority.

Promotion requires exactly Focus Qwen3-Reranker-0.6B, Context Compact Qwen3-1.7B
and Context Large Qwen3-4B. Each input starts unqualified with no qualified
targets. Native validation reuses Core Profile, stage/ABI validation, current
compiler/task-policy owners, actual CpuFit identity, complete logical asset
hashes and Core transport validation. Candidate math, tokenizer, compiler,
calibration, ABI, resource bounds and CPU tier cannot change during promotion.

The private final proof has schema `airk.private-final-stage-qualification/1`.
It binds model, raw candidate Profile SHA, canonical Core asset-roster SHA,
compiler/calibration/task-policy hashes, runtime, CPU execution identity,
platform and qualified task scope. Context scope is the actually qualified
GenericRead/Unknown/Uncertain subset; Focus scope is relevance ranking only.
It references all original evidence by exact file SHA and byte count:

1. Actual native numerical/readout parity for this final candidate.
2. Actual native CPU/resource observations for this exact tier/platform.
3. Actual composed MiniLM + Focus + selected Context path, including source,
   cancellation, deadline, noninterference and recovery acceptance.
4. Actual frozen held-out A6 comparison and its complete input/closure seals.
5. Rights/notices approval covering the exact distributable logical assets.

This is a final reviewed evidence projection, not a boolean copied from a
benchmark. Root's separately SHA-pinned recorded promotion decision must name
the exact final proof and original evidence pins. Missing, incomplete, failed,
nonfinal, synthetic-only, numerical-only, resource-only, model/tier/platform or
asset mismatches refuse. Existing raw numeric/resource/CAL receipts and
`airk.private-native-goal-comparison/1` remain unqualified evidence. Their
evaluation/release flags are not rewritten. The held-out report's one pass flag
alone cannot promote; actual contribution, original floors, source/critical
evidence/citation checks and execution/input seals must also reconcile.

Only the Core qualification digest, qualified-target proof pins, reviewed release
transport roster and release manifest identity are added. The new release
manifest uses the recorded domain `airk.arbiter.release-profile/1` over the final
Rust Profile with only its manifest field zeroed. The promoter never creates

The offline plan remains a secondary manual-import option. Optional Arbiter

The stager requires those exact native output pins, a fresh named output under
