# Private native CUDA component qualification

These ignored test-support/gpu-cuda selectors reuse the actual private-control
ServiceLease, NativeInferenceOwner and ServiceComputeScope. No new process,
crate, public wire/DTO, product selector or actor authority is introduced.
RuntimeAssemblyInput and the request tagged airk.private.cuda-component-probe-request/1
are Rust-owned private diagnostic input. A request is data, never a permit.

The request emitter consumes explicit path/SHA/name-list/bound environment
scalars and serializes native requests. Assembly observes held authenticated
producer/DLL/PE bytes with no DLL activation; output is fits-empty and
unapproved. It works without compiled activation pins. Metadata preparation
uses current native CPU policies, original Focus5072/Compactc79/Largef8 graphs,
raw RuntimeManifest pin and new native raw-only calibration. It creates a
fresh directory with Profile, exact new CAL, updated opaque ResourceRunInput,
Probe request and literal native executable commands. No old profile/CAL or
reference bytes are overwritten. Native current-policy /3 and Core unavailable
/2 dependencies must be applied before generating those inputs.

The four component score selectors consume only the emitted Probe variant.
Context at 17, 128 or 8192 tokens retains the complete three-row original numeric
fixture and executes its selected exact native tensor row. The 8192-token case
requires eight candidate positions and an entirely live attention mask.
Focus consumes all twelve genuine512-token reference cases, including their
original padding/hostile/model-view cases. Each selected row requires both
complete finite independent references and pinned producer/original asset
roster before load. Reference arrays and tensors remain immutable; new native
results never transfer prior CPU verdicts or qualify product advice. Numeric
limits are the maintained same-artifact raw.001/mass.00001(Focus) or.05(Context),
original-FP32 raw.25(Focus) or.001(Context), mass.05 and exact argmax.

One original Core GpuProbeReservation expiry (<=120000ms) starts before request
parsing; all preflight, load, scores, synchronization, drop and posthash share
it. The maintained operation journal has additive create_until with the exact
fixed native-monotonic expiry; historical relative operations are unchanged.
The external owned-process watchdog remains required for unreturned FFI.

Before GPU activation, actual Windows Job process/job limits and kill-on-close
must equal the explicit request. Compact retains the historical 16 GiB process
and 24 GiB Job pair. On x64 Windows, fresh Compact graph and score requests may
instead use an exact 32 GiB process and 32 GiB aggregate Job pair with the
original 120000 ms deadline, 24 GiB device bound, and 16/8/2 GiB device
cold/warm/headroom values. Focus and Large keep their existing bounds. A real
Kernel Resources optional reservation charges the full declared host bound with
actual fresh OS headroom and a retained release observer. This is an isolated
component resource owner, not product
lane admission. Host CPU fit and source/weight limits remain unchanged. Actual
CUDA device cold/warm claims observe free memory under the native broker; no
measured device peak is invented (null until the separate real peak observer).

The scorer uses the actual same-lease EvaluationCatalog, native device witness,
TF32-off strict provider, actual final all-subgraph placement and explicit
score_with_deadline/sync. Failure retains partial rows and complete actual
placement refusal. Unknown completion, including pre-device admission failures,
retains actual Session/device buffers plus native owner, lease, full host charge,
source map and private control root. Scorer drop precedes the final poison
observation, so late teardown uncertainty also prevents release. Known settled
failures remain failures; there is no retry, fallback, threshold change or
qualification claim. Exact request/profile/source/fixture/producer/model/runtime
pins are rechecked after actual teardown.

Native elapsed_us_to_final_report_start deliberately excludes final report
retention; original expiry is checked after retention and refuses if exceeded.
Whole owned-process duration/hashes/Job settlement remain the parent's genuine
receipt. G4 still requires its complete 8192-token, Resource20 and coexistence
evidence. G5 FP16 dispatch/math, semantic labels, public provenance, packaging
and product Auto/future-request recovery each retain their qualification gates.

The actual final persistent peak RSS is sampled after adapter observation,
session teardown, exact post-input hashing and native control cleanup, before
setting complete/report retention. Missing/zero/over-original-bound peak refuses
success even if earlier row peaks passed. The original primary error remains
primary when this final independent check also refuses. Job commit limits and
the optional charge do not substitute for this real persistent RSS observation.

## Runtime-only admission diagnostic

The ignored cuda_runtime_only_admission_diagnostic selector consumes the same
frozen Probe request and metadata/source/manifest pins under the original120s,
16GiB process/host charge and24GiB Job bounds. It uses the actual same-lease
NativeInferenceOwner and production runtime admission, including cuInit and
all mapped-image reconciliation. It never calls adapters, creates a device
context, evaluation catalog, session, scorer, model operation or operation
journal. Reading metadata does not open model asset bytes. The installed
manifest locator and pin must match the frozen request before admission.

Its distinct private airk.private.cuda-runtime-admission-diagnostic/1 result
reports diagnostic_complete separately from runtime_admitted and an admitted
or refused outcome. A faithfully diagnosed policy refusal may exit successfully;
that is not runtime admission, component success, numerical or product
qualification. The full anyhow error string and every chain element are kept
unchanged, including the production stage and aggregate module-refusal JSON.
A separate diagnostic_error reports failures of postpins, final RSS, original
deadline or custody accounting without overwriting the admission error.

The receipt includes request/native-input/profile/source/manifest identities,
actual binary hash, PID, execution user and token default-owner SID, bounds,
actual Job limits, original expiry, actual optional host reservation, resource
snapshot, final RSS and actual native cleanup/host-release/poison facts. Native
execution requires matching execution-user/default-owner identities before
writing. No-model scope fields are explicit false and forward_count_observed
is null; no absent operation journal is presented as component evidence.

Clean native release requires no retained custody or poison, successful control
cleanup and observed host-charge release. A refused admission that poisons the
native process instead retains owner, lease, charge and control root until
process exit: retained=true, poison=true, cleanup=false, release=false. This
state may be a complete diagnosis, never a claim of native release. The parent
must independently prove natural retained-HANDLE exit and empty Job before
accepting the diagnostic. Inconsistent or failed cleanup facts refuse diagnostic
completeness. Admitted diagnostics require clean native release.

Postpins, final RSS and final report retention share the original expiry;
request/profile/source/manifest drift, missing peak or exceeded bounds refuse.
The parent's original wall watchdog and full retained input seals remain
mandatory. No retries, changed admission rules or inherited qualification follow.

The receipt operation_scope explicitly limits false operation flags to calls
made by this diagnostic caller. Production admission includes cuInit; these
flags do not assert that driver internals allocate nothing, create no internal
contexts or perform no internal adapter observation.


# Disposable CUDA session placement diagnostic

Private test-support only. Normal Scorer open/profiling retains CUDA-only provider
registration, disable_cpu_ep_fallback=1 and complete strict final placement gate.
The diagnostic requires a current native evaluation lease, unqualified Compact
FP32 profile and same admitted device/bounds; it cannot accept release authority.
It retains exactly the existing graph/external-byte/large-initializer/ABI setup.
Only its private OpenMode permits disable_cpu_ep_fallback=0 to inspect actual
partitioning. No CPU exception or hybrid policy is thereby admitted.

A successful diagnostic observes a complete final SessionState map, explicitly
synchronizes, drops the actual SessionOwner and synchronizes/checks poison and
pending claims again. It returns data before Scorer construction. No Session,
Scorer, run callback or executable capability is returned. Failed creation,
partial placement or uncertain settlement retains error/log/observation evidence
and existing unknown-work custody; Drop alone never proves release.

An opaque cloned log observer survives consumed ExecutionProfile/Binding failure.
It carries data only. Existing 65536-byte total and 4096-byte formatted-entry caps
remain. Selected CPU preference/missing/unsupported-kernel/assignment diagnostics
retain location and message; seen/selected/retained/omitted/bytes/truncated fields
make selection and loss explicit. Unselected optimizer noise counts as seen,
not omitted. Logs never substitute for the final same-core placement collector.

Native ignored selector cuda_load_only_placement_diagnostic returns private
schema airk.private.cuda-placement-diagnostic/1. It retains actual PID, binary,
request/profile/source/runtime pins, original120-second expiry, process16GiB,
Job24GiB, native host reservation, control/host release and poison observations.
It creates no operation journal and dispatches no forward. Session load is explicit.
Diagnostic complete requires session creation, full placement, untruncated selected
logs, observed pre/post teardown synchronization, pending claims zero, no poison,
actual host/control release and original deadline. Failure never becomes a pass.

The owning source transition explicitly advances current runtime.rs identity
without rewriting legacy CPU metadata, task/compiler identity or qualification.
Inverse textual replay of the reviewed runtime delta must reproduce prior9e.
G5's old9e->DDE supplement must be rebased onto this new source rather than copied.
This diagnostic grants no execution or precision admission, qualification or
publication.

## Native placement diagnostic result ownership

The ignored cuda_load_only_placement_diagnostic uses the unchanged frozen Probe
request, installed manifest locator, unqualified Compact FP32 profile, actual

Its operation_scope is exactly: Disposable session creation and final placement
observation only; no Scorer, forward, hybrid policy or qualification is returned.
The distinct airk.private.cuda-placement-diagnostic/1 receipt sets qualification
and product_admission false, cpu_fallback_disabled false for this private loader,
and strict_production_unchanged true. Existing production strict placement stays
mandatory. A CPU-assigned node may appear as an observation, never admission.

An opaque LoadObserver survives the consuming diagnostic call. Both success and
failure capture the final available session_created, placement, selected bounded
logs and teardown observation without inventing missing fields. Success requires
both diagnose_cuda_placement returning Ok and the owning LoadSnapshot::validate,
plus actual outer control/host-charge release, no poison, unchanged pins, final
RSS and original expiry. A failed/partial/truncated/uncertain observation retains
full error/error_chain and diagnostic_error; it cannot exit as a complete pass.
Snapshots are data only and do not prove cleanup without the actual owner facts.

Outcome placement_observed is emitted only after all those final proofs pass;
otherwise it is failed or not_dispatched. session_load_dispatched is set only
immediately before the actual consuming diagnostic call. The separate parent
still proves retained-HANDLE exit/empty Job and seals this native result/stdout.
No row scores, execution identity or forward completion evidence is emitted.

A caught SessionOwner Drop panic poisons the actual device and retains its
Binding before post-sync. Existing native Custody observes device poison and
retains owner, lease, host charge, source files and control root. The teardown

never relabels that unknown native teardown as an observed native release.


## Native final-graph metadata diagnostic

The existing placement selector, byte writer and strict selected-log completeness rules remain unchanged. A distinct ignored cuda_load_only_graph_metadata_diagnostic selector emits airk.private.cuda-graph-metadata-diagnostic/1 and can report graph_metadata_observed only after the actual native diagnostic call, complete final placement, complete final graph metadata cross-comparison and real session/outer custody settlement all pass.

The new selector consumes fresh authenticated FP32 Compact Probe metadata with the current native runtime manifest/static-core identity. It retains the original 120-second deadline, the Compact host and Job pairs described above, actual lease/device/evaluation authority, file authentication, host reservation, final RSS and post-input checks. It returns no Scorer, dispatches no forward, creates no operation journal and grants no hybrid policy, activation or qualification. Existing poison/unknown-release custody remains unchanged.

The graph_metadata object is the Retrieval-owned airk.private.ort-final-graph-metadata/1 observation. The full capped log snapshot is retained. selected_logs_complete is true exactly when logs.truncated is false and logs.omitted is zero; false is explicit and does not claim that the old placement diagnostic passed. New-mode success requires LoadSnapshot::validate_graph_metadata rather than the older log-complete LoadSnapshot::validate. Missing graph metadata, partial placement/graph records, mismatched node identities, failed actual session load or unproved teardown refuse success.

New-mode receipt serialization is compact and bounded during encoding to16MiB before the output file is changed. Existing modes retain their old pretty serialization. The receipt is synchronized and its retention checked against the unchanged original deadline. Serialization overflow cannot replace a previous partial receipt with truncated JSON or become a successful diagnostic. Primary model/load errors and actual cleanup facts remain explicit.

Pure controls cover missing/failed metadata evidence, log-completeness disclosure, serializer failure before output mutation, compact JSON preservation and byte caps. They do not prove actual graph capture, CUDA execution or model qualification. Integration requires scoped Clippy and selected native tests after combined review.

## Unprofiled Compact Resource20

This separate private selector measures one cold CUDA model load, one
all-live T8192/N8 warmup, and exactly 20 unprofiled forwards in one
same-session graph-gated scorer. The exact R2 graph, model, references,
capacity policy, device envelope and host Job limits are required.
The parent supplies the original 3600-second process expiry in the
shared monotonic clock. Each operation uses its own original 120-second
expiry clipped to that parent expiry. The actual native call receives a
conservative Instant projection of the durable original start marker.
Each start and return uses the existing native operation journal and
retains both durable elapsed and native-call elapsed observations.

The first error, expiry, score mismatch or resource failure stops the
series and preserves its observed partial rows. Completion requires
exactly 20 actual warm samples, native and parent custody settlement
and post-input pins. The series uses shared ResourceSeries nearest-rank
p95. It omits ORT profiling overhead, retains the separate profiled
diagnostic evidence, and reports the component only. Composed Answer,
physical device memory peak and product admission remain separate.
