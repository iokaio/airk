# Development retrieval capture

`development` is a separate test-only owner for the reviewed private DEV64
experiment. The original205 entry, source2772 assertion, inputs and grader remain
unchanged. This is direct Kernel evidence, not CLI, MCP, Service or Workbench
transport qualification.

Before model admission, the capture checks the exact corpus,20/44 mask and
six-family descriptor hashes,64 unique original IDs, development roles, and
the reviewed366-file manifest. Every request searches the same complete
cross-document DEV collection. No final/calibration source or question is
admitted. Actual `Core::SearchQuery` construction keeps vector top10 and32768
bytes; full raw native results, publication, indexed roster, model/pipeline,
binary/runtime identity and per-request timing are retained. A chosen native
semantic unit is not permission to credit unshown parent-file text.

The capture retains incomplete receipts at completed request boundaries and
honors the explicit stop file there. A native error or changed input/source
closure prevents completion. The existing Nextest profile owns process timeout;
no new native performance bound or successful cleanup is inferred. Source
roster and corpus/mask/descriptor checks run again before success. Data and
receipt paths must resolve outside the read-only fixture. Models are admitted
only through the existing private evaluation owner, with product catalog
refusals preserved.

`development_retrieval.py` prepares exact DEV source bytes and original support
intervals, then grades all64 records from each of six matching native families.
The fixed20 aligned questions alone supply the quality denominator;44 refused
questions remain `NOT_EVALUABLE`, never perfect or silently replaced. Every
returned hit still passes original source/citation byte checks. Preparation and
grading use the reviewed singlethread60second/256MiB runtime guard. Successful
preparation is not native evaluation; DEV evaluation is not final qualification.

A new child test requires a newly built test image. An older matched product
pair or test image must retain its original identity and cannot be described
as containing this capture.

`candidate.rs` is a distinct, test-support-only owner for the preselected
visible-prefix-mining epoch1. Its emitter constructs the existing Rust
`OnnxManifest`, pins the exact two exported ONNX files, tokenizer, export
receipt, complete runtime seal and twelve-case oracle, validates through the
actual evaluation owner, and preserves refusal outside that owner. It emits
fresh manifests and a separate two-family master; it never rewrites the closed
six-family descriptors. The primary-reviewed master hash is required by both
candidate numeric and DEV consumers. Numeric admission keeps exact tensor
equality, component error at most 1e-5 and cosine/L2 floors .995/.1 for every
candidate. Candidate DEV retains the same64 requests,20 aligned/44 refused
mask,366-source closure and full native results. A candidate is development
only; neither this module nor its numerical checks establish final quality.

Using retained R10 baseline results alongside a new candidate image requires
the reviewed same-index old-model control comparison. Any unexplained result
difference requires all eight families on one matched image; old receipts
retain their original binary/source identities.

`fresh_final.rs` is a separate opaque capture entry for the new immutable
205-question FINAL experiment (171 Hotpot/34 QASPER,1685 original paragraphs).
It derives questions and Hotpot-global/QASPER-paper scopes inside Rust from
the sealed corpus, without returning gold annotations to a developer. Its
input manifest, complete physical source census and all205 original IDs are
checked before any query. An independently reviewed immutable
candidate/export/CAL freeze must bind six distinct roles/families, exact model
and descriptor digests, runtime, actual native binary and inspected pipeline.
The capture retains the entire canonical vector10/32768 result, publications,
timings and all error/continuation fields. It rechecks source/corpus/descriptor
and freeze bytes before marking completion. An empty, foreign, duplicate or
incomplete population fails; no task substitution or refill is allowed.

The FINAL observer and protocol are private evaluation owners. Compilation or
fixture preparation does not authorize neural execution or prove quality.
Root's explicit resource release follows the actual pre-outcome freeze. The
original failed205 experiment and DEV64 sources/graders remain separate and
unchanged; no FINAL outcomes may choose checkpoints, calibration or recipes.
