# Retained publication diagnostics

`observe_discovery_publication` opens an existing service registration with
`Kernel::open_existing_service_observer`. Pass its exact canonical source
path, canonical data root, collection, project binding, published revision
and independently recorded file count, in that order. It emits the complete
native `FileList` responses as JSON lines on standard output. Every page must
carry the expected revision and strictly advance through the native cursor.

Run this example against a stopped, independently authenticated store. Keep
the input inventory and pre/post custody evidence outside the store. Redirect
standard output to a fresh private result and retain standard error with the
invocation and settlement evidence. The result measures kernel inventory on
the supplied revision. Live service access, vector configuration and model
ranking require their own observations.

The companion observe_service_activation_reads example takes the same first five arguments. It reports elapsed time for the retained observer, rebuild receipt, configured roots, full service inspection, status and recovery observation. A full service inspection acquires the native writer exclusion while hashing saved settings. On Windows this can change the selected directory timestamp when its transient writer marker is created and released. Keep per-entry custody witnesses and the original command deadline.
