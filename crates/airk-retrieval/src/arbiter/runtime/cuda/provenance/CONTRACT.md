# Distributable CUDA runtime provenance

This Rust owner projects authenticated successful private GPU build/aggregate
metadata into a path-free distributable notice and an exact package-file roster.
It grants no runtime, device, model, numerical or scientific qualification.
The existing CPU verifier and C7 six-field opaque static_ort projection do not
change. Raw producer/continuation receipts, commands/logs, absolute private
paths, source trees, toolkit/developer files, model assets and state never ship.

Public schema airk.native.cuda-runtime-provenance/1 binds the successful opaque
producer/continuation receipt SHA (static_core_build), independent maintained
build/aggregate proof SHAs, exact aggregate archive hash/length, producer and
verifier source/lock hashes, source/component versions and inventories, compiler/
tool identities, semantic CMake options, runtime DLL hashes and original legal
notice identities. Failed-parent ancestry is an opaque historical digest only;
syntax diagnostics or compiled kernels cannot become model/qualification claims.
No actual output hash is known until the current build naturally succeeds.

The public decoder is direct typed deny_unknown_fields with bounded vectors and
strings; it authenticates the exact Core Notice Asset named
airk-cuda-build-provenance.json. The static build must equal the compiled/runtime
owner's expected build identity. Its DLL roster must exactly equal the native
RuntimeManifest files (name, length and hash), never a wildcard or prefix copy.
Only the explicit provider pair and reviewed CUDA/cuDNN runtime basenames are
allowed. Driver nvcuda.dll, second onnxruntime.dll, injection/debug/developer DLLs
and unlisted helpers refuse. Each selected component needs at least one exact
original notice as direct protected basenames airk-cuda-notice-<component>-<leaf>. Names are
ASCII relative package names without separators in basenames, traversal, case
collisions, colon/control characters or reserved Windows device names. No legal
text is inferred from DLL/version names; original pinned notices and existing
redistribution review remain mandatory.

The metadata-only native projector consumes SHA/length-pinned successful private
producer, maintained proof and aggregate proof, source locks and legal inputs.
It reopens their exact authenticated bytes, reconciles same-build provider rows,
aggregate producer-proof binding, source inventories, compiler/options/dependency
closure and actual original notice bytes. It emits only the typed allowlist.
Its output remains unapproved; the existing compiled RuntimeManifest/2 SHA and
held-file/PE/module/source/lease gates remain the activation authority. Neither
serialized proof booleans nor this public JSON can create a capability.

The native legal_assets() accessor returns exact RoleNotice CoreAssets for the
loader to hold/open/hash every direct-child legal file; semantic coverage labels
alone never substitute for actual notice custody.

Native loader API: provenance::validate(raw, CoreAsset, expected_static_build,
&[manifest::RuntimeFile]) returns the validated descriptive public record. Loader
owns actual held-file custody and all payload-byte/PE checks. Product manifest/2
references this Core Notice Asset; scientific manifest/1 keeps its historical raw
private receipt semantics. Metadata preparation has no model invocation. Root
retains the raw private evidence separately and reviews successful same-build
proof before compiling approval.

The legal projector requires a SHA-pinned exact private legal roster and its
maintained extractor source, alongside actual notice bytes. This roster contains
component, package_name, bytes, sha256 and source_artifact_sha256 per file. It is
an input hash inventory, not an approval/rights flag or runtime contract mirror.
Versions absent from source metadata remain absent. Installed CUDA toolkit
inventory identity is explicitly distinct from an archive hash; source archives
and modified inventories are never conflated. Compiler version-kind identifies
MSVC toolset separately from exact compiler executable identity.

The aggregate command plan must itself name the exact canonical current producer
proof, not merely match a resealed plan hash. Regression inputs reseal all
unrelated source/proof references before targeting status/settlement failures;
intrinsic DLL/unsafe-option controls keep all unrelated roster fences valid.

The test-support-only opaque native input is versioned
airk.native.cuda-provenance-projection-input/1. Rust serializes/deserializes the
actual Input/PayloadInput/NoticeInput owner types, rejecting unknown/duplicate
fields, oversized requests/rosters, zero or unsafe pins and invalid payloads
before source opening. decode_input is available only inside the native CUDA
owner; the public native metadata bridge retains the actual lease/source custody
and original deadline. This is no new user command, wire permit or runtime
approval. Future input emission uses real observed producer pins; no placeholder
actual hashes are supplied by this implementation.
## Incremental final-graph derivation

Canonical build proof/3 and raw cuda-static-incremental-receipt/1 describe a fresh core derived from the authenticated f9fac checkpoint producer and 042c aggregate. The sibling incremental validator authenticates that unchanged parent checkpoint, the exact reviewed recipe and producer/helper closure, the one translation-unit/object replacement, 39 retained session objects, 95 retained libraries and unchanged provider pair. Original 600-second execution and per-phase cutoffs, actual suspended human identity, original Job bounds, retained HANDLE exits and naturally empty settlement are mandatory. Archive member closure preserves the existing bounded deduplication semantics. No success flag alone establishes derivation.

Fresh raw producer identity becomes static_core_build; parent identity remains ancestry. Optional omitted-by-default incremental_history contains hashes and bounded descriptive scalars only. Existing checkpoint_history continues to describe the parent. Absent optional fields preserve historical serialized bytes. Fresh public aggregate and producer must differ from their ancestors; qualification and cold_build_qualified remain false. ONNX source changes include the exact patch and after-source hashes. Old private evidence is neither rewritten nor retagged.

The assembly incremental_proof input is mutually exclusive with checkpointed_proof. Assembly and projection call the same native validator under existing held-source custody and deadline. New manifests, runtime profiles, compiled identities and probe requests must derive from genuine fresh producer outputs; no previous runtime manifest becomes approval for the new core. The maintained validator deliberately refuses execution until its exact reviewed recipe digest is frozen. Source implementation and metadata validation grant no model or product qualification.
