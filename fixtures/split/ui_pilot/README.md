# Usage and Help semantic cases

Rust owns these payloads. `help_native.json` and `usage_native.json` use
`airk.split.ui-pilot.native-payloads/1`; `native_reads.json` uses
`airk.split.ui-pilot.reads/1`. This is a test-fixture contract, not a new service
wire or persisted state format.

Each case retains its name, surface, complete CLI argv, Admin operation and typed
request, and complete native `ControlResponse`. The aggregate adds I2 exit code,
exact stdout and stderr strings, and I3 HTTP status and complete JSON envelope.
Consumers retain unknown native fields. They must not confuse the I2 Usage
document with I3's `result.status=usage_document` wrapper. I2 Help stdout is the
complete MCP result; I3 wraps it in `result.status=tool_result`. A failed Usage
document appears in I3's `error.native`, with HTTP 409. Failed MCP Help remains a
complete tool result inside a successful I3 envelope; I2 additionally returns its
native error line and refusal exit class.

Help cases call the canonical native Help owner with landing, topic, continuation,
invalid topic and invalid line inputs. The no-project case also proves the actual
I2 resolver keeps Help unselected. Usage cases use native summary types with fixed
content-free observations and the actual bounded page collector. They replace the
persisted store and wall clock; they are not a snapshot of a live collection. The
31-day case invokes the actual early owner refusal, preserving the supported
1..30-day bound. The native-failure control and future-field controls are explicitly
injected packets, not claims about fields emitted by the current producer.

I3 cases exchange an actual session and run the real handler with an injected
native dispatcher. Additional `request_refusals` retain entire forbidden packets,
400 refusal envelopes and zero-dispatch observations. Native session cookie and
anti-forgery values are scanned against the entire normal response and are never
written to these fixtures. Documentary words in Help, such as `caller`, are not
secret material. There is no generic response-field filter or synthetic unsafe
response classification. These tests establish parser, formatter, admission and
handler semantics; live IPC, HTTP listener and installed-product qualification are
separate acceptance checks.

Regenerate sequentially from the repository root with the pinned toolchain and
the campaign target directory. Set the named environment variable to `1` for
each command, then remove it. Preserve `--locked --timings` and the target setting
used by the owning validation receipt:

1. `AIRK_WRITE_UI_PILOT_HELP`: `cargo test -p airk-mcp --lib ui_pilot_help_native_cases --locked --timings`
2. `AIRK_WRITE_UI_PILOT_USAGE`: `cargo test -p airk-frontend --lib ui_pilot_usage_native_cases --locked --timings`
3. `AIRK_WRITE_UI_PILOT_CLI`: `cargo test -p airkctl --lib ui_pilot_cli_semantic_cases --locked --timings`
4. `AIRK_WRITE_UI_PILOT_I3`: `cargo test -p airk-https --lib ui_pilot_i3_semantic_cases --locked --timings`

Review all generated bytes before frontend adoption. CLI regeneration deliberately
invalidates the previous I3 projections; the fourth command restores them from the
actual handler. Ordinary runs compare saved cases with the owning native paths.
