## Exposure and correction

Official RustSec reports the server schema-cache issue
[0461](https://rustsec.org/advisories/RUSTSEC-2026-0461.html), OAuth SSRF issue
[0457](https://rustsec.org/advisories/RUSTSEC-2026-0457.html) and client response
buffering issue [0462](https://rustsec.org/advisories/RUSTSEC-2026-0462.html).
Version 3.9.0 is outside all three published affected ranges. No advisory
exception is introduced. AIRK requests `server`, `macros`, `transport-io`,
`transport-streamable-http-server` and `client`, with defaults disabled. It does
not request OAuth or the SDK's built-in reqwest/Unix-socket HTTP clients.
The server cache path is enabled; AIRK's authenticated gateway reduces
exposure but does not make an upgrade unnecessary.

The exact 3.9.0 HTTP tower source removes the persistent `tool_schemas` map and
looks up the handler schema for each request. Its stateful worker inherits the
server cancellation token. The session manager trait is byte-identical to
3.2.0; local-manager lookups now clone handles before awaiting a worker, releasing
the map lock. Existing AIRK request/session/authority/native admission bounds
and accepted-work lifetime remain required. The HTTP adapter, gateway, stdio
lifecycle and relevant test source were inspected together.

The client bounded collector rejects oversized Content-Length before polling,
checks each incoming chunk against remaining capacity before retention, and
returns a typed error rather than truncating. OAuth DNS/redirect enforcement is
described by the upstream advisory; these disabled feature paths were not
independently audited or enabled for this change.

## Build and transitive source observations

The SDK's unchanged build script can invoke `git config core.hooksPath` only
when the package grandparent contains both `.git` and `.githooks`. A normal
registry cache does not have that layout. This behavior is disclosed rather
than described as a script-free dependency. No download is present in this
script. The macro crate has no build script; inspected macros generate Rust
tokens, tool routing and schemas via syn/quote. No filesystem, process or
network access was found in its source scan. Output-schema generation changed
to the serialization contract; AIRK's catalog fixtures must confirm its output.

The six new RustCrypto packages have no build scripts. `crypto-common` and
`digest` forbid unsafe code. Their typed block/output APIs and enabled digest
wrappers were inspected. `hybrid-array` uses layout casts over transparent
arrays and MaybeUninit; its generator tracks the initialized prefix with a drop
guard for errors/panics. `block-buffer` uses sealed size/kind invariants, raw
copies and initialized-position tracking, with reset guards around compression.
`const-oid` validates BER arcs before its borrowed transparent slice cast.
The SHA-2 implementation dispatches hardware intrinsics behind CPU feature
checks and retains software compression. There is no proof here of all unsafe
preconditions, cryptographic correctness, constant time, panic freedom or all
optional feature paths. No process/network/runtime filesystem access was found
in the inspected new RustCrypto sources. Optional entropy features are not
requested by this new SHA-2 dependency path.

## Compatibility and limits

`ServerConfig` replaces the deprecated `ServerInfo` spelling; both alias
`InitializeResult`, with no type or serialization change. The SDK now fills
`ttlMs: 0` and `cacheScope: "private"` for cacheable completed catalogs at
protocol 2026-07-28 and later. Legacy catalogs and tool-call results do not
receive these new fields. The user approved this additive modern catalog change as a narrow D8
exception; it is retained in complete replies, without transport normalization.

Two AIRK regressions cover fresh schema lookup across unknown/changed tools and
modern-only catalog hints while preserving tool records and call content. The
existing stdio/HTTP sessions, isolation, cancellation, full-result parity and
typed refusal tests remain part of validation. No Rust compile, test, runtime,
dependency scanner or platform qualification was performed by the security task.
Local source evidence is distinguished from the official published defect and
from pending execution results in the readiness ledger.
