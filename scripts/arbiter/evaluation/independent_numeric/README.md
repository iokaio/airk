# Independent numeric reference recipes

The private static512 legacy CPU regression uses `prepare_legacy_cpu_source.py plan|copy|verify <destination>` with the campaign's fixed proposal directory. Run the plan before creating checked output parents. Copy prepares a bounded Cargo source snapshot with one proposed runtime pin. The snapshot includes the checked-in intent asset required by the native build. Model weights stay in their original private storage. The native ignored test `legacy_focus_release_cpu_replays_original_compiled_pairs` consumes original assets through `AIRK_LEGACY_FOCUS_ASSETS` and the original `AIRK_LEGACY_FOCUS_METADATA` file. It prints the original 10 compiler-produced input bindings and raw reference comparisons. Preserve its separately authenticated native build, parent invocation and outcome.

This folder owns independent Focus W8 storage/math, native reference preparation and complete-array assembly. source-provenance.json maps the seven original sources to maintained hashes; originals, weights, executions, reviews and numeric fixtures remain untouched under artifacts. reference_parent.py is a byte-identical superseded historical owner preserved for reproduction mapping only; maintained code imports the authenticated no-site parent/worker/owner trio through maintained_helpers.py.

Preparation separates tracked source from private state, retained evidence and selected FP32 export inputs. Provision an existing, human-owned fresh artifacts directory, then run `python -B prepare_reference.py --inventory --state-root <absolute-private-state-root>` from this folder. The concrete plan command requires that same --state-root, --evidence-root pointing to the retained independent-numeric review directory, --export-root pointing to the selected original FP32 export, and every original explicit native input/template/roster/model/limit/output argument (see --help). It refuses a historical inventory that names an artifact reference module. New inventory pins maintained Qwen reference source and publisher assets; new plans pin maintained helpers. No retained seal is rewritten or relabeled.

Assembly accepts every original explicit input/hash/execution argument plus --output-root <absolute-existing-artifacts-directory> and --output <fresh-child-directory>. It still validates complete natural process settlement, exact arrays, identities and seals; it grants no native qualification. Preparation and assembly do not launch models. External same-user output preflight and post-write ownership audit remain mandatory.

For a fresh maintained reference phase, add `--execution-powershell <absolute-pwsh.exe>` when preparing the concrete plan. The resulting plan seals the Windows output guard and the launcher. From the verified human shell, run the pinned Python with `-B -S run_reference.py --plan <path> --plan-sha256 <hash> --output-root <checked-existing-private-root> --name <fresh-child-name> --powershell <same-absolute-pwsh.exe>`. It runs one suspended-and-authenticated child under the sealed Job limit, keeps caches and outputs inside the fresh child directory, and emits `execution.json` for the existing assembler. Audit descendants after an interrupted or failed phase before using evidence. Complete natural settlement and check device and host headroom before starting another phase.

The historical standalone parents retain their frozen output anchors. Pure helper decision tests can run without model inputs. Synthetic filesystem and Torch/ONNX tests require provisioned packages, explicitly guarded private test directories and a same-user runner.

The filesystem fixture tests require a pre-created, guarded `artifacts/independent-numeric-test-state` parent (assembly uses a fresh UUID child). Focus synthetic math tests use `artifacts/focus-w8-test-work`. Audit all created descendants before consuming results. Those filesystem suites were not run for this migration.
