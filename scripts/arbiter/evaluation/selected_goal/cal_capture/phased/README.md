# CAL100 capture on one installed corpus

Run `python -B -S capture.py --output <fresh-absolute-D-campaign-child> --node <pinned-node>` under the verified Windows owner. The input is the fully closed R3 installation, the selected 1024-token CPU Focus profile and the frozen CAL100 census. R3's ten Focus admissions and all earlier question results are excluded from the new census.

The owner writes the entire question assignment to `lifetime-plan.json` before starting the first service. Each of the original thirteen phases runs once under its own native service, observer journals and grant lifecycle. Every service opens the same native installation through the existing same-owner restart protocol. The native restart independently validates the original ready, closed and stage records and reacquires the catalog lease. Every phase retains the previous phase's closure and verifies the original source, eligibility and publication. A changed grant fingerprint across native instances is expected.

The 10,800-second campaign limit includes the completed R3 installation's entire 545.806 seconds, every restart, request, phase and native closure. A phase has at most 1,800 seconds encompassing restart and closure. Each original request has 120 seconds with five seconds of delivery grace. The 32 GiB Job and native per-lifetime limits remain in force.

Each lifetime directory contains the original native exchanges, active stage checks, W4 grant and release evidence and complete Focus dispatch, warm and lease-closure records. The whole-run fixture closure links all thirteen in sequence. An incomplete phase ends the campaign and preserves its original evidence. A successful capture is input to independent scientific certificate evaluation and fit.
