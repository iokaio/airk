# Phase 12 exchange timing

The diagnostic worker uses the original phase implementation, SDK, timeout and
four question IDs. The parent supplies a pinned plan and enrolls the service
process. Before each new scope grant, the pinned helper applies the declared
CPU affinity for that ordinal and reads it back. The service and SDK execute
each original operation. The timing wrapper records the monotonic invocation
interval before hashing the original CLI arguments and response bytes.

After verifying each completed phase Job and the whole original service
dispatch journal, pass its transcript events, observer events, four plan IDs
and pass index to `readout.measure`. It returns one observation per original Status, Answer and delivered probe. A missing response, incomplete native dispatch or unmatched
event within the pass refuses the complete timing readout. The original
receipts preserve incomplete attempts. The residual subtracts the union of
millisecond-resolution dispatch intervals from monotonic CLI duration and
includes all remaining work inside that exchange. Its precision reflects
those two clocks. Distinguishing retrieval, service processing and transfer
inside a residual requires additional observations.

Run the model-free controls with `node --test test_exchanges.cjs` and
`python -I -B -S test_readout.py` from this directory. The timing results
describe the diagnostic passes only. The original R5 outcome remains 98
completed questions and a partial question 99.
