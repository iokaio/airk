# CAL100 service capture

This Windows owner connects the retained, partly exposed CAL population to
the current native service. It installs the bundled MiniLM, publishes one
CAL index, observes its pipeline and enables the frozen CPU Focus and
Compact bootstrap profiles. The native CAL observer records the two
compiler censuses before any Context model dispatch. The bootstrap
profile and the CUDA artifact to be fitted have separate identities.

Run `python -I -B -S prepare.py` from this directory for the private
launch-input audit. It hashes the retained service, CLI, profile descriptors,
compiled SDK modules and CAL inputs, and lists the exact native fixture
selector. The replay and census receipt paths are under the campaign root.

Run `python -B -S launch.py --output <fresh-empty-campaign-directory>
--node <pinned-node.exe>` for CPU setup and shutdown. The checked Windows
shell must own the output parent and audit the generated service control
state, index, semantic drafts, command logs, image copies and receipts.
The launcher requires 24,130,011,529 bytes of profile assets before index
and runtime overhead. It uses the service's 64 GiB/four-thread preset
inside the retained 32 GiB process and aggregate Job limits.

After setup is independently reviewed, `--capture` starts a fresh fixture
and processes the ordered 13 phases under one 10,800-second lifetime.
Each phase uses the retained Windows suspended-launch Job owner to run the
pinned SDK and CLI. The output gains private `phases/phase-NN.jsonl`
transcripts, per-phase Job receipts, an aggregate, and the fixture's
native shutdown and reacquired lease. Preserve failed attempts in place.
The current worker accepts the explicit one-index agent selection.
Terminal judgments, reference certificates, model scores and fitted
policies each need their own measured steps.

Run the focused controls with `node --test test_phase.cjs` and
`python -B -S test_owner.py`. The controls use synthetic records.
A retained command that lists one test proves fixture discoverability.
A setup-only execution and a full capture have separate receipts.
