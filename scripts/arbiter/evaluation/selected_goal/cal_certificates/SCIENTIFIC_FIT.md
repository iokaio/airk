# Compact scientific CAL fit

The ignored kernel test `context_action_calibration_tests::selected::compact::fit_compact_artifact_generic_read_scientific` fits one exact Compact artifact against the 100 preregistered CAL questions. It calls the selected native generic Read fit, original whole-card selector, calibration serializer and replay. A positive fit requires at least one independent original-reference admission and zero uncertified admissions. A run with no safe margin preserves the abstention result. The two-model selected fit remains the owner of the full gate.

The active scientific input requires a frozen static-1024 Focus launch audit, its exact independently certified capture and fresh raw scores. The archived static-512 Focus capture and the numeric development selectors have different inputs. A CUDA fit uses scores from the reviewed QKV graph `e621cf6b…` and profile manifest `dabbc7e0…`. An original Compact fit uses graph `c79c6725…` and profile manifest `6e7520aa…`. The output identifies its source profile and scoring evidence. Each invocation independently derives its rule.

## Inputs

Set `AIRK_CONTEXT_ACTION_FIT_INPUT` to the absolute path of the private input JSON, `AIRK_CONTEXT_ACTION_FIT_INPUT_SHA256` to the SHA-256 of those exact bytes and `AIRK_CONTEXT_ACTION_FIT_OUTPUT` to a fresh guarded directory. Run the exact ignored Rust test through the checked owned process after its producer receipts have been reviewed. The input has these fields.

| Field | Contents |
| --- | --- |
| `preflight` | Path and SHA-256 of the complete 100-question certificate output |
| `launch_audit` | Path and SHA-256 of the corresponding native launch input audit and its staged profile roster |
| `model` | Existing native model input fields `profile`, `profile_sha256`, `raw`, `raw_sha256` and `base_assets` |
| `producer_binary` | Path and SHA-256 of the scoring image |
| `scoring_closure` | Path and SHA-256 of the reviewed scoring closure |

The scoring closure uses the private schema `airk.private.compact-cal-raw-closure/1`. It links the raw, preflight, model-profile and producer-binary digests, records its backend origin, and retains pinned original owned Job receipts. The CUDA closure also retains the independently produced, input-specific matching-FP16 and original-FP32 reference bundle, plus the native return/synchronization observation. The candidate producer owns authenticating the leased execution, tested image, graph, weights, input-specific reference lineage, actual native readout and resource lifecycle. The fit consumer checks arithmetic input alignment and row provenance. Its scientific result carries no numeric or release qualification.

The raw stream uses the selected native raw schema, including complete finite original card scores, all original admission and compiler refusals, the exact capture, Focus roster and scorer identities. Every scored row must match the original complete compiled input and roster in capture order. Each successfully scored CUDA row has independent reference vectors on those exact input bytes. An unavailable request, compiler refusal or unsupported action keeps its place in the 100-question census.

A successful invocation creates `fit-report.private.json` and, when a safe margin exists, the experimental calibration and profile under `model/`. These files stay private. The 98% paired comparison requires its separate measured outcome.

The shared private registration in `crates/airk-retrieval/src/arbiter/scientific_cal.rs` authenticates the profile file, native manifest, consumed graph, all registered external weights and the reference-math basis. The fit and native scorer consume the same registration. The original Compact publisher FP32 vector can be reused across candidate variants only when its exact original case, capture, original scope/roster, compiled tensors, original publisher parameters/runtime and checked producer match. A matching FP16 vector additionally requires the exact registered graph, weight precision routes, cast/rounding and attention math. A native score, fitted calibration, placement, memory or speed result stays with its producing artifact and target. The CAL raw owner retains the original references and actual native output separately. See `../cal_raw/README.md`.
