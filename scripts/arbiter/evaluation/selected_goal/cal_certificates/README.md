# CAL100 independent reference certificates

This owner consumes a fully closed Focus-on, Context-disabled CAL100 capture.
It verifies the ordered phases and derives a positive reference proxy only
when an additional returned read covers previously missing evidence from an
original human annotation. The native fitter owns whole-card eligibility and
per-action thresholds. A refused read, missing assessment or lack of observed
gain remains unknown. Terminal actions have no independent labels here.

Run in the checked human Windows shell from the repository root.

```powershell
python -I -B -S scripts/arbiter/evaluation/selected_goal/cal_certificates/test_certificates.py
python -I -B -S scripts/arbiter/evaluation/selected_goal/cal_certificates/certify.py --preflight
python -I -B -S scripts/arbiter/evaluation/selected_goal/cal_certificates/certify.py --active-audit <absolute-1024-audit-path> --audit-sha256 <audit-sha256> --focus-manifest <active-focus-manifest> --capture <absolute-capture-directory> --outer-sha256 <outer-owned.json-sha256> --closure-sha256 <fixture-closure.json-sha256>
```

Source-only preflight reports the retained 512-token epoch by default. Supply
the three active-audit arguments to verify the new 1024-token Focus epoch.
Live certificate generation requires the new launch audit and exact Focus
manifest, original CAL census, corpus, rubric, manifest and scopes, plus the
authenticated 1024-token compiler. Every delivered Search observed inside an
Answer or a probe must identify the original ready MiniLM publication and a
complete hybrid or vector result. Its observed count must match the per-question
and total search counts retained by the closed fixture.

The last command emits a private, single-line selected Context CAL reference
preflight to stdout. Retain it at a fresh checked campaign path and verify its
owner and SHA-256. It contains native requests and human-reference progress.
The source-only preflight emits counts and issues no certificates.

The producer follows the closure links for the live fixture, original service
identity, native admission observer, dispatch and warm completion, and all 13
owned phase transcripts. It checks each selected question and probe against
the original native exchange and admission file. The native read-attempt ID
and outer MCP telemetry ID have separate issuers. Their association uses
actual record order, question, scope, assessment ordinal, roster basis and
planned prompt digest. The capture identity in the native reference format
is the fixture-closure digest. The output also retains the outer-owner and
phase-census digests.

For static Focus 1024, every question starts with a new native window grant.
Its Status, Answer and probes must identify the same grant fingerprint, original
publication, repository roots, revision and policy. The verifier checks the
single project membership and the ready 753-file, 767-vector collection. It
accepts a question only after its window release and rejects fingerprint reuse.

A phased fixture uses the same command with its own outer and fixture closure digests.
The verifier authenticates the original installation, the predeclared 13 lifetimes,
all native restarts, the 100 original windows and the common clock including original
setup time. Each lifetime must close its own native service, warm and dispatch
journals before any certificates can be issued.

Each counterfactual starts from the same source-authenticated baseline. The
maintained goal_sources owner matches returned excerpts to the exact source
file and byte window. The maintained goal_rubric owner measures gained facts
within each human alternative. The adapter authenticates the live source
owner against the selected original bytes and compares the two scoring
functions' complete syntax trees against the selected rubric before using
them. Only the maintained implementations run. The report carries all 100
rows and qualifies no profile.

For a future completed grouped capture, the certificate reader verifies all 13 original phase Jobs across three distinct native lifetimes with 32, 32 and 36 questions. It checks the settled incomplete R4 predecessor, exact recorder source and per-lifetime admission limit, original phase and common deadlines, unique window grants, and the final publication and input census. Per-phase diagnostic files retain zero certificates until the whole cohort closes.

A grouped capture also requires `--mutex-release-sha256` from its final `control-mutex-released.json`. This post-exit receipt binds the original acquire record, parent PID, original outer Job closure and the release time after all groups settle.
