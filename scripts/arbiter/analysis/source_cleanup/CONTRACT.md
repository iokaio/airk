# Exact source cleanup contract

This owner removes only explicit retired authored source duplicates after a committed rescue and reviewed consumer transition. It never discovers deletions by wildcard, recursively removes directories, imports recovered code, executes vendor code, or changes ACLs. The Python CLI is read-only; only apply.ps1 contains a single-file Remove-Item operation. Root combined review and a committed freeze precede any apply invocation.

Inputs are a SHA/length-pinned private request, an explicit maintained source-map allowlist, a pinned consumer review and a fixed rescue commit equal to HEAD. Maps, replacements, this implementation and the human guard must match raw committed blobs. A row needs a unique source/destination map, matching original and maintained hashes, exact original length, and a unique byte-identical or whitelisted SPDX-prefix inverse. Other adaptations are deferred. Selection requires an explicit retired-authored-source role; upstream, copied fixture, corpus, reproduction-input and receipt roles never qualify. Metadata containers are outside the source-extension selection; suffix alone cannot grant eligibility.

Consumer review schema airk.source-cleanup-consumer-review/1 has files rows with source, role:'retired-authored-source', status:'clear', active_consumers:[], nonempty consumer_searches, verification_transition, and evidence:[{path,sha256,bytes}]. This is a reviewed assertion authenticated by pinned evidence, not an automatic proof that text search found every dynamic caller. Any nonclear status is deferred. The root reviewer owns correctness of the finite selection and absence of active writers.

observe.ps1 checks effective/default-owner/interactive-user identity using the maintained guard, ordinary source ancestry, human owner and every parent access policy, then records source hash/length and file/parent SDDL. The planner's pure candidate seam accepts injected observations for tests; production always invokes the fixed PowerShell observer. verify rebuilds the plan and requires exact equality, no deferred rows, a nonempty roster and unchanged HEAD/tool bytes.

Apply writes a fresh immutable pre-removal proof, then intent and outcome receipts for each literal file. It reobserves identity, source and all parent policies and rehashes immediately before deletion. One failure stops the batch; earlier results remain. A crash between deletion and outcome is an unresolved intent, never an assumed success. No receipt or historical map is overwritten. Receipts are created with CreateNew, flushed and audited for human ownership before use. The caller must keep the fresh receipt parent within private artifacts and clear active writers. Metadata preflight and final rechecks are not atomic confinement against hostile concurrent path mutation; uncertainty refuses the run.

Permanent source inverse tests reconstruct original bytes from committed sources and compare recorded original hashes/lengths without private artifacts. Custody audits are separate: before removal they authenticate the actual original; afterward they require a bound successful removal receipt plus its immutable pre-removal proof. A missing original without that proof remains a failure. This module does not make existing inverse/custody consumers silently optional; their reviewed transitions must precede clear consumer status.

The pure `verify_custody(expected, original_bytes_or_None, proof_or_None)` seam accepts expected source/source_sha256/source_bytes/source_map. A present original must exactly match. A missing original requires proof containing result_raw, its result_pin, pre_removal_raw and replacement_raw; hashes, success, exact source/map binding, original observation, raw Git blob identity and strict inverse are checked. `audit_original(expected, removal_pin=None)` authenticates live inputs and historical committed replacement reachability before that seam. It never substitutes a current adapted implementation for the original.

Observation batches use one verified human PowerShell process and one interactive-user lookup. Every entry still rechecks the effective/default-owner token, file owner, file SDDL, all ancestor policies and source hash/length; no ACL observations are reused across files. Apply passes its verified identity to the same-process observer and audits newly created receipts directly through the current-token/path guard, avoiding repeated interactive-user probes. Optional map-declared original and maintained lengths are enforced. Before emitting a plan, a final read barrier rechecks HEAD, tool bytes, request, maps, consumer review and its evidence, and all accepted replacements; HEAD is checked again after that barrier. Committed replacement lookup is cached per unique destination, with final raw-byte checks preserving drift detection.

The custody.py adapter exposes an explicit --audit-originals path to preservation suites; default test invocation does not call custody readers. Its optional pinned removal roster has schema airk.source-cleanup-removal-roster/1 and files:[{source,result:{path,sha256,bytes}}]. Duplicate source rows and partial pins refuse. Every audited map row produces a present-original, proved-removed-original or refused result; missing originals without a bound result refuse. Map and roster pins are rechecked after the pass. SHA/length/roster assertions in permanent tests remain independent of private original availability. CSS is included only as an authored source suffix; the same explicit committed-map/consumer-role rules still govern deletion eligibility.
