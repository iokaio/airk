# Native and client historical proposal source, r1

This versioned research source collection preserves unique authored native, client, browser-test and fixture implementations from the reviewed source-rescue routing r2. It does not apply their behavior to AIRK. Some files describe failed or superseded attempts; preservation is not endorsement, compilation, model execution, numerical qualification or release evidence.

`rescue-map.json` records every original path, raw SHA-256 and length. Exact maintained matches point to their existing owner instead of duplicating code. Exact reachable Git matches, if present, identify their blob and anchor commit. Upstream-only compiler examples, PowerShell implementation and unchanged ORT baselines are explicitly classified as reference evidence rather than authored source. Original artifacts and receipts remain untouched.

Unique source bytes live in `sources/` once per digest. Their filenames prefix the digest to avoid collisions; original relative layouts and duplicate identities remain in the map. Rust files use `.rs.in` because they are historical proposal templates, not unreachable production modules. No source is mounted through `include!` or a path attribute. Header/license notices are retained byte-for-byte.

Inputs are the exact routing rows and original source files. Output is a checked source map plus exact code copies; model weights, data, private indexed content, training examples, credentials, runtime state and receipts are excluded. Synthetic fixture code and machine-specific paths remain source evidence, not portable output authorization.

From the repository root, use `python -B -S scripts/arbiter/research/proposals/native-client-r1/rescue.py` to verify maintained copies and exact owner mappings. `--plan` performs a read-only recensus against the original routing and current maintained/Git identities and prints JSON; it does not write or execute rescued code. All copying requires the repository same-human output preflight and post-write audit. The map is a source-preservation result, not a launcher.

To revive a variant, use the map to recover its original module/sibling layout in a newly reviewed proposal, read the owning live contract and current callers, rebase deliberately, and run focused checks under guarded private outputs. Do not run historical browser scripts, compiler stubs or source-relative helpers directly here: their old paths/seals, imports and process assumptions are intentionally unchanged. Runtime qualification and fresh recipes belong to their current component owners.

## Notices and machine-readable mapping

The standard source-provenance.json maps the182 authored source occurrences and exact existing owners for generic inventory verification; rescue-map.json additionally retains8 upstream-only evidence dispositions. Authored ORT-derived C++ variants retain original headers. Their upstream MIT license and third-party notices are preserved in ORT-LICENSE.txt and ORT-ThirdPartyNotices.txt from the provisioned ONNX Runtime source. TensorFlow-derived Windows code retains its Apache-2.0 header; the repository LICENSE supplies that license text. These notices do not imply ownership of upstream code.

Failed intermediate tests remain identified by their original filenames. Browser scripts retain historical dependencies and must not run from this flat source store. |

`license-provenance.json` records exact original license/notice locations, lengths and SHA-256 values. `source-disposition.json` separately binds the eight upstream-only exclusions to pinned original provenance evidence and actual upstream revisions.

Historical JavaScript without an SPDX header is also stored as .cjs.in/.mjs.in inert templates. This preserves original bytes without introducing executable headerless files; the source map records every rename.
