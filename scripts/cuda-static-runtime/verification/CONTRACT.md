# Historical checkpoint verification

The maintained validators reopen the original source, recipe, receipt, command,
Ninja, archive and custody bytes as data. They never import ignored Python,
launch tools, copy artifacts, mutate inputs or qualify a runtime.
Historical composer/runner/R8/R12 hashes remain authority for what actually ran;
maintained validation source is a distinct implementation identity.
Canonical proof/2 fields and values remain unchanged for identical observations.

Sections require exact order, source ancestry, natural process settlement,
original deadlines, immutable Ninja state copies and unchanged materialized
inputs. Materialized validation retains the original source/tool/configuration,
mirror, CUDA/cuDNN and configured-target checks. A pure command-request owner
reconstructs historical requests without executing the ignored process runner.
Existing older verification modes retain their existing dispatch.

policy_owner.py supplies fresh-plan cpu_owner and identity_and_parent without
importing the historical R8 producer. It authenticates the tracked CPU owner and
lock, checks effective/default-owner/interactive identity with the pinned
maintained guard, and retains the exact approved parent SDDL. Optional original
parent deadlines are checked before and after the bounded guard process. It
changes no ACL and creates no output. Historical policy source pins remain data.
