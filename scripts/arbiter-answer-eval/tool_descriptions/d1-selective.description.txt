Finds, in one call, where the code and documents for a task are when that is not already known. Use it when the task describes behaviour without saying where it lives, spans several parts of the system, or asks for every place something occurs. Do not use it when the task already names the file, type or function to work on, or is confined to one or two files: open those directly, which is cheaper. Call it once at the start; call again only with narrower needs if something is still missing. Pass the task text as task. Fill needs (up to 8 short statements of what you must learn, each at most 400 bytes); add anchors (up to 16 exact strings from the task: identifiers, routes, quoted text, numbers with units; each at most 200 bytes), deliverable (code_change, test, document or analysis) and known (ranges you already hold). The reply is a short map of files and line ranges read from the current files. Read the ranges it lists with offset and limit rather than whole files, and do not repeat its searches.
