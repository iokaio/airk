# Original Compact17 native component owner

This maintained developer owner runs exactly the existing ignored native
cuda_original_context_fp32_t17_component selector. It does not activate a product
profile, export a model, run128/8192, or establish resource20, p95, CAL, semantic,
FP16 or release qualification. Existing NN0 metadata, retained helper bytes and
historical native build/image identities remain unchanged. A new private plan/receipt schema separates this
actual component run from metadata and historical CPU observations.

Preparation requires the reviewed actual six-file native metadata parent receipt
and preserved approved Inference image packet. It reopens their complete original
input/source closure, build receipt, native sources, helper files, runtime census,
profile/model assets and independent three-row numeric fixture. The full original
17/128/8192 denominator stays sealed; only literal all-live-0 at17 tokens is run.
Native profile/request/fixture digests are consumed, never manufactured in Python.
The metadata commands' older image locator is historical; the new plan binds the
separately preserved approved image and its actual build packet explicitly.

A reviewed corrective native build receives a fresh plan. The complete preserved
required_native_sources key set, union the mandatory component source keys, is
rebound to the new authenticated build map. No old key may be dropped, no missing
build key may default to a live hash, and no unrelated key is added. The old
metadata receipt/input_seals remain byte-identical and are checked against their
original build/image packet. For each changed live native path, the fresh plan
records explicit old/new SHA values; the old SHA must match the old build and
the live bytes must match the new build. All other historical inputs still match
their original seals. This is separate historical metadata custody and current
image/source custody, never a claim that changed live source matches an old hash.

The new runtime census explicitly includes any separately named new native image
beside the unchanged original manifest/DLLs. Old images, metadata, failed receipts
and manifest locators are preserved. Current checked-guard bytes are sealed into
the fresh plan; an old plan is not replayed after a guard or native source change.

CLI preparation (all paths absolute; caller supplies reviewed SHA values):

```text
python -B -S scripts/cuda-component-execution.py --prepare
  --approved-script-sha256 SHA --metadata-receipt PATH --metadata-receipt-sha256 SHA
  --image-packet PATH --image-packet-sha256 SHA --powershell PATH
  --output-root FRESH_APPROVED_PRIVATE_CHILD --plan FRESH_PLAN_FILE
```

Preparation creates only that plan file. The immediate parent must exist and
pass the checked human execution guard. Output-root is a fresh direct child of
the existing approved human private campaign root. Root must review the complete
plan and source before the separate --execute-reviewed-component invocation with
--plan, --plan-sha256 and --approved-script-sha256. No plan is permission to infer
an execution result. No automatic retry is provided.

The single original whole-phase120-second cutoff includes authentication, hashes,
launch, model work, native settlement, audits and final output proofs. The existing
owner preserves its original five-second cleanup deadline without converting
forced/unknown cleanup into success. The frozen process bound is16GiB, Job24GiB,
log64MiB; native device planning is24GiB/cold16GiB/warm8GiB/headroom2GiB. The
suspended callback changes only JobMemoryLimit from the primitive's initial16GiB
to the predeclared24GiB, then queries exact flags and limits. This configures the
new owned process Job; it never changes accounts, ACLs or existing processes.
Actual PID/image/user/default-owner SID must match before resume. All children
inherit the verified human token. Native Rust independently observes the exact
process/Job bounds and holds/releases the real host reservation.

Output checks use the reviewed read-only human execution guard plus the existing
exact protected parent policy. Neither helper repairs policy drift. Source and
runtime inputs are immutable; all outputs are create-new. The run owns its temp
and private-census directories. Native output parents are checked before launch;
created output owners are audited before consuming them. Unexpected surviving
outputs are audited too. This is pre/post custody, not race-proof filesystem
sandboxing. There is no credential, account, ACL, interpreter-cache or ambient
DLL fallback. Missing original metadata/access remains a refusal.

A passing native capture binds actual request/input/profile/model/runtime,
independent fixture/producer, image and PID/SID. It must contain exactly one
finite three-score17-token result and original same-artifact/original-FP32 raw
error<=.001, mass<=.05 and exact argmax. Complete final SessionState placement
must cover every reported node/string and use CUDA only. Native host/control
release, unpoisoned teardown, final positive RSS<=16GiB and original timing are
required. The opaque Rust execution identity tuple is retained; Python does not
reimplement the native digest algorithm. Adapter observations are retained and
are not a measured device-peak claim.

The operation journal must contain exactly four ordered events: Load0 start and
return, Numeric1 start and return, with exact original identity/input and one
unchanged native absolute expiry. Returned operations must succeed before expiry.
Unfinished/extra/reordered operations cannot pass. Native result, operations and
stdout are all mandatory final SHA proofs. Every callback runs even after a prior
failure; changed/missing/oversized outputs, source drift, missing owner proof or
late final clock force incomplete. Parent failure and cleanup evidence survive.
Receipts retain started_utc, finished_utc, the original UTC deadline and the
unchanged original monotonic deadline. UTC finish is sampled after final proofs
and before the final monotonic observation. Wall time never renews the cutoff.
Receipt encoding/writing follows the final measured observation, matching the
existing owner convention; receipt retention itself is not included in elapsed.

Cheap tests use literal synthetic captures and injected observations. They prove
refusal/validation behavior only. Real native GPU execution requires separately
reviewed exact inputs and the original retained process/Job/HANDLE evidence.


## Batched read-only output custody

Same-stage path audits share one inherited same-user PowerShell process. Each
batch authenticates the checked guard and PowerShell bytes, proves the human
interactive identity once, and reobserves the effective/default-owner token for
every path, refusing a changed token group roster before deny evaluation. Every
path receives fresh ancestry, reparse, parent ACL and owner
checks; no path, ACL or input-hash cache is introduced. Existing single-path
entry points remain available. Directory creation stays ordered: existing parent
proof, creation, created-owner proof, then use as an output parent. Sibling paths
may share a batch, but a failed prerequisite batch cannot authorize any write.

Every measured batch uses at most the lesser of ten seconds and the original
whole-phase remaining time. The guard checks that budget before/after each path;
the parent rechecks its original monotonic cutoff after the process returns.
Malformed, missing, reordered, late or refused results cannot pass. A batch
returns each attempted path outcome, preserving both actual refusal and expiry
when they coexist, and final proof handling
still attempts all three original callbacks. Final guard errors are retained
separately; an owner-refused file is never hashed/consumed as successful proof.
Input/source hashes and the runtime roster are still fully checked as before.

Only plan creation and final execution-receipt retention use their existing
bounded ten-second audit calls outside a measured execution phase. Final receipt
retention follows finish's original final clock observation, even when execution
expired, so failure evidence is preserved. It grants no new execution time and
cannot change complete=false or refresh a model deadline. Historical plans pin
their original guard bytes; this correction requires a fresh reviewed plan.

## Separate runtime-only diagnostic mode

An explicit runtime-only preparation/execution mode uses a distinct fresh plan,
ignored native selector, native result schema and parent receipt schema. It
retains the same original 120-second whole-phase deadline, 16GiB process/24GiB
Job, 64MiB log, five-second cleanup, same-user/default-owner, exact image/build/
source/runtime custody, all input seals and final-output proofs. It cannot be
selected by changing an existing component plan's selector or weakening the
component validator. Existing component plans and their mandatory operations
journal, successful17-token numerics and complete placement requirements remain.

The diagnostic invokes native runtime admission only. It may observe provider
initialization, driver initialization and module-custody refusal, but must
explicitly report zero model/session/forward operations and no product admission
or qualification. Native full error chains and stage-specific module-census
facts remain unmodified in its authenticated result; bounded output must never
truncate a refusal into a passing runtime result. No model operations journal is
expected for this distinct selector. Its mandatory proofs are its native result
and complete bounded stdout, plus all the original source/custody checks.

A naturally settled, bounded refusal may be a complete diagnostic observation
with runtime_admitted=false and an explicit error. This does not mean runtime,
component, model, device-fit, placement, numeric, resource, CAL or release success.
Native admission success must remain separate from diagnostic completeness.
A refused admission may honestly retain native control/host charge until child
exit: retained=true, poisoned=true, cleanup=false and host-release=false with no
cleanup error. Parent natural retained-HANDLE exit plus empty Job is then the
separate settlement proof; it must never be labeled native clean release. Admitted
results require native clean release. Unknown parent settlement, inconsistent
native retention flags, missing identity/caps, wrong selector/schema, model work,
stale inputs, missing/truncated error evidence or late final observation refuse a
complete diagnostic. The full failed native result remains retained when parent
validation fails. Fresh source/image/guard changes require new reviewed plans.

Exact diagnostic identities are plan airk.private.cuda-runtime-diagnostic-plan/1,
native result airk.private.cuda-runtime-admission-diagnostic/1, parent receipt
airk.private.owned-cuda-runtime-diagnostic/1, and ignored selector
inference_engine::pool::arbiter::qualification::software_v2::cuda_qualification::cuda_runtime_only_admission_diagnostic.
CLI uses --prepare-runtime-diagnostic and --execute-reviewed-runtime-diagnostic;
existing --prepare/--execute-reviewed-component retain their original meaning.
The diagnostic outcome is admitted or refused; diagnostic_error must be null for
complete observations. Admission error/error_chain remain intact, null/empty
only on admitted. Explicit no-work facts include model requests, adapter
observation, device context, scorer, session and operations-journal creation all
false, with forward_count_observed=null. cuInit/provider initialization is allowed;
no adapter enumeration or model session follows it. These facts are native-owned,
not synthesized from a successful process exit. Python retains the entire
existing sealed input closure; this first diagnostic mode does not omit model
asset hashes from parent custody even though the native selector opens no model.

Aggregated airk.private.cuda-module-refusal/1 errors require complete=true,
omitted_count=0 and matching positive unapproved/reported/mismatch counts for
parent completeness. Incomplete census remains retained failure evidence.

The exact native operation_scope clarifies that false operation flags cover
explicit diagnostic caller operations only. Production cuInit admission may
allocate or create contexts internally; the diagnostic makes no contrary claim.
A clean released refusal must also be unpoisoned, matching native settlement.

## Separate load-only placement diagnostic

The explicit placement diagnostic uses plan airk.private.cuda-placement-diagnostic-plan/1,
native result airk.private.cuda-placement-diagnostic/1 and parent receipt
airk.private.owned-cuda-placement-diagnostic/1. The ignored selector is
inference_engine::pool::arbiter::qualification::software_v2::cuda_qualification::cuda_load_only_placement_diagnostic.
It authenticates the same current metadata, model assets, source/image/runtime
closure, suspended PID/user/default owner and original 120-second/16GiB process/
24GiB Job/64MiB stdout/five-second cleanup bounds. No budget is renewed.

This diagnostic permits CPU partitioning only to observe final SessionState
placement. It never returns a Scorer, dispatches a forward, admits a product or
qualifies a component/model. Complete placement observations retain all original
node/string/count/status bounds, including every subgraph. Incomplete placement,
truncated logs, inconsistent teardown, stale custody or late observation refuse
parent completeness while retaining native failure evidence. The production
CUDA-only component and runtime-only diagnostic requirements stay unchanged.

The native owner defines exact placement/log/teardown fields. Parent validation
and literal refusal tests match that owning contract. This mode provides
diagnostic evidence only; it cannot establish component or model qualification.

Native schema and fields are frozen with the owner: outcome placement_observed,
session_load_dispatched/session_created/strict_production_unchanged true; scorer_returned,
forward_dispatched, model_requests_dispatched, qualification, product_admission,
cpu_fallback_disabled false; forward_count_observed null. Exact operation_scope:
Disposable session creation and final placement observation only; no Scorer, forward, hybrid policy or qualification is returned
Clean native release and teardown pre_sync_observed/session_drop_attempted/
post_sync_observed true, integer pending_claims=0 and poisoned=false are required.
Every original common PID/image/default-owner/input/resource/deadline check remains.

Logs carry seen/selected/retained/omitted/bytes integer counters and rows with
location/message. selected=retained+omitted; seen>=selected; retained=row count.
Complete observations require omitted=0 and truncated=false. Combined UTF8
location+2+message is at most4096 bytes/row; total at most65536 bytes, with exact
reported byte count and at most65536 rows. Native failure/partial observations
remain retained; no default or inferred cleanup facts can complete the parent.
The maintained CLI adds --prepare-placement-diagnostic and
--execute-reviewed-placement-diagnostic; fresh reviewed plans are mandatory.

Final native teardown also requires observed session_drop_returned=true and
errors=[]; a drop attempt alone cannot establish return. diagnostic_error must
be null after native post-validation. These checks do not infer cleanup from exit.

The required native roster additionally pins runtime.rs, runtime/cuda.rs and its
contract, the CPU source-transition owner/tests/contract, and new cuda/diagnostic.rs
plus cuda/diagnostic/tests.rs, alongside every historical required owner. Only
those two new diagnostic files may be absent from the original build manifest.
Every new required hash comes from the actual new build and is checked against
live bytes. native_source_introductions records exact absolute path/new_sha256
rows separately; no old digest is invented. Historical required owners and
historical source seals still require original-build matches and explicit
native_source_transition rows. Missing, extra or stale introductions refuse.
The original16MiB native-result cap remains; JSON overhead can cause a full
placement to exceed it and fail closed. No output cap is widened.

The retained Compact profile is admitted through current Context action/Qwen
compiler policy digests, whose owners remain unchanged. runtime.rs is outside
those policy inputs; the separate CPU Focus source supplement is not Compact's
admission path. The new build/source introductions remain freshly pinned and
no old profile qualification is transferred or relabeled by this diagnostic.

## Separate final graph metadata diagnostic

This mode uses distinct plan airk.private.cuda-graph-metadata-diagnostic-plan/1,
native result airk.private.cuda-graph-metadata-diagnostic/1, and parent receipt
airk.private.owned-cuda-graph-metadata-diagnostic/1. Its ignored selector is
inference_engine::pool::arbiter::qualification::software_v2::cuda_qualification::cuda_load_only_graph_metadata_diagnostic.
The scope is disposable session creation and final graph metadata observation;
no Scorer, forward, hybrid policy or qualification is returned. All existing
source/image/asset/PID/user/default-owner/Job/memory/deadline/teardown checks and
16MiB native-result/64MiB stdout caps remain. It requires complete final placement
and complete bounded graph metadata with matching full node identities.

Selected logs retain their original64KiB cap, counters and omitted records.
This separate mode may complete graph capture with selected_logs_complete=false;
it never claims complete logs or changes the old placement mode's truncation
failure. It cannot qualify a component/model or authorize CPU fallback policy.

Native graph metadata schema airk.private.ort-final-graph-metadata/1 owns typed
ordered records and six counters: accepted nodes, values, edges, raw UTF8 span
bytes, constant source-element payload bytes, and accepted records. Checkpoint
callbacks are cancellation-only, not records. Native exact encoded_bytes remains
native-owned; the parent also bounds its independent compact UTF8 JSON encoding
at8MiB without claiming serializers have identical floating-point formatting.
The parent validates graph nesting, identities, references, dimensions, slots,
producer links, attribute and immutable-constant payloads, counters, and the full
placement cross-map. Partial graphs, inconsistent logs or failed teardown refuse.

Graph preparation requires a freshly authenticated static_graph_binding in the
preserved image packet. The full maintained /5 environment -> /3 producer -> /2
historical ancestry verifier runs only in the separate, at-most600s preparation
operation. It checks complete original metadata/build-tree inputs while current
consumed artifacts and source owners are held immutable. Its private
airk.private.cuda-graph-provenance-preparation/1 receipt remains unqualified and
requires an explicit reviewed SHA before graph-plan preparation.

The execution plan is an exact projection of that prepared plan with current
boundary seals and the reviewed preparation pin. Current custody includes
runtime/model/profile/fixture/source inputs, producer/recipe/ancestry documents,
actual archives and native image/Cargo/manifest linkage, metadata outputs and
maintained helper sources. It does not include unused historical headers, objects
or unchanged parent archives merely because they were old input seals.
Those files remain verified historical derivation evidence. The current roster
is deterministically derived and capped at512 including preparation and plan.

Graph execution retains read-only, no-write/no-delete-sharing Windows handles
for every current boundary object throughout dispatch, native Job settlement
and final proof. It replays exact current relationships using held bytes,
including actual executable collector exports read through the held image.
It reobserves identities, content and ACL policies and closes all handles before
the final original120s clock observation. Missing or extra paths, conflicting
pins, source/file identity drift, failed cleanup or any expired boundary refuse.
Native process settlement and resource checks remain independently required.
The existing5s native cleanup bound is not extended.

Fresh graph plans select maintained ownership helpers and the maintained r8
output-policy implementation. The latter must be an exact SPDX-prefix-only copy
of the retained historical policy source, which is evidence and never imported.
The policy's canonical CPU owner and lock remain pinned; its PowerShell uses the
plan's exact absolute interpreter and remaining original deadline. Existing
component/runtime/placement routes are unchanged.

Preparation elapsed time includes full verification and final input/handle
settlement; checked receipt retention is separately bounded and disclosed, as in
the existing parent. The graph operation keeps the original120s whole-phase
clock for input authentication, relationship replay, native work, final output
proofs and input-handle settlement. No execution call repeats the full600s
historical verifier or borrows preparation time for inference.

The exact CLI, boundary derivation, receipt fields and readiness requirements
are specified in [PROVENANCE-PREPARATION.md](PROVENANCE-PREPARATION.md).
The new pure graph-preparation controls cover bounded custody, closure derivation,
relationship substitutions, refusal/cleanup and mode isolation; existing
component controls remain required. Actual Windows custody timing and native
collector execution require separately reviewed fresh inputs and receipts.

The parent retains native metadata bounds: fewer than64 attributes per node,
and exactly one element for readable scalar attribute types1,2,3. The maintained
verifier roster includes verification/checkpoint_sections.py and materialized.py.
Historical raw producer/metadata identities remain unchanged; current verifier
pins and native source introductions are explicit.
