# Compact Windows CUDA Resource20

This private route gives the unprofiled Resource20 selector its own linked
native image, held plan and receipt. It reuses the original complete held
CUDA /6 preparation, unchanged runtime manifest and static archive, exact
R1/R2 predecessor images, passing R2 profile, signed-off 8192-token fixture,
and sealed R2 capacity policy. The image refresh verifies both selected
lib-test images and all current native source bytes through the reviewed
actual Cargo receipt and JSON log.

The whole monotonic allowance is 3600 seconds. Each Load, Warmup and
Sample operation has an original 120-second allowance clipped by the same
parent process cutoff. A native return marker retains that operation's
expiry until the next authenticated start or actual process exit. The
independent watcher waits on Windows process and directory handles. It
authenticates the current journal's file ownership, fixed schema, sequence,
PID, image, input, profile and shared QPC clock while the held Job runs.
It keeps the first failure and invokes the existing owned Job cleanup.
The CPU/Job cap is 32 GiB per process and 32 GiB aggregate. R2's exact
22 GiB CUDA arena and 2 GiB headroom remain inside the 24 GiB device budget.

Use the exact verified Python interpreter from the original graph plan.
Arguments are absolute paths. The refresh uses the [R2 image refresh
arguments](BOUNDED-HYBRID-R2.md) with this Resource20 script and contract and
the additional `--resource-predecessor-packet R2_NATIVE_TEST_IMAGES`.
The `--predecessor-packet` argument remains the exact R1 image inventory.

```text
python -B -S scripts/cuda-component-execution/compact_resource20.py --prepare-plan
  --approved-script-sha256 SHA --approved-contract-sha256 SHA --watchdog-sha256 SHA
  --capacity-policy-sha256 SHA --graph-preparation RETAINED_PREPARATION
  --graph-execution RETAINED_OWNED_GRAPH_RECEIPT --profile-execution PASSING_R2_OWNED_RECEIPT
  --image-packet RESOURCE20_NATIVE_TEST_IMAGES --image-packet-sha256 SHA
  --supplemental-fixture ASSEMBLED_32_1024 --output-root FRESH_DIRECT_HUMAN_CAMPAIGN_CHILD
  --plan FRESH_PLAN

python -B -S scripts/cuda-component-execution/compact_resource20.py --execute-reviewed-plan
  --approved-script-sha256 SHA --approved-contract-sha256 SHA --plan REVIEWED_PLAN --plan-sha256 SHA
```

Preparation holds the existing supplemental provenance as part of the graph
boundary. The Resource20 child receives only the approved graph, exact
retained 8192 row and capacity pins. Owned retention requires one native
result, one stdout/stderr log, and exactly 44 journal events comprising
Load0, Warmup0 and Sample1–20 starts and returns. The parent verifies the
reported 20-sample and independent timing observations, complete final
output hashes, retained input rechecks, natural empty Job, and aggregate
host memory. It produces no ORT trace and grants no product admission.
