# Bounded FP16 conversion custody

This maintained owner performs one explicitly reviewed graph conversion, never
model inference, GPU/native execution, training, activation or qualification.
`--prepare` creates only fresh private metadata after authenticating the frozen
original export source plan, the retained runtime baseline, the selected model's
Windows CUDA FP32 scoring and Resource20 receipts, and separate merged-G5 Clippy
and Nextest/JUnit evidence. The explicit model is Compact or Large. Focus awaits
its independent prerequisite. Preparation creates metadata for review before
an explicit `--execute-reviewed-conversion` invocation.

Preparation requires the exact four-width and separate unprofiled timing
receipts supplied through `--first-fp32` and `--resource-fp32`. Both bind the
same selected graph, native Probe, runtime and 8192-token scoring input.
Compact retains the original 32/32 GiB process/Job and 24 GiB device envelopes
and same-artifact reference. Large retains 48/48 GiB, 44 GiB device, and the
reviewed equivalent-predecessor lineage back to the original export.
Preparation reopens the original numerical and timing outputs and checks the
ten scored and 44 unprofiled journal events under their original deadlines.
It authenticates the native and suspended PID/image/user/default-owner,
actual Job, host reservation and native teardown, natural HANDLE/Job
settlement, and immutable original build and output pins. Each original source
epoch remains distinct from the current G5 readiness source group.
The private `airk.private.fp16-prerequisites/2` manifest binds model, scoring,
timing, current readiness and the maintained validator sources. The conversion
plan's schema and original limits are preserved.
G5 receipts must identify the same native group, unchanged successful inputs,
current required G5/provider/CPU-transition sources and all15 literal G5 tests,
all9 current CPU controls and the new G5 transition control in passing JUnit.
An FP32 receipt cannot substitute for either native-G5 readiness receipt.
These are developer prerequisites, never native profile or product admission.

The generated prerequisite manifest pins all source helpers used to interpret
these records and all consumed evidence. Authentication repeats these predicates
before execution and in final input proof, using the original conversion clock.
Original source-plan and runtime-baseline SHA256 identities are fixed, not supplied
as freely replaceable expected values. Every retained baseline file must remain
present and byte-identical. A fresh complete runtime census explicitly includes
additional files; no roster or metadata-size cap is increased.

Preparation uses one600-second metadata deadline, independent of a later explicit
conversion invocation. It validates prerequisites before writing anything, checks
all output parents, writes only create-new JSON and audits ownership before
consumption. Failed preparation retains partial metadata; no replacement or retry.
The output plan and sibling runtime/prerequisite manifests must be fresh paths
under checkout artifacts with an existing reviewed parent. Full input census and
each JSON document retain the original50000-file and32MiB bounds. The current
execution guard is pinned. Preparation never imports NumPy/ONNX or reads tensors
as tensors; streaming source hashes authenticate the existing weights.

## Inputs and outputs

The private `airk.private.fp16-conversion-plan/1` plan names one Focus, Compact
or Large original graph, complete original external-file closure, maintained
exporter, wrapper, checked PowerShell guard, Python/PowerShell images, all three
unchanged reference ownership helpers, prerequisites, and a full explicit input
census. The runtime manifest contains exactly roots, files and import_paths.
Every regular file beneath each canonical runtime root is included except
`__pycache__` directories. Imports use an absent nonwriting cache prefix, -B -S,
and explicit runtime import paths; actual loaded module files must be in the
sealed census. Unexpected runtime members, changed bytes, aliases, pyc imports,
omitted sidecars or imported modules outside the census refuse. This is Python
module/file custody, not a general native DLL dependency or kernel trust proof.

A fresh output root must be within this checkout's artifacts directory, with an
existing human-owned parent. The original read-only PowerShell guard authenticates
effective/default owner plus interactive logon and conservative inherited policy.
Its exact image/source pins are consumed inputs. Parent calls it before output
creation; the retained suspended process owner authenticates the actual child
image and effective SID, and this runner additionally checks its default owner.
No alternate token, owner, DACL, configuration or global environment is created.

The child receives the parent's original deadline and writes only beneath that
fresh root. A Python audit hook rejects out-of-root writes, spawning and network
connections, verifies each writing parent/previous leaf owner, and checks output
ownership on subsequent Python reads. The ONNX checker is wrapped to check the
new directory, graph and sidecar ownership before its native reader consumes
them. All candidate files are owner-audited again before parent consumption.
This is a bounded cooperative developer tool, not OS sandbox confinement.

Candidate output is exactly model.onnx, weights.bin and the private export
manifest. The parent validates actual graph hash, exact planned weight size and
28 Focus/Compact or36 Large attention-node identities, retaining native_execution
and qualification false. These are conversion facts, not actual Flash/MEA kernel
or numerical/reference acceptance. Original graph bytes and all source sidecars
remain immutable; output failure retains partial files and never retries.

## Original bounds and final proofs

Reuse reference_owned.py2d7a, reference_parent_no_site_r2.pyfe4c and
reference_worker.py9c04, unchanged. The single whole phase is600 seconds, including
initial authentication, output-policy checks, child startup/conversion, natural
settlement, output validation and every final proof. Process/Job committed limit
is8GiB, log bound64MiB, emergency/settlement cleanup remains the helper's original
five seconds. No new timer is granted to the child or to final hashing. Every PowerShell guard
subprocess receives only the remaining original deadline as its timeout; timeout
and late guard parsing remain failures. The receipt records UTC start/end and the
original UTC/monotonic deadline; final UTC is sampled before final monotonic time.

The parent requires actual retained-HANDLE exit0, one naturally settled child,
unforced empty original Job, retained handle-close proof and measured committed
memory within8GiB. Leader exit alone never passes. Six final callbacks are always
attempted: graph, weights, manifest, stdout, worker result and complete original
input/runtime/plan census. Missing/malformed callback rows, changed validated
output bytes, input drift or an original failure make the receipt nonpass. The
same monotonic clock is sampled last, after every callback, and late final work
cannot become a pass. Final receipt serialization/write and its owner audit are
outside measured elapsed scope, disclosed explicitly; receipt writing never
changes an already failed result.

`airk.private.fp16-conversion-execution/1` is developer custody only. No existing
native model/profile/wire/digest format changes. Passing conversion still requires
independent whole-DAG and publisher-byte validation, original/matching-half
numerical checks, actual native placement/kernel completion, resources, task/CAL,
and product acceptance under their separate exact identities.

Fresh preparation now seals the byte-identical maintained ownership primitives
under scripts/cuda-native-execution/helpers. Historical artifact source copies
and old plans retain their original identities; no conversion is rerun or
qualified by this source relocation.

## Independent Compact T32 reference

The [Compact verifier](verify_compact.py) consumes the reviewed conversion
receipt and its matching plan under a separate owned Windows CPU reference
phase. Use the pinned Python from the plan. The parent supplies the original
absolute monotonic deadline within 600 seconds, holds the reviewed inputs
and captures the child's stdout under its checked output parent.

```text
python -I -B -S -X pycache_prefix=ABSENT_PREFIX_FROM_PLAN
  scripts/arbiter-fp16-execution/verify_compact.py
  --conversion-receipt ABSOLUTE_EXECUTION_JSON --conversion-receipt-sha256 SHA
  --conversion-plan ABSOLUTE_PLAN_JSON --conversion-plan-sha256 SHA
  --deadline-monotonic ORIGINAL_PARENT_MONOTONIC_EXPIRY
```

Use `--owned-output FRESH_CAMPAIGN_CHILD` in place of `--deadline-monotonic`
to run through the maintained parent. It retains one same-user child under a
32 GiB process and aggregate Job cap, the original independent 600-second
whole deadline, a 64 MiB log and five-second cleanup. The parent authenticates
the suspended child and requires a natural exit, empty Job and retained handle
closure before it retains the independent proof.

The parent sets `CUDA_VISIBLE_DEVICES` to the empty string before launch and
supplies the verified human token, private cache/temp locations, and offline
dependency settings. The worker uses the conversion plan's pinned Python and
library census and only maintained source imports. Its Python audit hook
refuses filesystem mutations, new processes, and network connections. Torch's
deterministic setup can attempt an idempotent directory creation on the exact
existing audited cache directory. New cache files and subdirectories refuse.
The
parent retains responsibility for native-library effects, Job bounds and
settlement, and proof ownership.

The worker reopens the conversion outcome, original Compact export and sidecar
closure, retained T32/N8 fixture and publisher proof. The independent graph
and parameter check precedes one CPU Torch forward derived from authenticated
publisher weights. The fresh matching-half vector and the original independent
FP32 vector retain separate identities under the same unchanged native input.

On success the worker emits one `AIRK_FP16_COMPACT_REFERENCE ` line containing
the UTF-8 JSON record `airk.private.compact-fp16-independent-proof/1`. The owned
parent retains the bounded stdout and may write the JSON bytes after that marker
to an audited fresh proof file for the native metadata selector. The record
contains the conversion/output pins, complete graph and parameter proof, and
both score arrays. Native dispatch, placement, resources and qualification
require their own later observations.

## Owned Compact metadata and T32 probe

The [native probe parent](probe_compact.py) owns one exact test invocation.
The first invocation consumes the reviewed Compact Prepare request and the
independent proof. The second consumes the emitted Probe request and native
`metadata/metadata-receipt.json` from the passing first invocation.

```text
python -I -B -S scripts/arbiter-fp16-execution/probe_compact.py {metadata|graph|t32}
  --request ABSOLUTE_REQUEST --request-sha256 SHA
  --evidence ABSOLUTE_EVIDENCE --evidence-sha256 SHA
  --image ABSOLUTE_STAGED_IMAGE --image-sha256 SHA
  --build-receipt ABSOLUTE_REVIEWED_CARGO_RECEIPT --build-receipt-sha256 SHA
  --powershell ABSOLUTE_POWERSHELL --powershell-sha256 SHA
  --output FRESH_CAMPAIGN_CHILD
```

Each phase uses one original 120-second whole deadline and a 32 GiB process
and aggregate Job, with suspended-image and token proof and natural HANDLE and
Job settlement. It retains full bounded stdout and native outputs under the
fresh checked child. The T32 invocation inherits GEMM2 and attention debug
logging before ORT initialization. A passing T32 result requires all 28 named
FP16 FlashAttention records, the durable returned operation and native
synchronization, strict placement and teardown. The matching FP16 reference
requires finite scores, raw error at most 0.001, mass error at most 0.05 and
identical argmax. Against original FP32, mass error is limited to 0.05 and the
finite raw error and argmax verdict are retained as diagnostics. A fresh
receipt binds the actual native image and parent source. Retained outcomes
use the policy under which they ran. The T32 component supplies engineering
evidence for the accepted Context qualification rule. Task quality needs
paired judged requests.
[Accepted Context FP16 rule](../../docs/arbiter/final-plan.md#accepted-context-fp16-task-quality-qualification)

The receipt records failures and retained raw evidence when any check refuses.
Device capacity limits and adapter observations support the component receipt.
Measured device peak and product qualification require separate evidence.

The graph mode consumes the exact same emitted Probe and metadata as T32.
It records one Load operation and retains the complete typed, optimized
graph and final placement with observed disposal and synchronization.
Its private result schema is airk.private.compact-fp16-graph-diagnostic/1.
The result contains zero scorer forwards and serves as input to the FP16
placement review. T32 continues to require strict execution and all
original FlashAttention evidence.
