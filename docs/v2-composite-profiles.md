# Composite extraction revision 2

D11 activates extraction contract 2 for HTML, Vue, Svelte, Astro, MDX, Razor and notebooks. Readers explicitly accept contracts 1 and 2; unchanged standalone profiles remain contract 1. Mapped public binding requires contract 2. Old readers reject those profiles instead of treating region-local code spans as original source offsets. Source-map version 1 and chunk strategy 2 remain unchanged. Public `DocumentLocation::Mapped` carries the original host spans and embedded/cell locator; code/signature byte spans remain explicitly region-local. Unembedded binding retains its existing wire representation.

The scanner passes fresh path-free payloads directly to persistence. It never flattens mapped artifacts and reconstructs their payload by legacy conversion. Effective host profiles include the relevant child-profile identities, so changes to supported child extraction invalidate the host cache. Source hashes always identify original bytes. Rebinding a compatible moved host changes public paths while retaining verified payloads. Explicit file/context reads use verified retained original host bytes; decoded chunks cannot masquerade as original source lines.

One host allowance covers 256 attempted regions, depth 4, 100,000 map segments, 500,000 parser/walk work units, 10,000 facts, 16 MiB decoded text and 64 MiB fingerprint input. Empty, rejected and malformed attempts consume allowance. Markdown work conservatively charges its byte length before parsing against the shared work allowance, so large prose children can reach that bound before the native source ceiling. A single continuity budget covers host and child units. Unknown child adapters remain explicit omissions; specialized adapters without a shared walk cannot reset the allowance.

HTML retains tags and adds literal supported JS/TS and CSS/SCSS blocks. Vue/Svelte add written component/directive/slot/prop/event and setup/module/style markers. Astro supports leading TypeScript frontmatter and explicit script/style children. MDX supports bounded standalone ESM/JSX/expression islands, preserves prose outside excluded syntax/comments/fences and remains partial for mixed inline constructs. Razor supports directives, routes, injection and contiguous C# `@code`/`@functions` bodies; mixed template bodies remain partial. No host invokes a compiler, evaluates expressions or fetches linked resources.

Notebook format 4 admits only supported code/Markdown cell source strings or arrays, with exact JSON escape/surrogate maps and no invented array separators. Outputs/attachments are excluded from retrieval chunks. Original JSON remains available through explicit original-source reads. Duplicate cell IDs lose identity qualification; execution position is not a durable identity. Continuity uses unique written cell IDs or unique profile/kind embedded regions; identical sibling regions remain ambiguous. Original host location changes are fingerprinted separately from unchanged child declarations.

SCSS uses pinned `cortexkit-tree-sitter-scss` 1.0.1 (MIT, ABI 14, C scanner). Its parser/scanner content matches upstream SCSS 1.0.0 with the fork's MSVC build flag correction. The omitted license is pinned to upstream revision `0254de4cfbf81d152447aa14285d931adf4ab0f3` and SHA-256 `0eea8dc45e89deeb03c7799bbbc7b4688f365fb274562f4540ecfebdea82e727`. Selectors, variables, mixins/includes, functions and use/import/forward syntax are bounded evidence without Sass evaluation. Non-ASCII selectors and interpolation remain partial; Unicode strings/CRLF have separate exact-location fixtures. SCSS does not advertise declaration continuity fingerprints.

Razor uses `tree-sitter-razor` 0.1.0 (MIT included in its archive, ABI 14, C11 parser/scanner), upstream revision `ecc86b71b1252a5d788cf5f319a805664825aaee`. Both new grammars use the existing Tree-sitter 0.25.10 runtime and compiled on Windows and in the local Linux container. Generated notices cover 438 dependencies, retaining the four pre-existing separate-license-text review flags.

Qualification receipts are recorded in the [ledger](architecture-v2-ledger.md). Final packaging, clean build/size comparisons, macOS, installed clients and real-agent trials remain phase 12 work. H2/model-sharing are separate packages, not implied by composite extraction.
