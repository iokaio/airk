# 0.1.0 implementation review

This review covers native ingestion, collection storage, retrieval, usage recording, scheduling, MCP, the VS Code extension, packaging and repository controls. It includes newly implemented roadmap components. It is not a security certification or approval to release. The [validation record](validation.md) distinguishes observed tests from untested release requirements; the [release checklist](releases/release-checklist-0.1.0.md) remains the candidate approval record.

## Correctness findings addressed

| Finding | Change and regression evidence |
|---|---|
| Context could select evidence from two different published revisions | Kernel context retrieval pins one snapshot; persistent lexical/vector/hybrid queries share one generation and model identity. Publication/concurrent-reader fixtures exercise the boundary. |
| Whole snapshots coupled every query to all retained source text | Streaming ingestion stores original sources and extracted artifacts by digest. Compact, digest-bound inventories and immutable generation catalogs serve individual artifact reads; unchanged content is reused. Migration, tampered inventories, quota rollback and leased-generation blob collection have regression fixtures. |
| Scheduler status depended on write capacity and trusted negative persisted counters | Status uses read-only SQLite, including legacy schema reads. Queue writes reserve database and rollback-journal capacity; failed admission leaves pending work intact. Invalid negative counters and retired data roots fail explicitly. |
| Relocation could fail on transient lifecycle contention during parallel Unix crash tests | Initial exclusive root acquisition retries for a bounded 250 ms before taking other locks. Shared-reader and subsequent acquisitions remain fail-fast, preserving lock order. A short-lived-reader regression and 50 parallel Linux store-suite repetitions passed. |
| Persistent publication and pruning failed on Windows with open handles | Lexical reload uses explicit immutable-generation behavior; model sync uses writable handles; reader lock files live outside removable generation directories. Windows publication, old-reader pruning and removal fixtures exercise real filesystem behavior. |
| Windows storage paths beyond 260 characters could fail atomic temporary-file publication | Managed data paths resolve through an existing canonical ancestor without creating state during reads. Temporary object and writer-marker publication use canonical parents, retaining atomic no-clobber behavior. Long-path regressions and a CLI lifecycle smoke cover existing/new storage, queries, aliases, quotas, usage and relocation while preserving source hashes. |
| A crashed writer could leave indexing permanently blocked | Versioned writer markers are protected by stable OS advisory locks and recover after process death. Atomic no-clobber marker creation preserves exclusion with older writers. A child-process crash test verifies recovery. |
| Scheduled edits or registered roots could be mishandled between worker passes | Automatic edits during a running pass advance the revision; repeatedly dirty roots do not monopolize the queue. Registered roots are checked again before scanning/indexing, and unsupported root encodings are refused rather than collapsed into a lossy identity. |
| Coverage could imply completion despite unsupported or capacity-limited inputs | Native eligibility/freshness inventory reports incomplete, blocked, stale and failed states; unsupported binaries no longer consume eligible source capacity. Extension rounding and incomplete-state tests prevent false 100%. |
| An initial editor index could race a coverage write, and the command could hide the failure from callers | Coverage, indexing and pruning share a local queue keyed by data directory and collection. Explicit commands notify and reject on failure. A held-coverage regression verifies indexing waits; simulated external contention preserves pending work and permits a later explicit retry. Read-only requests and other collections remain independent. |
| Workspace aliases could make editor paths differ from canonical collection roots | Active-folder selection and event eligibility retain verified workspace spellings alongside canonical roots. Alias paths map back to the same collection before existing eligibility checks, preserving nested-root selection and managed-state exclusion without filesystem reads on editor events. |
| Excluded binary-heavy trees could evade the eligible-source budget | Independent traversal and raw-read limits abort a pass without replacing the previous generation. These limits complement eligible-source and extracted-text caps. |
| Trees dominated by unsupported files or directories could evade eligible-corpus work limits | Independent discovery-entry and raw-read budgets abort the whole index pass before publication. Small-budget regressions cover unsupported binary reads and directory-only traversal. These bounds do not forcibly preempt native parsers. |
| Background scheduling could lose cross-host edits, starve other roots or follow a replaced root | Automatic notifications advance an active revision; completed batches yield to older pending work; native watch reconciles between jobs. Canonical root bindings reject replacement symlinks and non-UTF-8 identities. |
| Usage recording could race clearing/removal or distort totals | Bounded SQLite aggregate transactions, incarnation checks, lifecycle locks, replay deduplication and wide signed arithmetic prevent stale resurrection and fabricated positive savings. SQLite page-cap rollback and late-writer fixtures cover these paths; actual full-disk fault campaigns remain qualification work. Native scheduler jobs count actual work once in the job collection, without also counting joined CLI callers. |
| Optional measurements could mix scenarios with native observations or retain private text | Explicit numeric imports separate client-reported/user-supplied provenance, model/tokenizer identity, alternative contexts, sessions and paired-task quality bins. Local byte-BPE calibration consumes bounded transient samples and retains only counts/definition identity. Dated price scenarios use signed fixed-decimal arithmetic and preserve unknown cache splits. Native request totals and provider-billing claims remain separate. |
| Usage data could bypass the shared quota or keep expired optional rows indefinitely | Ledger writes reserve bounded DB/journal growth under the managed quota. Implicit admission is nonblocking with brief checked inventory budgets, while clear reclaims without VACUUM growth. Ordinary and supplemental activity prune expired rows from both histories. Category/replay/disabled/quota/retention regressions and a public CLI smoke cover these contracts. |
| Publication could fail spuriously when usage reserved capacity between a quota status check and publication reservation | `reserve_available` now computes and reserves available publication capacity under one quota lock. Concurrent accounting cannot invalidate a separate status-derived allowance; actual capacity exhaustion still fails before publication. |
| Dense facts could exhaust a fixed catalog cap despite available configured storage | Removed the 1 GiB catalog cap, the artifact-size multiplier and the 4 GiB publication-attempt ceiling. Catalog admission uses remaining configured quota and observed disk capacity after other components are charged, preserving room for pointer/WAL/SHM writes. A long-citation regression reproduces the old failure and verifies atomic publication under sufficient policy; small-disk arithmetic remains bounded. |
| Unix relative or aliased managed paths could turn index writes into source-change events | Watchers resolve the existing managed-path ancestor without creating directories and filter its canonical location before admitting callbacks. Relative-path and Unix symlink/event regressions cover the boundary. |
| Linux benchmark RSS could include memory inherited from its Python launcher | Qualification hashes files incrementally and reports sampled post-exec executable RSS separately from lifetime `wait4` memory. A large-parent/small-child regression exercises the distinction; absent samples remain unknown. |
| Delimited headers and empty DOCX paragraphs lost original coordinates | CSV headers retain multiline/leading-blank source ranges; empty DOCX paragraphs retain their original block ordinals. Dedicated extraction regressions cover both. |
| DOCX tables needed more than flattened prose | Row/cell facts preserve header candidates or explicit headers, logical columns and merge markers. Tabs, breaks, entities and CDATA preserve text boundaries. Header propagation is bounded before cloning. |
| XLSX requirements lacked native indexing | Workbook/worksheet relationships, shared/inline strings, stored formulas/caches, sparse addresses, merge markers and calendar evidence produce bounded row/cell and prose facts. Shared-string expansion is capped before retaining repeated values. |
| OOXML could silently accept incomplete parts or invalid attributes | Selected parts require one complete bounded XML root, valid attributes and no DTD; unexpected root content, duplicate attributes, missing parts and unsafe relationships fail explicitly. |
| Live provider output could be stale, escape its workspace or erase native evidence | Explicit LSP/Ctags adapters bind producer, executable, source and declared build identities; validate original coordinates; reject external/unindexed or modified copied sources; and replace only the imported domain. Process groups/jobs, bounded framing/output and deadlines control subprocess lifetime. Real Windows providers and public CLI fixtures exercise publication, source preservation and invalidation. |
| Raising indexing limits could silently enlarge live-provider work | Persisted scan limits have independent validation ceilings, while live providers retain their own 10,000-file/64 MiB source-copy limit, selected-path limits and bounded responses. A regression rejects an oversized provider inventory before copying sources. |
| Manual publishing lacked an exact candidate verification path | Dispatch builds all four platforms; verification binds source SHA, version, channel, locks, toolchain, native target and every payload digest. OIDC publication uses the verified VSIX files from that run. Tampering and incomplete-platform tests fail closed. |

## Delivered capabilities

Disk-backed generations now combine SQLite revision/fact catalogs, persistent Tantivy lexical indexes and Microsoft's DiskANN algorithms using AIRK's portable file provider. Deliberately provisioned local assets support both static word-vector pooling and a real CPU ONNX BERT-family encoder with WordPiece tokenization, masked mean pooling and normalization. The pinned MiniLM fixture matches an independent ONNX Runtime oracle and retrieves all six fixed expected passages; this establishes adapter correctness on that fixture, not production semantic quality. Missing or unsupported assets fail explicitly, without a cloud fallback. Readers hold generation leases, and maintenance previews/prunes obsolete unleased generations.

The durable native scheduler coalesces revision requests across workers sharing a data root, preserves pause/failure state, and recovers interrupted work. Native Windows/macOS/Linux filesystem-event adapters and periodic reconciliation feed the same queue. Explicit per-user service commands support Task Scheduler, systemd user services and launchd; the real Windows install/start/edit/stop/restart/uninstall smoke passed. Linux/macOS login-session lifecycle remains separate qualification. The extension exposes measured coverage, queued indexing, usage and generation maintenance while preserving workspace trust and collection isolation. A two-real-binary upgrade test verifies that an existing cached helper continues working after extension replacement and a changed trusted digest receives a new cache path.

Collection scan limits are explicitly configurable with bounded ceilings and conservative defaults. Source bytes, extracted bytes, file count, discovery entries and raw-read work have independent limits. Exceeding a pass budget preserves the previous generation; larger permitted limits are not measured capacity guarantees. Local LSP and Ctags adapters supplement source/build-bound SCIP imports. LSP uses advertised symbol/reference/definition/type/implementation/call-hierarchy evidence; Ctags contributes syntax declarations only. Explicit local Tesseract OCR, with Poppler rendering for PDFs, retains selected original page numbers and executable/model/source provenance. Providers are trusted local executables selected by the operator, without automatic downloads or cloud execution.

Local usage now has both native observations and opt-in evidence inputs. Native reports include serialized bytes, latency, indexing reuse, measured scan/extraction and publication times, bounded logical disk samples/deltas, and available OS process CPU, peak RSS and I/O counters with explicit semantics and sample coverage. Overlapping process spans suppress counter attribution; missing counters remain unknown, and transfer counters are never relabeled physical disk I/O. `usage import` accepts bounded content-free client/session and paired-task records; `usage calibrate` supports exact fingerprinted byte-BPE definitions and offline Hugging Face BPE/WordPiece/Unigram/WordLevel pipelines with explicit framing; `usage report --price-scenario` applies explicitly supplied dated input rates. The [reporting contract](usage-reporting.md) documents limits, provenance and commands. Imported numbers cannot silently become AIRK request totals, verified provider usage or billed savings.

The live main ruleset requires a PR, current checks, resolved conversations and linear history, with no bypass/force push/deletion. Zero mandatory approvals matches the compared repositories; this is not a claim that another reviewer approved this change. The publishing environment permits only `main`.

The extension listing and [content specification](extension-content.md) explain the purpose, agent-specific setup and original illustrations. DOCX and XLSX extraction are documented in [document indexing](document-indexing.md). Build/publish operations are documented in [release workflow](release-workflow.md).

## Remaining qualification

The core implementation now includes the previously planned disk indexes, local transformer inference, streaming source storage, native events/services, quotas/retention, source aliases, relocation, live providers/OCR, usage and coverage. Full roadmap acceptance and release qualification are **not complete**. The following limits remain explicit:

- Content-addressed streaming ingestion and lazy artifact reads are implemented. [Configurable limits](ingestion-limits.md) permit larger explicitly selected profiles, while [scale qualification](scale-qualification.md) records the workloads actually measured. Validation ceilings do not establish production capacity, physical disk I/O or retrieval quality; compact metadata and ANN build memory remain bounded implementation costs.
- Root/collection application-byte reservations cover participating publication, database/journal, model and temporary writes while counting retained generations. These are logical-byte quotas, not physical filesystem or external-writer enforcement. Explicit transactional relocation verifies copies, retains old managed state and recovers interrupted preparation; source aliases are revision-bound. Windows/Linux process-kill and isolated full-volume admission/recovery campaigns passed. Mid-publication disk exhaustion, physical power loss, retained-root capacity planning and full platform qualification remain required.
- Real local ONNX inference and fixed-fixture numerical/retrieval qualification are delivered. Held-out production-corpus relevance, model/language upgrades, long-context behavior and full native platform inference performance remain unqualified. Synthetic ANN recall and a small MiniLM fixture do not establish general semantic quality.
- Native watchers and per-user service lifecycle commands are delivered. Windows Task Scheduler lifecycle was exercised; reboot/login recovery, systemd user sessions, launchd and network-filesystem events still require corresponding host evidence.
- Live LSP/Ctags, explicit OCR and source/build-bound imports are delivered. Original fixtures and selected real Windows tools do not establish every language server, build environment, framework or document's accuracy. Resolved relationships remain provider-asserted and capability-scoped; OCR can misrecognize text and does not reconstruct table geometry or unselected pages.
- OS process resource probes and local Hugging Face tokenizer pipelines are implemented. Physical I/O attribution, spawned-provider resource attribution, representative held-out calibration, provider-specific chat framing and causal paired-task/billing savings remain unverified. Imported client counters are explicitly self-reported; hypothetical price equivalents are not verified bills.
- Actual macOS installed-host/editor qualification and signing/notarization are deferred to the maintainer's original Mac. Remote editor hosts, full client qualification, production scale/relevance and physical full-disk/power-loss campaigns remain release evidence requirements. The helper replacement/cache boundary is tested; this does not qualify all remote or installed upgrade/rollback paths.
- Four standalone upstream legal-text gaps remain flagged: PDF-Extract, Adobe-CMap-Parser, Type1-Encoding-Parser and htmlescape. Publisher declarations are preserved; legal review and publisher-account trust are not inferred from build success.

Keep required release gates open until evidence is recorded or the maintainer explicitly accepts or defers them. The Mac signing handoff does not qualify that platform. Required DCO, hosted checks and release approvals remain separate gates.
