# 0.1.0 implementation review

This review covers native ingestion, collection storage, retrieval, usage recording, scheduling, MCP, the VS Code extension, packaging and repository controls. It includes newly implemented roadmap components. It is not a security certification or approval to release. The [validation record](validation.md) distinguishes observed tests from untested release requirements; the [release checklist](release-checklist-0.1.0.md) remains the candidate approval record.

## Correctness findings addressed

| Finding | Change and regression evidence |
|---|---|
| Context could select evidence from two different published revisions | Kernel context retrieval pins one snapshot; persistent lexical/vector/hybrid queries share one generation and model identity. Publication/concurrent-reader fixtures exercise the boundary. |
| Whole snapshots coupled every query to all retained source text | Streaming ingestion stores original sources and extracted artifacts by digest. Compact, digest-bound inventories and immutable generation catalogs serve individual artifact reads; unchanged content is reused. Migration, tampered inventories, quota rollback and leased-generation blob collection have regression fixtures. |
| Scheduler status depended on write capacity and trusted negative persisted counters | Status uses read-only SQLite, including legacy schema reads. Queue writes reserve database and rollback-journal capacity; failed admission leaves pending work intact. Invalid negative counters and retired data roots fail explicitly. |
| Relocation could fail on transient lifecycle contention during parallel Unix crash tests | Initial exclusive root acquisition retries for a bounded 250 ms before taking other locks. Shared-reader and subsequent acquisitions remain fail-fast, preserving lock order. A short-lived-reader regression and 50 parallel Linux store-suite repetitions passed. |
| Persistent publication and pruning failed on Windows with open handles | Lexical reload uses explicit immutable-generation behavior; model sync uses writable handles; reader lock files live outside removable generation directories. Windows publication, old-reader pruning and removal fixtures exercise real filesystem behavior. |
| Windows storage paths beyond 260 characters could fail atomic temporary-file publication | Managed data paths resolve through an existing canonical ancestor without creating state during reads. Temporary object and writer-marker publication use canonical parents, retaining atomic no-clobber behavior. Long-path regressions and a CLI lifecycle smoke cover existing/new storage, queries, aliases, quotas, usage and relocation while preserving source hashes. |
| A crashed writer could leave indexing permanently blocked | Versioned writer markers are protected by stable OS advisory locks and recover after process death. Atomic no-clobber marker creation preserves exclusion with older writers. A child-process crash test verifies recovery. |
| Scheduled edits or registered roots could be mishandled between worker passes | Automatic edits during a running pass advance the revision; repeatedly dirty roots do not monopolize the queue. Registered roots are checked again before scanning/indexing, and unsupported root encodings are refused rather than collapsed into a lossy identity. |
| Coverage could imply completion despite unsupported or capacity-limited inputs | Native eligibility/freshness inventory reports incomplete, blocked, stale and failed states; unsupported binaries no longer consume eligible source capacity. Extension rounding and incomplete-state tests prevent false 100%. |
| An initial editor index could race a coverage write, and the command could hide the failure from callers | Coverage, indexing and pruning share a local queue keyed by data directory and collection. Explicit commands notify and reject on failure. A held-coverage regression verifies indexing waits; simulated external contention preserves pending work and permits a later explicit retry. Read-only requests and other collections remain independent. |
| Excluded binary-heavy trees could evade the eligible-source budget | Independent traversal and raw-read limits abort a pass without replacing the previous generation. These limits complement eligible-source and extracted-text caps. |
| Trees dominated by unsupported files or directories could evade eligible-corpus work limits | Independent discovery-entry and raw-read budgets abort the whole index pass before publication. Small-budget regressions cover unsupported binary reads and directory-only traversal. These bounds do not forcibly preempt native parsers. |
| Background scheduling could lose cross-host edits, starve other roots or follow a replaced root | Automatic notifications advance an active revision; completed batches yield to older pending work; native watch reconciles between jobs. Canonical root bindings reject replacement symlinks and non-UTF-8 identities. |
| Usage recording could race clearing/removal or distort totals | Bounded SQLite aggregate transactions, incarnation checks, lifecycle locks, replay deduplication and wide signed arithmetic prevent stale resurrection and fabricated positive savings. SQLite page-cap rollback and late-writer fixtures cover these paths; actual full-disk fault campaigns remain qualification work. Native scheduler jobs count actual work once in the job collection, without also counting joined CLI callers. |
| Optional measurements could mix scenarios with native observations or retain private text | Explicit numeric imports separate client-reported/user-supplied provenance, model/tokenizer identity, alternative contexts, sessions and paired-task quality bins. Local byte-BPE calibration consumes bounded transient samples and retains only counts/definition identity. Dated price scenarios use signed fixed-decimal arithmetic and preserve unknown cache splits. Native request totals and provider-billing claims remain separate. |
| Usage data could bypass the shared quota or keep expired optional rows indefinitely | Ledger writes reserve bounded DB/journal growth under the managed quota. Implicit admission is nonblocking with brief checked inventory budgets, while clear reclaims without VACUUM growth. Ordinary and supplemental activity prune expired rows from both histories. Category/replay/disabled/quota/retention regressions and a public CLI smoke cover these contracts. |
| Delimited headers and empty DOCX paragraphs lost original coordinates | CSV headers retain multiline/leading-blank source ranges; empty DOCX paragraphs retain their original block ordinals. Dedicated extraction regressions cover both. |
| DOCX tables needed more than flattened prose | Row/cell facts preserve header candidates or explicit headers, logical columns and merge markers. Tabs, breaks, entities and CDATA preserve text boundaries. Header propagation is bounded before cloning. |
| XLSX requirements lacked native indexing | Workbook/worksheet relationships, shared/inline strings, stored formulas/caches, sparse addresses, merge markers and calendar evidence produce bounded row/cell and prose facts. Shared-string expansion is capped before retaining repeated values. |
| OOXML could silently accept incomplete parts or invalid attributes | Selected parts require one complete bounded XML root, valid attributes and no DTD; unexpected root content, duplicate attributes, missing parts and unsafe relationships fail explicitly. |
| Manual publishing lacked an exact candidate verification path | Dispatch builds all four platforms; verification binds source SHA, version, channel, locks, toolchain, native target and every payload digest. OIDC publication uses the verified VSIX files from that run. Tampering and incomplete-platform tests fail closed. |

## Delivered capabilities

Disk-backed generations now combine SQLite revision/fact catalogs, persistent Tantivy lexical indexes and Microsoft's DiskANN algorithms using AIRK's portable file provider. Local static word-vector assets must be deliberately provisioned with license and digest metadata. Missing assets fail explicitly; there is no cloud fallback. Readers hold generation leases, and maintenance previews/prunes obsolete unleased generations.

The durable native scheduler coalesces revision requests across workers sharing a data root, preserves pause/failure state, and recovers interrupted work. Its explicit foreground watch process periodically reconciles registered roots even without the editor. The extension exposes measured coverage, queued indexing, usage and generation maintenance while preserving workspace trust and collection isolation.

Local usage now has both native observations and opt-in evidence inputs. Native reports include serialized bytes, latency, indexing reuse, measured scan/extraction and publication times, and bounded logical disk samples/deltas. `usage import` accepts bounded content-free client/session and paired-task records; `usage calibrate` counts supplied logical JSON with an exact, fingerprinted byte-BPE definition; `usage report --price-scenario` applies explicitly supplied dated input rates. The [reporting contract](usage-reporting.md) documents limits, provenance and commands. Imported numbers cannot silently become AIRK request totals, verified provider usage or billed savings.

The live main ruleset requires a PR, current checks, resolved conversations and linear history, with no bypass/force push/deletion. Zero mandatory approvals matches the compared repositories; this is not a claim that another reviewer approved this change. The publishing environment permits only `main`.

The extension listing and [content specification](extension-content.md) explain the purpose, agent-specific setup and original illustrations. DOCX and XLSX extraction are documented in [document indexing](document-indexing.md). Build/publish operations are documented in [release workflow](release-workflow.md).

## Remaining qualification and optional extensions

The core implementation now includes the previously planned disk indexes, streaming source storage, native scheduling, quotas/retention, source aliases, relocation, usage and coverage. Full roadmap acceptance and release qualification are **not complete**. The following limits and optional extensions remain explicit:

- Content-addressed streaming ingestion and lazy artifact reads are implemented. The existing corpus/file/pass limits remain until larger workloads have measured RSS, physical disk I/O, latency and retrieval quality evidence; compact metadata and ANN build memory remain bounded implementation costs.
- Root/collection application-byte reservations cover participating publication, database/journal, model and temporary writes while counting retained generations. These are logical-byte quotas, not physical filesystem or external-writer enforcement. Explicit transactional relocation verifies copies, retains old managed state and recovers interrupted preparation; source aliases are revision-bound. Power-loss/full-disk fault campaigns, physical capacity planning for retained old roots and native platform qualification remain required.
- Local vectors use static word-vector pooling. Transformer/ONNX inference and a qualified production model are not delivered. Synthetic ANN recall does not establish semantic relevance on real repositories.
- Periodic native reconciliation is implemented, but OS event watchers and installed-service lifecycle management are not. The user must keep the explicit worker running.
- Broader language/provider adapters, OCR, live LSP/Ctags and complete resolved graphs remain beyond the implemented native/SCIP slice.
- Portable process CPU and physical I/O counters remain unknown. Local byte-BPE calibration and explicit session/paired-task inputs are implemented, but provider tokenizer/framing compatibility, other tokenizer algorithms, representative held-out calibration and causal task/billing savings require separate implementation or real measurement evidence. Imported client counters are explicitly self-reported; hypothetical price equivalents are not verified bills.
- macOS/remote/upgrade/signing, physical fault testing, representative large-repository benchmarks, full client qualification and publisher-account trust remain release work. Dependency notice gaps are explicitly listed for legal review.

These are implementation or qualification gaps, not completed checkboxes. Keep them as release blockers under the requested full-roadmap scope until resolved or explicitly rescoped by the maintainer. No commit sign-off, publication approval or successful hosted run is implied by this document.
