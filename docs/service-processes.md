# Native process ownership and cleanup

This records opt-in service development behavior, not installed-platform qualification. The [implementation checklist](service-implementation-checklist.md) retains the complete drain-accounting and owner-crash gates.

`airk-process` supplies process lifetime primitives to extraction and native lifecycle adapters without depending on indexing, the service registry or agent behavior. Windows jobs retain their existing bounded handle-based descendant drain; see [resource accounting](service-resources.md).

Unix extraction and short-lived native manager commands now use a private process-group owner. Its `try_wait` observes the exact child with `waitid(WNOWAIT)` and never reaps the leader. The unreaped PID reserves the group number until cleanup completes. Cleanup signals that owned group, verifies terminal members and only then reaps the leader. Repeated completion uses the saved status; attempting another kill after reaping fails. A timeout or unavailable observation retains the owner instead of releasing capacity. Auto-reaping and custom `SIGCHLD` dispositions are rejected before provider execution. The same read-only disposition check now runs before service-owned project, inference and watcher subprocess creation; it never changes the embedding process signal policy.

On Linux, group enumeration is bounded to 131,072 observed processes and the drain deadline. Each matching member is checked with a native pidfd and zero-timeout poll. A `/proc` zombie state alone is insufficient: the regression exposed a window before the native exit handle signals. Provider admission requires `pidfd_open` support (Linux 5.3 or later) and permission to use it before starting the provider. Unknown native state keeps cleanup pending; AIRK does not change host policy to obtain access. See the [Linux pidfd contract](https://man7.org/linux/man-pages/man2/pidfd_open.2.html).

On macOS, bounded `proc_listpgrppids` enumeration and `PROC_PIDTBSDINFO` inspect up to 1,024 group members per observation. The query explicitly includes unreaped zombies; permission, capacity and unknown native failures retain cleanup. Apple's [libproc implementation](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.c) returns a PID count for the group wrapper, and [process-info implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/proc_info.c) documents the zombie-query argument. The adapter has a cross-target compile/Clippy check; execution on macOS remains unqualified.

These groups manage trusted local providers that stay in their assigned group. They are not a security sandbox. Service/worker owner death, providers that escape groups, process-tree RSS aggregation and persistent recovery of outstanding descendant charges are separate requirements; this provider primitive does not close them. No process is killed by executable name or by an unowned/reused numerical group ID.

Native project, inference and watcher owners no longer treat an unknown child wait result as permission to signal its remembered numerical PID. They keep ownership and admission charged while retrying read-only exit observation. This is a fail-closed unknown outcome: health can expose aged cached observations, and management deadlines may expire; no successful drain or released capacity is inferred from an error or elapsed time. Normal live-child deadlines still terminate the exact owned child and confirm exit. No process-name kill or signal to remembered unowned identifiers is introduced.
