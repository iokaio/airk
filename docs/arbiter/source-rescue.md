# Source rescue from ignored artifacts

Status: source-capture checkpoint `c787da29` is committed; additional source
families and broad reconciliation remain in progress, 17 November 2026.
All 104 previously reported access-denied directories are readable after the user
repaired their permissions. That observation does not close deeper inspection gaps.
The scoped 10,356-candidate reconciliation has zero unresolved sources after fresh
owner/hash checks. Broad primary/additional-format scans, generated JavaScript,
embedded fields and upstream/reference proofs still require combined reconciliation.
This document does not claim that all artifact code is rescued or committed.

## What is being retained

- Maintained training, fine-tuning, MiniLM/Qwen export, ONNX storage normalization,
  acquisition, rights/provenance, numerical evaluation and process helpers.
- The C++ final-graph collector, native Rust decoder/diagnostics, authenticated
  incremental producer and static-runtime build/verification source.
- Distinct historical training/conversion, evaluation/orchestration, platform,
  packaging and native/client proposal implementations. Identical source copies
  share an owner; historical variants remain explicitly identified.
- Source inventory, reconciliation, embedded-source discovery and Git byte
  preservation tools. Generated JavaScript can be accounted for by exact
  in-memory reproduction from retained TypeScript and compiler/config pins.

Source maps retain original path/hash and maintained destination/hash. Where a
license header was absent, documented prefix-only transformations preserve the
original body exactly. Unintegrated Rust and selected historical JavaScript are
inert source templates. Original artifacts and their receipts remain unchanged.

Operational history r2 preserves 2,413 original paths through 2,047 distinct new
copies and seven aliases to existing owners. Eighteen build CMD wrappers are
explicitly retained as historical generated copies; exact producer-parameter
reconstruction remains a separate proof. Their preservation grants no execution,
installation or publication authority.

No model weights, training examples, corpus inputs, private indexed documents,
credentials, generated libraries or live state are added. Upstream/corpus
exclusions require explicit source/evidence identities; a directory name is not
enough. Synthetic regression fixtures and embedded source-transfer bundles are
identified as implementation, not training data.

## Reproduction and evidence limits

Current operational entry points and private input/output requirements are
documented in their READMEs. Historical source capture is not a portable launcher:
old paths, sibling imports, deadlines and seals require deliberate adapters and
fresh reviewed input identities before rerunning. Full historical ORT build
launching remains unimplemented; its maintained manifest command validates
inputs read-only. Source rescue does not establish repeat training quality,
identical model outputs, CUDA execution or release qualification.

The maintained native changes passed scoped all-feature Clippy and 161 focused
tests (304 skipped) using the existing static core. The new C++ collector itself
has not been compiled or exercised. Migration families have separate source,
path/refusal and preservation checks; the ledger records their actual scope.
Exact Git byte preservation is checked separately, including CRLF sources.
Staged whitespace diagnostics retain 150 pre-existing findings in 19 authenticated
historical files and patches; original bodies and required patch context are
preserved rather than silently reformatted. This is not a global whitespace pass.

The final-plan continuation will use maintained source owners. The historical
[section 7 mapping](../../scripts/arbiter/evaluation/research_history/SECTION7.md)
identifies the CAL, confirmation and composed-service adapters still needed;
it does not authorize running archived launchers unchanged.
