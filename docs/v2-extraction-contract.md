# V2 extraction contract revisions 1 and 2

Contract revision 1 represents current standalone extraction payloads; revision 2 represents mapped composite payloads. Both participate in verified path-free extraction reuse and persisted collection policy. The [execution ledger](architecture-v2-ledger.md) records completed gates and platform limits. Current extraction uses identity `native-facts/10`, native adapter versions include `/sizing-1/detail-2`, and effective profiles independently bind mapping and chunk strategies, including published chunk strategy 3.

Revision 2 supplies mapped composite profiles and the public `Mapped` location. Current validation accepts these two representations; this is not compatibility with obsolete persisted indexes. Mapped binding requires revision 2. Old derived formats require `airk index --full`, which preserves saved collection configuration and rebuilds from source under a fresh incarnation. The retrieval engine specification now binds `generation-9` and `detail-projection-2`; old indexes are rejected before retained-payload hydration. Direct payload retention, shared child budgets, child-profile invalidation, exact original-source reads and qualified limits are specified in [D11](v2-composite-profiles.md).

[Core extraction](../crates/airk-core/src/extraction.rs) exports `AdapterCapabilities`, `AdapterDescriptor`, `ExtractionProfile`, `LocalSpan`, `LocalFact`, `ExtractionPayload`, `ExtractionCache`, `extraction_key` and `EXTRACTION_CONTRACT_VERSION`. Core needs the integrator's `identity` module and `serde_json` dependency. Profiles hash canonical struct-field-order JSON with sorted `BTreeMap` options and strictly typed canonical SHA256 input hashes through `framed_digest` domain `extraction-profile-v1`; source/profile digests compose under `extraction-key-v1`. The full registry and irrelevant policy rules are excluded. Changing effective options changes identity; adding an unrelated adapter does not.

Local facts use integer record IDs/owners and validated decoded UTF-8 spans. A separate bounded table of LocalSyntaxIdentity records (at most 20,000, comprising emitted nodes and their immediate owners) carries typed LocalSyntaxId, node kind, span and region. LocalCodeEvidence syntax_id/owner_id refer to this table rather than fact records; multiple framework facts may share one node, and an error-suppressed ancestor may remain an owner without becoming an emitted fact. Identity IDs and structural tuples are unique, and referenced owner spans must enclose their child in the same region. Generic fact ownership stays separate. No legacy path-bearing `CodeEvidence` is copied into the payload. Validation rejects duplicate/missing/cyclic owners, excessive owner depth, invalid UTF-8 bounds, unsupported versions and excessive facts/text/chunks/diagnostics/metadata. ExtractionPayload preserves artifact extraction_method, exact parse_status (including legacy serialized OCR provenance) and bounded typed ExtractionProvenance records with producer/options/asset digests even when no facts are emitted. Child profiles validate their identity and RegionLocation validates against the same decoded text/immediate-host source map; nested host composition remains a binder responsibility. LocalCodeEvidence preserves every existing native code metadata field except path-bound symbol/owner IDs. LocalFact retains syntax kind, line bounds, intrinsic DocumentLocation and complete DocumentEvidence/TableEvidence. LocalChunk retains intrinsic document locations. LocalRegion binds decoded text to SourceMap/RegionLocation and a selected profile; local relationships distinguish integer local targets from unresolved written spellings. Continuity descriptors hold versioned full-span dimension digests. Imported producer records stay in their separately bound domain. Validation admits up to 256 MiB of source, 32 MiB of extracted text and 256 MiB of serialized payload. Shared region text/map/depth limits remain independent. Structured source parsing stays within 4 MiB; larger UTF-8 sources use explicitly partial text-only extraction. See [ingestion limits](ingestion-limits.md). NativeAdapter accepts a bounded AdapterInput, effective profile, optional validated region context and mutable shared HostBudget; implementations must charge failed and empty work and return validated output. No parser or filesystem type crosses this interface. A cache implementation must verify source/profile binding and payload integrity and remain collection-local. The trait does not import store or provide a cache implementation.

[Selection](../crates/airk-ingest/src/adapters/profile.rs) exports `RuleMatch`, `SelectionRule`, `ExtractionPolicy`, `Selection` and `validate_relative_path`. Policy JSON is capped before deserialization at 128 KiB and 256 rules. Exact overrides precede scoped rules; longest matching scope wins; a case-sensitive match wins over an otherwise equal case-folded match. Equal-priority matching rules fail explicitly, including duplicate rules. Unknown adapters and unsafe paths fail. An empty scope prefix selects the entire registered root; nonempty scope prefixes match directory boundaries, not arbitrary string prefixes. Suffix/basename constraints are conjunctive. Original path case is never rewritten.

[Registry](../crates/airk-ingest/src/adapters/registry.rs) exports `AdapterRegistry`. `baseline` describes the admitted native, document and project profiles. Registered basenames precede explicit case-sensitive compound suffixes, ordinary case-folded baseline suffixes, bounded literal content-prefix discriminators and UTF-8 fallback. Content discrimination inspects at most 4096 already-budgeted bytes; multiple matching prefixes fail instead of silently choosing a dialect. Compound and discriminator registrations are capped at 256. Repository/project conventions and bounded structured-schema discrimination are specified in D8/D9. `.h` defaults to C with explicit ambiguity unless an override or captured policy-v2 context selects C++; unselected SQL and ambiguous `.m`, `.pl`, `.cls`, `.v`, `.s`, `.S` retain explicit limitations. Existing Vue/Svelte, SCSS and MDX paths remain partial pending phase 8. Gradle Kotlin now has bounded structural build overlays alongside native Kotlin evidence. See [project profile revision 1](v2-project-profiles.md).

Scanner dispatch selects an effective profile before extraction-cache lookup. Selection metadata is separate from profile identity; captured effective options/configuration hashes participate in the reusable profile identity. Discriminator/override choice alone does not fabricate configuration-input provenance. Persisted policy changes apply on the next indexing publication; [policy status](extraction-policy.md) distinguishes configured and published digests. Bounded selection warnings are regenerated during scans, including cache reuse, without replacing native parse/OCR provenance.

Code/document descriptor generation uses shared per-host limits of 20,000 units and 8 MiB encoded descriptors, with bounded hash-work counters. Native syntax fingerprinting is independently capped at 64 MiB of admitted input. Missing dimensions remain explicit. Kernel assigns durable keys only after artifact reconciliation; assigned keys and generation stamps do not enter path-free payload identity. Published chunks follow maximal declaration/document hints, cover intervening bytes exactly and preserve native location boundaries, with 8 KiB/160-line caps. Internal raw-fact conversion still adapts current native producers into the neutral payload; it is not an old-index migration reader.

Tests cover malformed paths, policy conflicts/precedence, preserved partial profiles, effective identities, UTF-8 bounds and ownership, original document/table/formula metadata, OCR provenance, shared syntax identities, continuity ambiguity and exact chunk coverage. Current Windows/Linux-container receipts and remaining platform limits are recorded in the execution ledger.

The independent chunk-count ceiling is `MAX_EXTRACTION_CHUNKS = 500,000`. That ceiling and independent fact/region budgets remain in force with the text and serialized-payload bounds above. A 400,041-newline original fixture verifies raw conversion and exact rebinding of 10,002 input partitions.


Policy version 3 adds collection detail selection. Essential/Balanced effective profiles include `index_detail` in their hashed options; Detailed is the interpretation when that option is absent. All current profiles include the new adapter identity above, so that default does not preserve an obsolete index identity. The immutable inventory records its published `index_detail`. Fact, relationship, outline and durable-key responses expose the served level and deliberate omissions, independently of a pending policy change.

Qualified common grammars select detail during their syntax walk. Essential avoids rich evidence/fingerprint construction while retaining independent written definition/signature spans; Agent Lean and Balanced retain generic calls and construct their selected framework cues exactly as the full-analysis reference does. Selected Markdown/plain/native-prose paths similarly avoid unused factual classification. Other adapters explicitly retain full-analysis fallback followed by filtering; [the qualification scope](extraction-policy.md#detail-aware-extraction) lists those boundaries. Parsing status, visited-node ceilings and shared host admission remain in force, including hidden seed metadata. Detailed document continuity uses a unit-only collector rather than rebuilding discarded facts.

Ingest-only `SemanticSeeds` holds at most 100,000 definition or heading hints with region-local UTF-8 spans. `Some(empty)` explicitly means a qualified producer found no hints; `None` requests derivation from full raw facts before filtering. Composite producers rebase child seeds to their mapped regions. Seeds are transient, contain no parser nodes and are not serialized. The required persisted `SemanticProjection` remains version 1: it partitions body text completely, keeps native slabs and mapped regions separate, and records written context independently of optional detail. Invalid coordinates fail; ambiguous overlapping hints may coarsen while preserving full body coverage. Retrieval uses this projection instead of reconstructing semantic boundaries from selected facts or display chunks.

Before continuity generation, selected fact IDs/owners and relationship references are renumbered together. Syntax identities are retained for selected evidence and its owners, sorted by region/span/kind and assigned dense `LocalSyntaxId` values; code syntax/owner references are updated separately. This preserves meaning when optimized extraction omitted intermediate nodes, including owners with no emitted fact. Essential has no structured continuity; Balanced retains declaration continuity and marks document-unit continuity unsupported. Complete-payload comparisons against full-analysis references qualify facts, references, continuity, chunks, projection and original locations.

The scanner can dispatch bounded pure extraction jobs using captured source bytes, hash and effective profile. Workers return validated neutral payloads; coordinator binding and storage callbacks retain discovery order. Execution settings never enter reusable extraction identity. Native document expansion and sources above 4 MiB stay serial, and shutdown waits for in-progress work. [Worker admission](ingestion-limits.md#bounded-extraction-workers) describes count/source/result bounds and their memory limitations.
