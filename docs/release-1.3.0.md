# AIRK 1.3.0

Native, extension and lockfile versions are synchronized at 1.3.0. The previous published helper is 1.2.4; the 1.2.5 candidate was built for local review but was not released. GitHub downloads and Marketplace packages are promoted separately from successful CI on the exact main commit; their workflow records establish publication status.

## Release summary

Version 1.3.0 combines an incompatible lexical index format, removal of an unsupported MCP endpoint, and call occurrence evidence at both structured default detail levels. Existing 1.2 indexes require a full rebuild before this version can use them.

## Why a minor version

This version changes the index format and the evidence contract together. SQLite FTS5 replaces Tantivy lexical storage in database format 126, so an older 1.2 collection cannot be read in place. The extension starts a full rebuild from saved source files when indexing a recognized older format; CLI users run `airk index --full`. The rebuild preserves original source files, collection ID and saved settings, but replaces derived index state. The source also retires the former `airk_history` MCP endpoint, leaving fifteen read-only tools. It could only return an unsupported error after AIRK 1.2 moved to one current index.

Agent Lean and Rich Structure now retain supported call occurrences and their syntax candidate relationships. Search Only continues to retain text and citations without structured facts; Detailed continues to include call occurrences and document-unit continuity. The extraction identity advances to `native-facts/10`, so existing evidence must be re-extracted before call candidates appear. Written call targets are unresolved; an empty or truncated relationship response is not proof that no caller exists. The extra indexing time and retained-state cost have not yet been isolated in a representative benchmark.

Together these are substantial storage and MCP/evidence changes relative to published 1.2.4, so the intended release is 1.3.0 rather than a 1.2.x patch. There is no historical search, checkpoint support or old-format reader in 1.3.0.

## Other changes

The editor's Collections row and status bar now show committed source-file counts during a source scan and published semantic progress during enrichment. Successful source-index completion retires the prior coverage percentage until the next measured inventory.

Collections without saved policies now admit up to 4 GiB of eligible source on machines with at least 32 GiB of detected memory, with 8 GiB of extracted text and 16 GiB of pass reads. The default logical disk quota is 256 GiB per collection within the existing 500 GiB data-root quota. Existing saved source-limit and quota policies keep their values. These ceilings do not qualify a 4 GiB source workload or reserve 256 GiB of disk space.

Committed lexical passages and facts become searchable while source discovery continues. Known saved paths can use scoped indexing; periodic complete inventories reconcile coverage. Semantic inference runs in bounded background batches after source discovery. Rebuild intents, revision-bound completion reports, pending-rescan coverage, diagnostics and guarded lexical snapshot reuse are described in the [dated indexing follow-up](indexing-follow-up-2026-10-21.md). Search returns focused snippets by default and can request full chunks; optional terse MCP replies retain evidence identity. Model setup uses the native CPU capability and qualified model catalog while automatic selection remains FP32 MiniLM.

The [earlier 1.2.5 candidate record](release-1.2.5.md) contains its dated Windows validation and local packaging results. Those results do not qualify this 1.3.0 source after the call-profile and version changes. Current operation and upgrade steps are in [the runtime guide](current-index-runtime.md), and the [MCP retirement record](unreleased-mcp-tool-retirement.md) explains the former endpoint. Installed-editor acceptance, other-platform qualification and a call-cost benchmark remain to be recorded for 1.3.0.

## Qualification status

Release preparation on 2026-10-22 rechecked all fifteen MCP tools with 33 calls, covering lexical/hybrid/vector search, exact symbols, compact/rich facts, cursor continuation, conditional reads, hash mismatch rejection, remembered-citation validation and expired-revision rejection. The sampled source hash and seven textual identifier occurrences matched live source. This is a functional smoke survey, not comprehensive retrieval-quality or corpus-capacity qualification. The container smoke now checks the exact fifteen-tool catalog and rejects missing, duplicate or retired tools. Historical change tracking is unsupported; `airk_changes` validates remembered evidence against the current publication.

The release-preparation pass also passed Rust formatting and workspace/all-target Clippy, 128 Python contracts with two explicit fixture-dependent skips, and the native-backed extension suite with 147 passed and two skipped. The writer-lock regression now uses the current `collections-1.2` namespace. Repository/link checks, byte-identical contributor guidance, lock/version agreement, dependency-notice generation and whitespace checks were reviewed. The notice bundle retains three documented upstream license-declaration gaps; no completed legal audit is claimed. Required exact-commit CI records native-platform and container qualification; release promotion requires a successful main candidate and separately verifies signing, notarization and package provenance. Installed-editor acceptance and the representative call-cost benchmark remain separate.
