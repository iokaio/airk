# AIRK 1.1.1 release preparation

Native packages and the extension target **1.1.1 on the stable channel**. Publication is tracked by the Marketplace listing and the [GitHub release](https://github.com/iokaio/airk/releases/tag/v1.1.1); this checklist records qualification, not proof of publication.

- The Activity Bar opens a dashboard with collection cards, measured coverage, direct indexing controls, indexing mode, pause/resume, storage selection and grouped setup and maintenance controls. Cards distinguish stale coverage and pending detail changes from a current index.
- Collection cards show MCP helper verification, tool counts, timestamps and errors. A machine-scoped VS Code registration switch controls automatic definitions; Manage agent connections opens the editor’s server controls. External agents retain their own settings.
- Choosing index storage holds new jobs and waits for the current indexing pass to finish safely. Cancelling preserves the existing location and pause preference.
- Essential, Balanced and Detailed evidence levels trade optional structured evidence for storage. New collections default to Balanced; existing indexes preserve Detailed behavior. Failed rebuilds retain the previous published revision and its reported detail level.
- Storage defaults are 100 GiB per collection and 500 GiB per storage root. Users can change quotas and retain zero through eight predecessors. New collections target the active generation only; existing saved policies remain authoritative. Readers and protected history may retain additional generations.
- Automatic retention uses bounded cleanup before or after publication and can continue during quiet editor intervals. Changing the retention target makes cleanup due without requiring another publication. Storage failures stop automatic indexing retry loops.
- Qualification corrected two concurrent-window paths: live writer contention leaves indexing queued rather than blocked, and quota enumeration tolerates disappearing temporary entries while preserving reservation accounting. Deferred lock retries do not count as failed indexing observations.
- Large-collection cleanup has a separate 8 GiB verification allowance and avoids loading a complete catalog for disabled history with no recovery work. Surviving roots are still authenticated before object deletion; a generation count alone is not proof that cleanup completed.
- New immutable catalogs share file and producer values, store source hashes as binary values and reconstruct complete MCP evidence. Publication can reuse unchanged native fact rows. A bounded verification cache avoids repeated semantic validation while still hashing current component bytes; it does not trust timestamps or keep obsolete generations pinned.
- New GitHub release tags use the package version, such as `v1.1.1`. Duplicate checks prevent republishing; a completed Marketplace and GitHub release can produce a draft patch-version PR for review. Tested binaries must still match the version committed on protected main.
- Agent summaries include Gemini CLI/Antigravity. Client-specific setup instructions remain separate.

Current local Windows checks include the workspace build, all-target clippy with warnings denied, formatting, extension tests with the native helper, Python release/packaging contracts, workflow syntax, repository and whitespace checks. The final complete native run passed all 677 tests with 4 ignored. Doctests passed. Extension tests passed 55 with the separately provisioned older-helper upgrade fixture skipped; Python tests passed 84 with the Linux-only RSS accounting test skipped. License notices were generated for 466 dependencies; four existing declarations still require release review for missing separate license text. This release changes no third-party dependency versions.

The [final scale comparison](scale-qualification.md#final-windows-enhancement-comparison-2026-10-17) is complete for all three detail levels on frozen AIRK and application workspaces. Balanced storage fell 12.2%/23.3% and Detailed 28.3%/24.9%; repeated exact-symbol requests were 4.3–6.3 times faster. All six controlled updates reused every unchanged file, completed cleanup with one generation, and passed MCP isolation and citation checks before and after cleanup. Peak memory was approximately unchanged. Catalog and lexical generation construction still perform generation-wide work; the report records timings, omissions and qualification limits.

The final Windows VSIX passed [installed-editor qualification](windows-local-build.md#installed-extension-and-two-window-qualification) in VS Code 1.142.0: trusted/untrusted, multi-root, two windows sharing one collection and two windows using independent collections in shared storage. Real panel controls, native MCP calls and citation hashes were checked. This does not qualify Marketplace installation, shared-profile settings synchronization, upgrades, remote hosts or macOS/Linux.

The packaged Windows 1.1.0 → 1.1.1 helper upgrade passed: the new helper read the previous index, completed a full rebuild and exposed all 16 MCP tools, while preserving the old cached helper and source bytes. This is a native adapter upgrade check, not an installed-editor rollback qualification.

See the [release workflow](release-workflow.md) and [1.1.0 ingestion-sizing notes](release-1.1.0.md). Installed-editor qualification remains Windows-only; shared-profile synchronization, remote hosts and editor upgrade/rollback remain unqualified.

The organization currently blocks Actions from creating or approving PRs (verified October 17, 2026). The automatic next-patch PR fallback therefore requires an organization administrator to allow it before the repository setting can be enabled. Manual version PRs and publishing an unused version remain available.

The first PR CI run exposed two additional qualification issues: the code benchmark needed to explicitly select Detailed to test optional call candidates, and private catalog admission needed space for filesystem activity between capacity probes. Catalog admission now leaves 10% of observed growth available in addition to the existing safety headroom; physical free space remains a point-in-time observation, and write failures preserve the previous publication.
