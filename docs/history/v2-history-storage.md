# Historical storage revision 1

> Historical 1.1 implementation record. AIRK 1.2 production uses the [single-current-index contract](current-index-runtime.md). Retained historical reads, checkpoint/retention administration and receipt-backed generations below are not current capabilities. Old primitive storage tests remain separate from production routing.


D10 adds authenticated lightweight representations of exact committed revisions. History descriptor, binding, conversion intent and removal intent versions are 1. Root pointer/schema version 4 adds history bindings; readers explicitly accept versions 3 and 4. Reading version 3 does not migrate it. The first writer requiring the new table installs it atomically. Original publication receipts, revision tokens, inventory, lineage and manifest bytes are preserved.

History packages retain original metadata and the explicit union of source/payload dependencies. They do not retain full-text/vector indexes or models. Exact `history_at` access pins the canonical generation lease before selection and verifies metadata and object binding. A missing full representation is treated as history only when a valid committed binding and package prove it; missing or corrupt dependencies fail closed.

Conversion uses durable stages for intent, verified package, published package, committed binding, detached full representation, physical removal and completion. Retirement has a separate intent and retains the receipt until historical bytes are removed. Recovery authenticates the original descriptor witness and obeys the same lease/quota boundaries. Active revision, committed predecessor and readers are protected. GC marks history dependencies, and collection relocation/removal respects historical leases. Checkpoint directories currently prevent conversion/removal until H2 adds their policy contract.

Descriptors are capped at 16 MiB and 65,536 dependencies; intents at 256 entries of at most 16 KiB each. Conversion and reads are bounded. The current metadata-work allowance conservatively charges every verified byte, including source/payload/full component hashes. Larger candidates fail explicitly; H2 can introduce a distinct bounded verification-I/O allowance. No automatic history policy or public history API is enabled by this storage package.

Windows qualification passed 12 storage tests, followed by the added historical relocation/removal fixture, plus existing lineage (2), maintenance (8 plus one intentionally ignored child entry) and publication (9) regressions. The maintenance suite executed its process-boundary children. Warnings-denied all-target store clippy passed. Linux-container qualification passed all 13 historical-storage tests. Fixtures cover every seven-stage conversion and five-stage retirement failure boundary, partial physical removal, quota/work rejection, imported evidence and exact original bytes/receipts, reader protection, GC corruption rejection, v3 read/atomic migration, relocation and collection removal.

Native macOS, physical full-disk/power-loss campaigns and final installed compatibility remain unqualified. H2 still owns bounded public reads, thinning, checkpoints and purge controls. See the [execution ledger](architecture-v2-ledger.md).
