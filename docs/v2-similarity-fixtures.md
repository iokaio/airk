# Bounded similarity fixture calibration

The suggestion implementation uses version 1 whitespace-token
five-token shingles, hashed with SHA-256 over framed token bytes. It compares
the shingle sets, never the similarity of source SHA digests. Case, punctuation,
and literals remain in the tokens. Whitespace normalization is a heuristic;
these scores do not establish semantic equivalence or artifact identity.

The proposed threshold is 8,000 basis points of exact shingle-set Jaccard
overlap, with at least eight distinct shingles in each endpoint. The following
original fixtures are generated by `suggestions.rs` private tests. The base is
40 lines of `billingN records original invoice entry N.` with N from 0 to 39.
An edited line replaces its final `N.` token with `revised-N.`.

| Original fixture comparison | Shared / union shingles | Score (basis points) | Expected suggestion |
| --- | --- | --- | --- |
| One edited line | 231 / 241 | 9,585 | Yes |
| Five edited lines | 211 / 261 | 8,084 | Yes |
| Six edited lines | 206 / 266 | 7,744 | No |
| Repeated four-token boilerplate, one added token | Below eight distinct shingles | Not scored | No |
| Two equal-scoring edited copies | Separate candidates | 8,084 each | Both; no selected identity |
| Same text, different registered root or extraction profile | Not compared | Not scored | No |

Scores were independently computed from token tuples using Python; Rust tests
assert the threshold-adjacent scores. The five matcher tests passed in the Linux container.
These small synthetic fixtures calibrate a
conservative cutoff, not real-world precision or recall.

The implementation considers at most 256 endpoints per side, 64 KiB per text,
8 MiB aggregate text, 2,048 distinct shingles per endpoint, 4,096 eligible
pairs and 64 returned file candidates. Exhausted bounds and invalid or duplicate
input endpoints set `partial`. Short low-information text is intentionally
ineligible rather than an exhaustion. Ordering is deterministic by score and
path. Input source/extracted-text domains must be consistent and authenticated
by the caller. Exact matches remain the existing exact matcher's responsibility.

Directory hints require at least three unique one-to-one child suggestions
with unchanged basenames and one consistent parent-directory mapping. Every
target is an actual indexed endpoint supplied to the matcher. Incomplete
searches, competing destination directories, or too few unambiguous children
produce no directory hint. Hints neither create paths nor redirect reads and
must never override an exact current path or promote a durable identity.

`changes` enables this work only with `include_suggestions: true`. The kernel
requires a verified `since` ancestor and pins that exact full generation or
historical representation. It reads only bounded retained UTF-8 source bytes.
Unmatched removed/added endpoints are compared; same paths, preserved identities
and exact source matches remain governed by the existing matcher. Missing
baseline retention reports unavailable coverage rather than consulting sources.
Omitted bytes or exhausted comparison bounds report partial coverage.

File and directory records share the existing `limit` and `max_bytes` budgets
with ordinary changes and validations. Coverage reports examined bytes/files and
compared pairs. Pagination binds the opt-in flag, exact suggestion records and
baseline representation; retention changes expire the cursor. Suggestions are
never added to read forwarding or durable continuity resolvers.


Focused qualification: four kernel integration cases passed for opt-in suggestions,
shared pagination budgets, retained-history baselines and cursor expiry. The CLI
opt-in contract passed; existing changes (eight kernel and three CLI cases) and
five MCP cases passed. Integrated Windows all-target clippy passed with warnings
denied. These synthetic tests establish bounded behavior, not real-world recall;
whole-workspace and native-platform qualification remain at P12.
