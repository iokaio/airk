# MCP response modes

The 1.4.0 development implementation defaults to **Terse response mode**. Choose **Full response mode** in the trusted extension panel's Agent connections section; `airk.mcp.responseMode` persists the machine setting and refreshes the MCP launch definition. Reconnect the agent after changing its launch configuration. Native clients can set `AIRK_MCP_RESPONSE_MODE=full`. An individual tool request can override either default with `response_mode: "full"` or `"terse"`.

Use terse for routine navigation. Use Full for provenance audits, parser/coverage limitations, readiness diagnosis and missing or surprising results. Every tool schema and description supplies this guidance, and initialize instructions retain the existing 512-byte ceiling. Full adds detail; written targets remain candidates, imported assertions depend on their producer and indexed evidence does not verify live files.

Terse keeps the exact current token under `publication.token`. Repeated conditional-read/change endpoints use `{"ref":"publication"}` to refer to that token. Different baseline/requested tokens retain their own identity. Source citations, hashes, read validators, evidence bytes, candidate/imported basis, truncation and work/response budgets remain independent of display mode.

Repeated per-record producer, producer-version and coverage strings move into a response-local `provenance` array. A record's numeric `provenance` selects that descriptor; its syntax/imported basis and candidate target remain on the record. The table has at most 64 descriptors; heterogeneous overflow retains original provenance instead of discarding it. Full preserves detailed envelopes and per-record provenance. Explicit compact/rich evidence options and cursor bindings remain separate; Terse/Full never changes compact selection or conditional validators; use `compact: false` for rich records and symbol IDs.

Readiness/freshness is included on first observation, when substantive state changes, or with `include_status: true`. Explicit status/capability/change tools retain their diagnostic information. Observation timestamps alone do not trigger repetition; failure text, completion watermarks, counts, indexing level and pipeline identity do. Unknown observations stay explicit. Availability of source files and independent source freshness are not inferred from index readiness. Service-mode reads now use a [fenced registry observation cache](service-freshness.md); missing or expired samples stay unavailable and never substitute the legacy per-root scheduler.

Status memory belongs to a client, with collection/incarnation-bound digests. The direct native adapter carries a fixed content-free receipt across renewed connections; only a completely received result advances the client's receipt. Independent clients, rebuilt incarnations, changed failures and canceled exchanges cannot inherit an unacknowledged observation. Workers retain shared admission limits across their separate client sessions. The bridge does not reformat evidence after native usage accounting.

Development tests cover schema/help guidance, default/override behavior, timestamp-only changes, new failures, client isolation, closing one client without closing another's admission, exact read validators, native receipt bounds, reconnection and rebuild reset, shared provenance and original source bytes. A repeated-provenance fixture checks a byte reduction without claiming a universal token-saving percentage. Minimal outline/symbol/import projection and the common fact result key are implemented as described below. Retained change baselines remain Phase 7 work in the [completion checklist](service-implementation-checklist.md).

## Minimal navigation and fact results

The development MCP `airk_outline`, `airk_symbols` and `airk_imports` tools default to minimal records: `name`, `kind`, `lines`, `signature`. Ordinary definitions omit duplicate qualified names, IDs, scopes and repeated citations. A response-local `files` table preserves the original path, exact source hash, language, parse status, line basis and default provenance. Multi-file rows select `file`; an exact-file outline implicitly selects file zero. Rows inherit the file’s `provenance` unless they carry an explicit override into the response-local table. Non-source locations, table/formula interpretation, truncation warnings and native call candidate labels survive projection. Full mode retains these bindings; `compact: false` explicitly requests rich evidence, independent of response mode.

`airk_code_facts`, `airk_document_facts`, `airk_symbols`, `airk_imports`, `airk_outline` and `airk_relationships` consistently return `items`, including empty and not-modified results. Native CLI compatibility commands retain their existing record envelopes until service cutover; `outline --compact` uses the same minimal selection and cursor binding under its `minimal` envelope. MCP usage accounting measures the serialized result and authenticates shared source bindings against the exact indexed revision.

Minimal discovery charges every admitted record and each new file/provenance descriptor before admission. Array/envelope framing is additional. An insufficient first-record budget returns `required_record_bytes` without dangling bindings; continuation cursors bind exact publication, filters and representation. Long signatures remain complete or require a larger budget. A small ordinary-definition fixture fits within 100 bytes per row; this is not a guarantee for arbitrary signatures or document tables.
