# Retained indexed changes

The 1.4.0 development implementation retains authenticated change metadata across up to **64 publications or 24 hours**, bounded independently by **10,000 records and 16 MiB**. These are ceilings: record/byte pressure and omitted observations can advance explicit coverage floors earlier. The default service cutover and final qualification remain open in the [completion checklist](service-implementation-checklist.md).

`airk_changes` accepts an exact saved token and returns observed file changes, plus selected symbol/document changes when requested. Delayed edits coalesce by durable subject, preserving the first before-state, latest after-state, observation count, changed dimensions and causes. A file edited and then restored still reports its intervening observations. Current remembered evidence uses the explicit **`index-current`** outcome; `unchanged` citation content and index readiness never establish live-source freshness.

The index stores parent tokens and bounded event chunks inside its authenticated current map. They enter the same quota-admitted journal and atomic SQL publication as the source/index head. Only older exact tokens are embedded, avoiding a current-token/root cycle. New chunks have independent digests and finite sizes; generation, record, byte and age eviction removes whole publication groups. Process restart preserves the window. A forged digest, another incarnation or a rebuild cannot revive a baseline.

Coverage for files, code, documents, ancestry and resolution remains independent. Missing/partial metadata, unsupported continuity and overflow are explicit. Unit observations carry fingerprints and original locations, rather than source excerpts or inferred reference resolution. Imported producer domains and unsupported families cannot become complete native coverage. Similarity suggestions remain unavailable. Metadata corruption is rejected; recognized retained-history corruption can disclose unavailable coverage while independently verifiable current selectors remain useful.

Changes are paginated before remembered validations. Complete serialized records count against `max_bytes`; envelope/array framing is additional. Cursors bind the exact current publication, selectors, prefix, code/document flags and the logical retention view. Changed publication/options or age expiry returns `cursor_expired`; restart from the saved baseline. Finish all needed pages before advancing that baseline. An insufficient first-record budget fails explicitly.

A physical-only compression repack advances the exact publication without inventing source changes. Retained metadata does not pin old source bodies, enable historical file/outline/context reads, retain checkpoints or provide rollback. Superseded exact source reads still expire. Original files remain read-only.

The earlier [1.2/1.3 current-index behavior](changes.md) and dated release records remain historical guidance for those versions.
