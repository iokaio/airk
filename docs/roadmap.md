# Implementation roadmap

The scaffold and optional native extension preview are runnable. The final DiskANN tier and full release qualification remain future increments.

| Stage | Scope | Acceptance |
|---|---|---|
| Foundation — implemented | Seven crate boundaries; original source, community files, CLI, setup renderers, collection-scoped disk snapshots and memory adapter; lexical retrieval | Windows and Linux tests passed; macOS/hosted CI configured but not observed |
| Native facts — initial slice implemented | Grammar profiles for common languages; fourteen MCP tools; Markdown/config/XML/SVG/delimited facts; text-layer PDF, DOCX/PPTX extraction | Original format fixtures, original locations, partial-syntax labeling, no fake semantic refs; expand language edge cases |
| Document cues — initial slice implemented | Heading context/styles/title placeholders, dates, numeric/qualitative requirements, architecture/design/features/decisions/acceptance; category-filtered CLI/MCP facts | [Parser contract](document-indexing.md); ambiguity/provenance/budget/re-extraction fixtures; English heuristics are evidence candidates, not inferred compliance |
| Rich code facts and optional semantics — initial slice implemented | Tree-sitter scopes/signatures/written types and selected framework cues; typed relationships; SQLite catalog/exact facts/edges; manifest-bound SCIP format adapter; optional LSP/Ctags later | [Recommendation review](code-indexing-options.md); qualify providers, coordinates, build/dependency invalidation and bounds before resolved-reference/caller/implementation claims; preserve DiskANN selection and simple default install |
| Collections — initial slice implemented | Stable configured ID/root, isolated storage/retrieval, one-container host recipe, disk-usage listing and managed collection removal | Isolation/removal tests and one-container persistence/MCP smoke passed; scale/crash qualification remains |
| Durable scalable indexes | Content-addressed sources, manifests, persistent Tantivy lexical/exact facts, local embeddings and real disk-backed DiskANN provider | Coherent publication; graph/vector reopen; bounded RSS/cache and disk I/O; crash/corruption/deletion/rename tests; recall against exact oracle |
| Scheduler and retention — extension batching implemented | Debounced/idle/on-save/manual per-host queues, pause/resume, pending revisions, soft collection-byte budget and explicit native removal | Rapid-edit/coalescing and native adapter fixtures; durable machine-wide scheduler, event watermarks, hard limits and generation/cache pruning remain planned |
| Optional native extension — preview implemented | Bundled platform helper, stable version/digest cache, storage picker, collection inspection/removal, VS Code MCP provider and guided client-config previews | Local Windows package/editor smoke; hosted platform builds configured. Clean-machine/remote/upgrade coverage and direct Cursor registration remain open |
| Release qualification | Native archives, one image, notices/SBOM and installation/upgrade/benchmark evidence | OS/architecture matrix, offline runtime, held-out retrieval quality, corpus-scale cold/warm latency/RSS/disk and actual token/context measurements |
| Local usage and savings — contracts/helpers implemented | Aggregate counters by default; performance/activity/index reuse; signed context-reduction estimates; future recording, reports, feedback and price scenarios | [Delivery plan](usage-reporting.md); calculation/isolation tests, then bounded multi-worker recording/retention, live hooks and CLI/extension views; no billing claim from byte heuristics |
| Workspace coverage — planned | Authoritative native eligibility/freshness inventory, current/eligible percentage, stale/pending/blocked counts and clickable extension footer | [Coverage plan](index-coverage.md); no false 100% from incomplete scans, capacity exclusions, stale files or rounding; bounded background work and scheduler click coalescing |

Semantic indexing stays local; missing models are explicitly not-ready, never a remote fallback. Provision assets deliberately with license/digest/specification. DiskANN's exact version/provider must be selected by cross-platform qualification, rather than assuming the inspected in-memory provider is a disk-based solution.

The large-repository target requires removing bootstrap corpus caps through bounded streaming and qualified storage, not raising limits on whole-snapshot loads. Multi-root collection inventory and source aliases are planned; one canonical root per collection is the current supported contract.
