# Implementation roadmap

The native beta and extension implement persistent lexical/vector components, real local transformer inference, local usage, workspace coverage, live provider/OCR adapters and durable scheduling with native events and optional per-user services. The remaining release-qualification work below is explicit; passing original fixtures does not establish production semantic quality or completion of the large-repository target.

Optional vectors stay local; missing models are explicitly not-ready, never a remote fallback. [Model assets](local-models.md) are deliberately provisioned with license/digest/specification. DiskANN 0.59.0 uses an independently implemented file provider. [The ONNX adapter](onnx-models.md) performs real CPU transformer inference alongside the compatible static word-vector adapter. Synthetic ANN recall and fixed MiniLM fixtures do not qualify semantic relevance for a production model or corpus.

## Remaining qualification

- **Large repositories:** content-addressed storage, compact inventories and streaming ingestion/file services are implemented. Configurable limits retain conservative defaults of 16 MiB per file, 64 MiB eligible sources, 128 MiB extracted text, 10,000 files, 100,000 discovered entries and 256 MiB pass reads. Larger selected profiles require measured cold/warm latency, RSS, physical disk I/O and real-corpus recall; the maximum accepted configuration is not a capacity claim. Compact inventories and bounded model/ANN structures still consume memory; native extraction and inference have no hard wall-clock preemption.
- **Storage and hosting:** application logical-byte reservations, OS free-space/headroom checks, hash-verified relocation and revision-bound source aliases are implemented. Native events and periodic reconciliation feed the same durable queue; explicit per-user service commands install/start/stop/uninstall real platform registrations. Qualify full-disk/power-loss behavior, actual login-session lifecycle and native platform locking before stronger claims. Physical blocks are not reserved against concurrent external writers. Storage selection alone retains old state; stop/uninstall the old service and use [relocation](storage-relocation.md) before reinstalling against a new root.
- **Provider and model quality:** CPU ONNX inference, live LSP/Ctags and explicit local OCR are implemented with bounded local assets/processes and source provenance. Broader language/framework/build environments, long text, document accuracy, unseen repositories and model upgrades require their own evidence. Provider-asserted graphs do not imply universal resolution; Ctags remains syntax-only, and OCR does not reconstruct tables or unselected pages.
- **Optional evidence and estimates:** usage supports local byte-BPE and Hugging Face BPE/WordPiece/Unigram/WordLevel tokenizers, explicit alternative-client/session/paired-task imports, dated prices, stage/disk metrics and OS process resource probes. Overlapping process measurements are not attributed, unavailable counters stay unknown, and transfer counters are not physical I/O. Representative held-out samples, provider-compatible chat framing and independent client/task evidence are needed before accuracy or causal savings claims; AIRK does not infer actual bills.
- **Release evidence:** complete the native/installed-extension matrix, remote and installed upgrade/rollback paths, physical full-disk/power-loss fault campaigns, held-out retrieval evaluation and provider/task comparisons. Real Mac testing and signing/notarization are deferred to the maintainer's original Mac, not treated as passed. Existing helper replacement and Windows service evidence covers only those exercised paths. Four upstream standalone legal-text gaps (PDF-Extract, Adobe-CMap-Parser, Type1-Encoding-Parser and htmlescape) remain legal-review items. [Validation](validation.md) distinguishes current tests from historical receipts; [the release checklist](release-checklist-0.1.0.md) is the review gate.
