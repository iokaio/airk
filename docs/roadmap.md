# Implementation roadmap

The native beta and extension implement persistent lexical/vector components, local usage, workspace coverage and durable scheduling. The remaining expansion and release-qualification work below is explicit; passing original fixtures does not establish production semantic quality or completion of the large-repository target.

Optional vectors stay local; missing models are explicitly not-ready, never a remote fallback. [Model assets](local-models.md) are deliberately provisioned with license/digest/specification. DiskANN 0.59.0 uses an independently implemented file provider. The initial mean-word-vector adapter is not transformer inference, and synthetic recall does not qualify semantic relevance for a production model or corpus.

## Remaining expansion and qualification

- **Large repositories:** content-addressed source/extraction storage, compact inventories and streaming ingestion/file services are implemented. Retain the 64 MiB eligible-source, 128 MiB extracted and 10,000-file bounds and independent 100,000-entry/256 MiB raw-read pass budgets until cold/warm latency, full-process RSS, physical disk I/O and real-corpus recall are qualified. Compact inventories and bounded model/ANN build structures still consume memory; native extraction has no hard wall-clock preemption.
- **Storage and hosting:** application logical-byte reservations, explicit hash-verified relocation and revision-bound source aliases are implemented. Qualify full-disk/power-loss behavior and native platform locking before stronger durability claims. Physical filesystem allocation and independent external writers are outside the quota protocol. An explicit watch worker reconciles registered roots; optional installed-service lifecycle remains open. Storage selection alone retains old state; use [relocation](storage-relocation.md) to migrate it.
- **Optional evidence and estimates:** transformer/ONNX adapters, qualified production model assets, live LSP/Ctags, OCR and deeper language/framework resolution remain separate implementations. Usage provides exact counts for explicitly supplied byte-BPE definitions, bounded alternative-client/session/paired-task imports, dated input-price scenarios and observed index stage/disk metrics. Other tokenizer algorithms and portable CPU/physical I/O counters require implementation. Representative held-out samples, provider-compatible framing and independently supplied client/task evidence are needed before stronger accuracy or savings claims; AIRK does not infer actual bills from these features.
- **Release evidence:** execute the full Windows/Linux/macOS native/installed-extension matrix, remote and upgrade/rollback paths, process-kill/full-disk/power-loss fault campaigns, held-out retrieval evaluation and provider/task comparisons. [Validation](validation.md) distinguishes current tests from historical receipts; [the release checklist](release-checklist-0.1.0.md) is the review gate.
