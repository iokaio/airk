# Indexed call candidates and temporary read retries

These are 1.4.0 development contracts for the default native clients. Final installed-platform qualification remains open in the [completion checklist](service-implementation-checklist.md).

## Terminal method-name discovery

`airk_code_facts` accepts a case-sensitive terminal native call method name. For example, `name: "reclaim_objects", kind: "call"` finds the retained written targets `x.reclaim_objects` and `x.next().reclaim_objects`. Results keep the complete written name, source hash and original citation. Native calls carry `candidate: true` in rich, compact and minimal evidence; imported assertions keep their own producer basis. This is syntax matching, with no receiver/type/runtime resolution. Dynamic subscripts and unsupported generic target expressions do not acquire invented terminal names.

New captured inputs carry posting format one, and terminal-name memberships participate in the same authenticated map, journal, budgets and publication as artifact updates. Replacements and deletions retire memberships using the prior capture's format. An authenticated per-incarnation marker permits selective exact-name discovery when the complete incarnation uses the new postings. Older incarnations use bounded authenticated file/kind candidates until a fresh rebuild; missing terminal postings never establish absence in that fallback. The legacy capture encoding remains canonical and readable. Imported producer identifiers do not acquire native method aliases.

## Temporary publication rejection

Ordinary format-150 publication continues serving the coherent committed generation. If read admission is temporarily unavailable, MCP returns an error whose JSON body contains `status: "retry"`, `retryable: true`, a bounded `retry_after_ms` (currently 25), and `action: "repeat_same_request"`. The code is `selection_busy` or `publication_busy`. Retain the same explicit revision and other arguments when retrying; a superseded exact revision still expires normally. AIRK does not automatically replay an ambiguous exchange.

Only confirmed selection-lock contention and typed temporary current-store opening rejection receive hints. Healthy Prepared/Applying phases continue serving the prior committed snapshot. Permissions, corruption, I/O failures, unsupported state and expired revisions remain distinct errors. Text resembling a busy error does not make an error retryable. A retry result contains no invented publication, `items`, source freshness or empty-success claim. Usage records the actual error result; failed reads do not advance status receipts.

Native regressions exercise typed read contention and exact-request retry, and reject false retry hints for permissions, corruption and expired revisions. Redb publication and retained-reader regressions establish committed-snapshot behavior separately. Current evidence and platform limitations are in [the 1.4.5 release record](release-1.4.5.md).
