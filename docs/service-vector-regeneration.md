# Service vector regeneration

The [service plan's vector repair action](airkservice-architecture.md#121-separate-diagnosis-from-mutation) regenerates vectors for all eligible committed artifacts. Ordinary `vectors` jobs continue the durable pending set; approving a `vectors` repair plan first queues a new regeneration set and then executes one bounded turn. A successful initial repair receipt and complete semantic coverage remain separate observations. Further service-owned turns drain the set; failure requires explicit retry.

The worker checks the approved plan's engine, incarnation, publication and settings guard before queuing. It clears an older semantic-continuation flag before effects, so an interrupted/failed approved regeneration cannot silently resume that superseded chain. It enumerates authenticated retained artifact metadata in 256-path pages, bounded to 100,000 selected artifacts and 64 MiB of serialized pending entries. It never scans or substitutes live source files. Model availability and enabled vectors remain required; retained source/extraction bytes are verified when their batch executes. Unavailable source roots do not by themselves prevent regeneration.

One authenticated semantic-work resource records the selected source/extraction identities and the initiating job. Repeating that job preserves completed work instead of resetting the set. The additive optional job field is omitted from older canonical resources, which remain readable. Compatible source updates preserve forced recomputation while selected work remains pending. A changed pipeline/selection follows the ordinary source-publication rules.

Each turn handles at most 32 artifacts with the existing thirty-second soft budget between publications. It bypasses embedding-cache reuse and computes each distinct selected input for that turn. Repeated inputs within a turn still deduplicate. The private DiskANN candidate appends a replacement node and tombstones its former node; physical IDs are never reused. Retained citations from other paths continue to refer to the same logical embedding key and are carried to the replacement binding. Disk and graph-ID admission remain in force, including the temporary replacement bytes and old tombstones.

The journal first authenticates unchanged vector-only inputs against committed artifact bytes. It retires their old occurrence memberships, then reattaches verified citations in the same captured transaction as the graph and reduced pending set. A binding may move to a newly allocated node only when the sealed delta proves the former node is tombstoned, or the authenticated base already proves an empty tombstoned binding. Both nodes must have the exact same embedding key. This also permits a deleted source to be re-added and regenerated. A missing proof, live former node, changed source/extraction binding or invalid occurrence still fails before publication. Lexical/fact/source rows remain unchanged by vector-only batches.

Readers keep their committed snapshot during preparation. After a batch, recomputed vectors and the remaining prior vectors are readable under the exact new revision, with partial semantic coverage disclosed independently. Pause, cancellation, helper failure, source priority and restart use the existing service work/continuation contracts. No uncertain inference request is automatically replayed.
