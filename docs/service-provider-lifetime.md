# Service provider lifetime

In 1.4.4, owned Unix cleanup first checks for a waitable leader and an empty process group. If that proof is incomplete, it attempts one signal after independently rechecking ownership, then polls fresh completion observations within the original deadline. Native signal and observation errors do not authorize reaping. At expiry, the signal error, latest observation error, or timeout is returned with ownership retained. This handles macOS zombie-only groups, which can reject a group signal with `EPERM`, without releasing live descendants or treating permission denial as success.

The default 1.4.0 service uses the existing `airk` executable in a private Unix guardian role for each admitted extraction provider, including the PDF subprocess. This adds a process role without adding a third deployed executable. Windows retains native Job Object containment. Providers must remain in their private group; these mechanisms are lifetime ownership for trusted providers, not a sandbox.

The project worker passes three pipe endpoints and a duplicate of its native project-lease file description over a private socket pair. Provider stdin, stdout and stderr connect directly to the worker. The guardian receives bounded command metadata and lifecycle requests; it never forwards source or extraction bodies. It starts before any async runtime and does not load an inference model. Existing parser CPU/address-space limits still apply, with the existing macOS physical-memory observation policy.

Before spawning, the guardian durably records a content-free ownership intent in the existing 32 MiB service registry. After spawning, it binds the exact group identity before acknowledging startup. There are at most 128 records, each at most 4 KiB. The actual parent retains the unreaped leader through native group-drain confirmation, then completes its record. Worker EOF causes the guardian to drain the group. The shared project-lease pin remains held until guardian process exit. Creating a pin disables explicit unlock by the original owner: only the last descriptor close releases that lease, including when the original Rust owner drops normally.

Worker cleanup retains its resident/work allowance until provider records and the project lease have drained. Restart admission also waits for unresolved predecessor providers, even when both worker and guardian have died. Cached resource observations expose `pending_provider_drains` and `provider_drain_error`; bounded RSS observations include guardians and group members. Reservations remain the admission floor, with incomplete telemetry reported explicitly. No hard service-wide RSS ceiling is claimed.

Recovery never sends a signal to a remembered numerical PID or process group. Within the same native process scope, signal zero can prove group absence; permission denial or a live/reused group retains the record. Linux binds boot identity and PID namespace. macOS uses a boot-session UUID when available; otherwise only a strictly lower fresh monotonic uptime in the same native process scope proves reboot. Wall-clock boot timestamps are not used. A record interrupted before group binding remains unresolved until positive reboot evidence. Timeouts, record age and client disappearance never free uncertain capacity. Restore damaged ownership metadata rather than deleting it to force admission.

The signal-zero contract is documented by [Linux kill(2)](https://www.man7.org/linux/man-pages/man2/kill.2.html). Apple's [native sysctl implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sysctl.c) exposes the boot-session identity; its wall-clock boot-time interface is a different observation.
