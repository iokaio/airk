# AIRK 1.5.4 development record

Status: 1.5.4 release candidate, 27 October 2026. Earlier local build evidence is retained below; release-cycle validation is recorded separately. Publication requires protected-main CI and authorized release workflows.

Native workspace packages, extension manifest and lockfiles are synchronized at 1.5.4. This release also includes the unpublished 1.5.3 changes: writer-bound snapshots for long semantic preparation, cancellation/progress checkpoints, explicit Semantic and Hybrid search with coverage, missing-source project removal and bounded unreadable-directory diagnostics. This follows the failed installed upgrade of the [1.5.3 local candidate](release-1.5.3.md). Its earlier fixture tests did not cover an existing format-6 service registry without the new traversal table.

The reported 49-second installation failure followed successful service shutdown in approximately 20 seconds. Installer quiescence opened the registry through the writable startup adapter, which required the newly added traversal table before it could create it. The 45-second polling loop suppressed that schema error as unreleased ownership.

- Watcher diagnostics now use an explicit transactional format-6-to-7 registry migration at startup. Saved older metadata remains read-only and reports no traversal observation. Fresh 1.5.3 registries with the exact additive table retain their observations during migration. Completed format-7 table loss remains a failure.

- Drain ownership checks read saved metadata without migration. Only ownership/SQLite contention is retried; permanent errors retain the underlying cause immediately.

- Admitted runtime activation records its durable intent before stopping the verified optional manager and hard-stopping same-user predecessor main/helper/launcher processes. Windows uses captured process handles and Linux uses pidfds; older releases need no new shutdown protocol. The shared process exit wait is five seconds, excluding verification, manager, copy and startup work. Connected AIRK clients must reconnect after upgrade. Post-upgrade retirement uses the same verified hard-stop path before deleting the old payload and restarting the selected service. A controlled restart of an exactly verified healthy service bypasses crash backoff; failed/unobserved startup retains the existing circuit.

- A newer bundled installer can resolve an exact superseded Drain/Launcher intent with native candidate/predecessor guards before starting its own upgrade. It does not retarget an admitted Probe or a committed selection.

- macOS retains the authenticated control/manager drain; forced predecessor termination is not implemented there. Older runtime binaries supporting only registry format 6 cannot restart after format 7 is committed. No metadata downgrade or source/index reset is performed.
