# Response to repository review 01

Date: 2026-10-30. This response concerns the unpublished 1.7.3 stable release candidate on `fix/extpkg`. The supplied [original review](reporeview01.md) remains a historical assessment of commit `c62c1e6936500801dbf41dffdd6e21453e48335d` (1.7.2); it is not rewritten as a review of these changes. Its linked companion reports and audit JSON were not supplied in this checkout.

## Changes made

- Confirmed the default attribute-iterator calls in Office and XML/SVG extraction. Updated quick-xml from 0.39.4 to 0.41.0, the patched release for [RUSTSEC-2026-0194](https://rustsec.org/advisories/RUSTSEC-2026-0194.html). Added a per-element 1,024-attribute ceiling to Office XML validation, XML/SVG facts and shared Office attribute lookup. Duplicate-name checks remain enabled. Attribute decoding explicitly preserves the previous literal-whitespace behavior instead of adopting the new upstream normalization API; a regression verifies tabs, newlines, carriage returns and entity decoding. MSBuild already limits each element to 256 attributes. Regression coverage accepts the boundary, rejects one attribute over it and retains duplicate-name rejection.
- Reproduced the npm findings against the extension lockfile. Updated only the affected publishing-tool dependency chain: Azure Identity 4.14.1, MSAL Node 7.1.2, its MSAL Common 16.15.0 dependency and qs 6.17.1. The [MSAL advisory](https://github.com/advisories/GHSA-xcx6-jx8p-x3h5) is patched at 7.1.0 and the [qs advisory](https://github.com/advisories/GHSA-6pq8-jhm2-2vcw) at 6.16.1. These updates fit the existing direct dependency constraints; the installed extension's jsonc-parser runtime dependency is unchanged. Preserved existing optional-platform restrictions in the lockfile.
- At the user's request, upgraded Tokio 1.53.2 to 1.53.3 and ZIP 4.6.1 to 9.1.3 rather than leaving those findings for follow-up. ZIP's fallible member-name API now propagates enumeration errors; existing CP437 member names remain readable, and duplicate XLSX parts are rejected before workbook reads. Added regression coverage comparing retained evidence with a legacy-encoded extra member and rejecting ambiguous duplicate names. Office processing remains bounded and in memory.
- Expanded [installation and evidence privacy](../vscode-extension.md#installation-and-evidence-privacy) and the Marketplace description: automatic host changes, native discovery despite auto-install opt-out, hidden/sensitive sources, retained result excerpts, agent-provider disclosure, storage permissions and uninstall limits. AIRK is not a secret scanner.

## Deliberately deferred

The user selected documentation now and permission enforcement separately for existing custom storage. Existing root permissions and ownership are not changed or newly rejected in this patch. Newly created Unix storage remains mode 0700; an existing shared root can still expose source-derived data. A future change needs migration and Unix runtime evidence before changing admission or permissions.

The source-only review did not verify distributed artifacts. That limitation is preserved. Release promotion retains authenticated producer records, artifact digests, platform signing/notarization, payload/source/lock checks and public-asset verification; these controls do not establish reproducible binary/source equivalence. Published 1.7.2 now exists on both destinations; the review's earlier catalog observations are historical.

No default installation policy change, storage migration or new routine CI matrix was added. The original report's dependency reachability assessments are not elevated into verified exploit claims. Installed cargo-audit 0.22.2 and audited all 374 lockfile packages against RustSec database commit `2295466c4e9df26647fd67d8fa1c705ac2fc7f81` (updated 2026-10-30). The final audit exits 0 with zero vulnerability matches: the quick-xml and ZIP advisories and Tokio AsyncFd unsoundness warning are cleared. Only the existing unmaintained paste/ttf-parser warnings remain. No advisory is suppressed. This is a dated dependency check, not proof of complete security.

## Validation

The focused ingest suite passed with the updated parser, ZIP and XML/filename regressions: 279 tests passed, seven ignored. The extension suite passed after a clean install of the updated lockfile: 419 passed, 15 skipped. The lockfile-only npm audit reports zero vulnerabilities. The [1.7.3 release record](../releases/release-1.7.3.md) records available repository/release checks, the unconfirmed full workspace result and the user's successful local installation report. Further local tests were skipped at the user's request before commit and PR creation. Local Windows evidence does not qualify macOS/Linux or the published package.
