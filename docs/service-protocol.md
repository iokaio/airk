# Native service and direct query protocol 1

Worker status can include optional transient `waiting` metadata: exact job, native wait reason and monotonic age. Private worker replies report the active grant and typed wait separately from progress; the supervisor accepts only its matching charged grant. Console pages can include the oldest `pending_job` and a native `pending_paused` observation, without admitting work. Existing absent optional fields remain valid. Stored progress is unchanged; see [the console contract](service-console.md).

Current development console/global lifecycle contracts are described in [the trusted service console](service-console.md). Its persistent metadata channel never carries evidence grants. Global stop/restart is an installed native transaction with a durable request key and observed instance; project restart remains a separate operation. Cold direct setup now retries transient admission/transport conditions within eight attempts/thirty seconds before submitting a query, with fresh health/grants and no uncertain query replay.

This contract describes the native 1.4.0 implementation, now used by the default extension and public CLI. It uses a fresh storage namespace and service-owned scheduling. The [shared embedding runtime](service-embedding.md), native installation and guarded maintenance are implemented. Complete publication/resource workload validation and installed-platform qualification remain open in the completion checklist.

`airk serve --runtime-dir <private-directory>` holds the service OS lease and listens on a user-only named pipe on Windows or a protected Unix socket. Both endpoints authenticate same-user peers. Control uses length-prefixed JSON with a 64 KiB maximum, five-second frame deadlines and 64 connection slots. Unknown protocol versions fail before dispatch. Health reads a cached service allocation policy, executable identity, optional install-manifest identity and uptime; it does not query a collection or wait on registry I/O. Those counters describe allocations, not live per-query worker telemetry.

The independent metadata actor has 32 queue slots and returns overload or bounded failure codes. Registration, project pages, request epochs, durable jobs and pause/cancel semantics follow [the job contract](service-jobs.md). An ambiguous acceptance timeout requires retrying the same durable key. Registry corruption leaves control health available; it does not trigger deletion or initialization over foreign state.

A saved registered source root may disappear while retained evidence remains useful. Worker activation can open an existing format-140 collection whose exact root/data/collection ownership matches that registration; it cannot initialize replacement state for a missing source. Missing paths require the saved absolute canonical identity, with unchanged existing ancestry. New registrations still require live roots. Retained queries and integrity checks remain available, while index/path-refresh/rebuild jobs fail with `source_unavailable`. Scans recheck roots before constructing deletions, so an unavailable root is not treated as a complete zero-file inventory. Service collection status includes an observation time and `available`, `unavailable` or `unknown` source-root availability, independently of indexed revision and coverage. Availability checks root locations, not every source file's readability.

The earlier complete workspace run is still progressing against its preceding snapshot. Installed-editor and macOS acceptance remain open.

The supervisor uses [service-wide resource admission](service-resources.md) for at most 32 project processes and uses a separate 32-slot brokerage queue. It admits one query and 64 KiB of response credit to each resident worker; allocations are not released until process exit is confirmed. Each identity/activation handshake has a ten-second bound and failed starts back off exponentially up to 64 seconds. Pending or interrupted jobs trigger supervision without a connected editor. One worker holds the project's OS lock, advances its durable generation, classifies interrupted jobs and claims only the exact job named by a service-issued work grant. Index/reconcile, vectors and bounded retained verification execute through the kernel. Replacement rebuilds use fresh owned sibling slots and an atomic manifest handoff; each native read pins the selection for that call. See [publication and retirement](service-publication.md).

At service restart, a bounded identity-only registry audit checks predecessor project locks. All new resource allocation waits for those locks and the separate pooled-inference lease to release, including when the old owner has no queued job. A new child first acquires its lock and reports identity, then waits for the service to account its allowance and acknowledge activation before opening collection state. Buffered initialization alone cannot activate a late child after parent death.

Parent/child anonymous pipes carry initialization, worker identity/activation, allowance renewal, work grants/completion observations, bounded source-freshness samples, connection grants and stop intent. They carry no retrieval request or evidence. Parent EOF stops new query/job admission; existing work drains while retaining its lease. Normal service shutdown requests drain, then terminates and reaps a child that exceeds its ten-second grace period. Durable journal/job recovery remains responsible for interrupted work. Workers retire after fifteen idle seconds. Their five-minute resource horizon is renewed every thirty seconds through private supervisor acknowledgements; expiry or failed acknowledgement drains ownership before capacity is reassigned. These are initial finite policy defaults, not measured workload objectives.

`connections` brokerage requires an already registered binding. It can start a worker but cannot register a project, index or install a model. The worker issues a random single-use grant lasting fifteen seconds, bound to service/worker instances, project, generation, protocol and authenticated user counter identity. Credentials travel only over protected control IPC. The returned role must equal the fixed role derived from the worker instance; a client computes its endpoint inside the verified runtime root and checks the direct identity acknowledgement. Replayed, expired, foreign or superseded grants fail.

The direct connection carries only read-only MCP tool calls and results in bounded 64 KiB frames. Established authorization lasts sixty seconds; idle reads wait at most thirty seconds. The bridge obtains fresh brokerage before reusing a channel older than fifty-five seconds or idle for twenty-five seconds. Canceling an in-flight exchange invalidates its channel so an unread reply cannot satisfy another call. This refresh happens before submission; ambiguous failed queries are not replayed. Each connection processes one request at a time. Worker-local policy shares the one-query allowance across every connection and authenticated caller. Reserved output capacity remains charged through result materialization and bounded socket writes. An oversized result or broken connection fails explicitly; there is no partial successful response, direct-store fallback or service forwarding path. Revision selectors remain unchanged when the client obtains a fresh connection. The native query/result envelope also carries a fixed content-free [response-status receipt](mcp-response-modes.md) for that client. The bridge retains it across renewed connections and advances it only after a complete result. It contains at most five state digests, is not a credential or evidence validator, and never enters service brokerage. Native usage accounting measures the same MCP result the client receives; the bridge does not subsequently shrink its evidence.

`airk bridge --runtime-dir <directory> --project <binding>` exposes the existing sixteen read-only tools through stdio. It opens neither sources nor index databases. Its request-line reader caps allocations before JSON parsing and permits at most four outstanding calls. A failed direct connection is discarded; a later request obtains a fresh grant. A shared worker-side MCP dispatcher records the collection usage observation once. The bridge forwards a bounded informational client-family label; it grants no authority and never changes collection scope. Brokerage and bridge forwarding add no duplicate usage entry.

Store and broker tests cover additional bounded/fencing transitions. Cross-platform installed lifecycle, full load/fault matrices and cross-platform pooled inference remain separate qualification gates.

Captured publication recovery runs as an admitted `recover` job. Successful operations perform a bounded retirement pass and save a content-free observation; the service schedules finite, durable `maintain` follow-ups for deferred cleanup. Idle retirement is deferred only while that bounded maintenance allowance remains eligible. Explicit maintenance cancellation suppresses automatic follow-ups. The `maintenance` control read reports the ledger's cached result and observation time without opening an index. See [durable maintenance behavior](service-jobs.md).

The opt-in [offline installer and stable launcher](service-installation.md) now stage approved payloads, select after native health and run the service on demand. An optional idle grace excludes health polling and waits for runnable jobs and resident owners to finish. Unix sockets use a short private namespace bound to the canonical runtime/user identity, independently of durable metadata. Windows child ownership uses Job Objects and preserves host-policy denial. Default editor cutover and installed qualification remain open.

Trusted native management also exposes [retained event pages and explicit retry](service-events.md). These operations use the metadata actor and ledger; they do not open collection indexes, forward retrieval payloads or add MCP capabilities.

## Cached worker observations and explicit restart

Trusted native control provides `worker { project }` without opening a collection or starting a closed project. It returns an optional exact `WorkerIdentity`, queued restart state, whether automatic startup is blocked, and the cache observation age. These observations are separate from index freshness, job progress and project registration. A missing worker does not mean its indexed evidence was deleted.

`restart_project { project, expected }` requires the exact currently observed worker identity, or `null` only when no worker is resident. Foreign/stale identities return `project_worker_changed`; a registered closed project may be started explicitly. The response `project_restarting` accepts the request without claiming that native drain or startup finished. At most 32 restarts are queued. Poll worker observations for a different worker incarnation and larger fencing generation. A timed-out acceptance has an explicit unknown outcome; inspect before submitting a changed identity.

The supervisor first stops the accepted old incarnation, waits for its native descendants and provider ownership pins, then returns its execution/resident allowance. Only that completed drain phase can admit a replacement. Unrelated workers and the service instance remain intact. Retained evidence can reopen with unavailable source roots; restart neither scans sources nor deletes evidence. Interrupted running jobs keep their durable recovery rules and previous receipts. Read-only MCP tools cannot invoke restart or worker management.

Unexpected project exits and startup/control failures consume a finite three-attempt automatic startup budget with exponential delay. Ordinary brokerage does not reset an exhausted circuit. Explicit restart clears that project's budget; repeating an already queued request joins it without resetting attempts again. A restart that exhausts startup becomes blocked rather than running an endless retry loop. Worker observations expose that state even when collection opening failed; source/job failures and native logs remain separate observations.

Temporary direct setup exhaustion returns a structured `direct_query_setup` rejection with `query_submitted:false`, a 100 ms retry hint and fresh-brokerage requirement. Only recognized transient setup failures receive that hint; permission, identity and unknown errors remain failures. Setup retains its own thirty-second/eight-attempt limit. No submitted or ambiguous query is replayed.

Native acceptance callers honor explicit publication/selection rejection for both tool calls and read-only CLI aliases, retaining the exact original arguments, revision and cursor within a finite deadline. They do not reinterpret that rejection as an accepted configuration/index request or retry mutations.
