# AIRK 1.5.5 development record

Status: local development patch on `feat/explorerrefinements`, 27 October 2026. Native and extension manifests and lockfiles are synchronized at 1.5.5. This version is not published or installed by this patch.

Explorer refinements in this candidate:

Management now exposes per-project index storage roots, accounted size, reservations and quotas with explicit inspection age and a fresh inspection action. Legacy startup review is collapsed. Projects and Indexing show executable versions with their observation basis. Agents explains Terse versus Full and the context-budget reason for the default. Usage & Savings loads inside its tab with the existing report controls; exports remain explicit. Logs shows recent events and opens distinct service/extension output channels using the native 32-record limit.

- Studio has a named Save action for complete draft inputs in the selected local project’s `.airk/strategies/`, without a folder picker. Loading restores inputs and edited prompts but recollects evidence. Built-in templates are saved as user definitions; collisions, outside edits, trust/binding changes, dirty editor buffers and redirected paths are guarded. Export remains definition-only.
- Search and Changes share spaced pagination controls with live page announcements. Failed Changes pages retain a labeled last successful page and require Refresh before more paging. Disconnected Review hides previous reports; empty Changes explicitly reports no uncommitted changes. The Tests fallback now propagates the actual WORKSPACE_UNTRUSTED error code.

- Search retains the selected project's form, latest completed result and page across tab changes and panel recreation in the same extension-host session. In-flight results can finish into that session after close/reopen. Project/binding changes clear it. No snippets or query draft are written to workspace Memento. Panel-generation fencing prevents an old request ID from answering a recreated panel's request. Incoming searches run once rather than repeating on each tab remount. Older-publication results remain labeled.
- Search displays twenty retained hits per page with Previous/Next and range/count indicators. The native request limit stays at up to 100, subject to its byte budget. Changing pages does not submit another search.
- Review Changes pages through the complete Git change list fifty files at a time. A Git-list digest and publication check prevent continuation across changed observations; refresh starts over. The old fifty-file total cutoff is removed.
- Impact and Tests shared test-directory discovery requested 200 files from a tool whose valid page maximum is 100. It now uses valid pages and existing cursors, retaining truthful clipping and sampling limits rather than removing native response bounds.
- Review reports restart once when a present publication identity changes, discarding the first attempt, within a shared 90-second deadline. Identical reads share a result only within an attempt. Missing identity, integrity and other tool errors are not retried as publication changes. A changing later Changes page requires refresh of the list.
- Tests is a change-focused candidate checklist: Git-observed changed test files and indexed textual-reference candidates appear separately, with counts and reasons. Refreshing unchanged inputs is expected to return the same candidates. Failed indexed analysis keeps changed test files visible, shows the original failure and an unknown declaration count, and omits unverified indexed references. It does not execute tests, report pass/fail outcomes or measure coverage.

Regressions cover session restoration, late completion across panel recreation, project/binding isolation, incoming-search consumption, exact twenty-hit pages, 123 changed files without omissions/duplicates, native inventory cursors, one successful report restart, persistent churn, missing identity and integrity-error handling. Bundled Help and Marketplace documentation describe the same behavior.

The locked dependency is unchanged; its minimum version is made explicit for the existing incremental matching API.
- Directory planning prunes ignored candidates before child metadata/listing access. Included permission failures remain `root_unavailable`; returned ignore-load errors remain `metadata_unavailable`. No permissions, original source files or private/index state are modified.
- Matchers are isolated to a root and refreshed with each bounded plan. Parent/root watches remain. Both additions and removals of watched directory scope request reconciliation, including changes caused by rules outside the watched root. The existing periodic reconciliation remains the backstop for external file-only rule changes.
- The native watcher reads ignore configuration through ingestion's adapter, but opens no source documents or derived indexes. Its service channel remains metadata-only. Existing collection/root isolation, no-follow checks, directory/path/entry/depth bounds and process supervision remain.

Regressions cover discovery/watch parity, negated inclusions, nested and parent rules, Git excludes, rule reload, malformed rules, foreign paths, scope-removal reconciliation, retained parent watches and an actual Windows ACL denial on an owned fictional directory. The ignored case completes; removing its ignore rule reports the same real permission failure. The fixture restores its own ACL before cleanup.
