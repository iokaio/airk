# Arbiter distribution through Hugging Face and GitHub Releases

*20 November 2026 · Approved source preference and implementation plan*

Use **Hugging Face as the primary download source and GitHub Releases as the backup** for AIRK’s custom, publicly distributable Arbiter assets. Publish the same ONNX graphs, external weight parts and required companion files to both hosts. Hugging Face serves large models through its storage and CDN network. GitHub retains a complete independent copy, so a fresh install can succeed from either host when the other is unavailable. ONNX Runtime and the planned provider sequence remain the inference strategy. [Hugging Face model downloads](https://huggingface.co/docs/hub/models-downloading) · [Current implementation plan](../arbiter/final-plan.md)

AIRK’s compiled catalog owns filenames, source locations, lengths and SHA-256 values. Use existing approved upstream repositories only for files that match the selected bytes exactly. Publish AIRK-derived graphs, weights and companion files to the AIRK-owned Hub repository with their verified licenses and provenance. For scale, the retained `models-1.8.201` catalog has 44 parts totaling 24,130,010,313 bytes and a 1 GiB maximum part. Use the approved final asset roster for actual storage, transfer and verification budgets. Hugging Face applies resolver rate limits, and public storage is subject to its plan and usage policies. Verify those limits for the intended organization before rollout. [Retained catalog](../../crates/airk-retrieval/src/arbiter/release-catalog.json) · [Hub rate limits](https://huggingface.co/docs/hub/rate-limits) · [Hub storage limits](https://huggingface.co/docs/hub/storage-limits)

## Public asset names

Use the same flat filename on both hosts. For new bundles, use `airk-arbiter-<slot>-<upstream>-<variant>-r<revision>.<role>.<extension>`. Use `focus`, `context-compact` or `context-large` for the slot, the recognizable publisher model name, and a variant that states the precision and any target that changes the actual artifact. Allocate a three-digit bundle revision starting at `r001`. Use the full Hub commit SHA and the approved GitHub release tag in URLs. The revision in the filename distinguishes the artifact itself from the application release.

| File | Illustrative name |
| --- | --- |
| Focus graph | `airk-arbiter-focus-qwen3-reranker-0.6b-cpu-int8-r001.model.onnx` |
| Compact weight part | `airk-arbiter-context-compact-qwen3-1.7b-windows-cuda-fp16-r001.model.onnx.data.part001` |
| Large compiler configuration | `airk-arbiter-context-large-qwen3-4b-windows-cuda-fp16-r001.compiler.json` |

Choose the labels from the approved build. Give shared bytes one canonical filename when several profiles can use them. Number split parts from `part001` in manifest order, with each part at most 1 GiB and at most 16 parts per logical file. Keep names lowercase ASCII and within Core’s 192-byte component limit. Title cards and release notes can describe the model in prose. Use a new bundle revision when content changes, and retain existing published filenames and pins for older clients. These names are transport names. Preserve installed logical paths and the external-data locations embedded in ONNX graphs. The Rust source map should carry the explicit mapping.
