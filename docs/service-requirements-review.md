# AIRK 1.4.0 requirements review

October 25, 2026. This reviews the complete [service plan](airkservice-architecture.md), including requirements before its phase table. A code path, a passing mechanism test and installed-platform qualification are different forms of evidence. The [completion checklist](service-implementation-checklist.md) retains outstanding exit gates; the [qualification record](service-cutover-qualification.md) identifies tested artifacts and observations.

## Local candidate gates still being completed

- Full frozen Windows workspace and non-root Linux production Docker runs.
- Serial documentation tests after all Cargo build/test processes finish, plus final formatting, Clippy, extension/Python, license, repository and whitespace checks.
- Final Linux container runtime and isolated tmpfs full-volume campaign.
- Final documentation/checklist reconciliation, review, strict VSIX packaging and all five scenarios against that installed VSIX.

The reviewed runtime pair and stage-only editor acceptance do not create a VSIX. Packaging follows the preceding gates. No public release is implied by a local manual-test candidate.

## Checks requiring another execution environment

The available host does not establish native Mac qualification, minimum Windows/macOS versions, actual SSH/WSL/remote-editor behavior, low-memory/slower-disk hardware classes, or enforced EDR/TCC/noexec/SELinux/AppArmor policy. Native Mac execution has been requested separately and remains unavailable. Physical device/cache power loss has not been simulated.

Published target promotion remains behind the plan's installed-platform/signing matrix. Existing publisher-declared license records for three upstream crates still need release review because their packages do not contain separate license texts; pinned declarations are preserved without inventing legal approval. These qualifications are not silently counted as passed.
