# Request execution and verification costs

The 1.3.x standalone adapter runs at most four evidence requests and two control requests per server instance. Status and capabilities use the control capacity. Up to sixteen additional requests wait for a permit for at most five seconds; a full queue or timeout returns a retryable capacity error. `airk_capabilities.request_admission` reports worker and queue limits, the current process-local queue length and rejected-request count. Separate MCP processes have separate limits.

The opt-in 1.4 service adapter instead shares one native materialization permit across all clients of a project worker, including status and capabilities. This matches the resident allowance for one bounded query. The permit covers kernel work, rendering and usage accounting, and survives cancellation or local transport failure; an outer IPC grant becoming free cannot start another materialization while that work remains active. Client sessions share admission while keeping their response receipts independent. `request_admission.shared_execution_budget` distinguishes this policy. Service shutdown drains that shared permit once. Independent service health and cached supervisor/resource observations stay outside project materialization.

An accepted request runs its usage setup, kernel operation, serialization, baseline lookup and ledger write on one blocking worker. Filesystem and SQLite waits therefore leave the asynchronous protocol executor available. In the standalone adapter, an evidence workload cannot consume the reserved control permits. A contended store can still delay its own accepted requests; this is bounded concurrency, not a universal latency guarantee.

Cancellation removes a queued request or stops waiting for an accepted response. Already accepted synchronous work completes and records once, retaining its permit until accounting finishes. Closing stdio or the local tool client stops admission and drains accepted workers. AIRK does not forcibly interrupt a thread holding SQLite state. Abrupt process termination can lose observations. Requests rejected before admission do not start usage spans and appear in the admission counter rather than the usage ledger. Optional usage failures retain the existing dropped-observation reporting and do not turn a successful retrieval into an error.

Current-index lexical and hybrid reads use head-bound physical lexical verification or a bounded guarded snapshot from the same process. A digest or timestamp alone never authorizes reuse. The [cache contract](indexing-follow-up-2026-10-21.md#lexical-cache-integrity-contract) describes file identity/change and SQLite witnesses, Windows notifications, thirty-second expiry and the limits of warm verification. Explicit integrity diagnostics bypass it. Hybrid shares verification across candidate branches; vector filtering and candidate fusion retain private chunk ordinals until the final text budget is applied.

Full-source usage comparisons authenticate only the receipt-bound manifest and catalog they consume, with the reader lease retained during lookup. They do not repeat vector, lexical or model verification already required by retrieval. The store's measured lookup API reports authenticated logical bytes, verification time and lookup time separately. This is a narrower authenticated projection, not a cross-request verification cache. Catalog hashing still scales with catalog size; the SQL progress deadline does not include hashing time. Logical bytes are not physical disk traffic.

Run the binary/source-bound retrieval qualification with:

```console
python scripts/check-retrieval-quality.py --binary target/debug/airk --output target/retrieval-qualification.json
```

Use `airk.exe` on Windows. The receipt contains fixed code, prose, minified, long-line, multilingual, alias and sparse-filter judgments, cold/warm latency distributions, usage enabled/disabled trials, four concurrent processes and available process counters. First-query latency means a new MCP process; operating-system caches are uncontrolled. The original static vectors establish adapter behavior only. Held-out judgments live outside the indexed source fixture; this is not an evaluation of learned semantic quality. Hosted native CI retains a receipt for each platform's exact binary.
