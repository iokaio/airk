## Workbench and MCP return the same data

CLI tool calls/shell and dedicated read aliases use the same frontend response-observation path as MCP, including capacity reporting. All 17 Workbench read operations now use the MCP handlers: search, symbols, references, read_file, outline, list_files, file_info, imports, code_facts, document_facts, changes, context, relationships, status, diagnostics, capabilities and help. Workbench keeps the full MCP result inside each completed step, including readiness, freshness, original locations, revision identity, coverage and result metadata. Fact results use the MCP `items` representation. Workbench requests full responses and retains its explicit rich fact default. Request IDs and cache observations describe individual requests.

Workbench `/status` and `/diagnostics` include `query_concurrency` inside completed step results. This reports configured frontend evidence capacity, not free slots. The outer parse admission observation is reused without another policy read or RPC. Payload accounting and output limits still apply; truncation remains explicit.

If added frontend metadata makes a step exceed the plan payload budget, the omitted result releases its previous byte charge. Later results can still fit, and `payload_bytes` counts the retained payload. The shared metadata mapper applies this rule to both configured-capacity and unified project/editor observations; omissions remain explicit failures with truncation/completeness details.

Forms and slash options expose native read inputs, including full search chunks, conditional validators, continuity/change selectors, detailed capabilities and help topics. Inner reads share the outer plan's permit, revision checks and accounting without recursive MCP calls or duplicate usage entries. Source files remain read-only.

The extension's Marketplace summary and README now describe complete cited results and configurable concurrent retrieval. Its Workbench screenshot was regenerated from the compiled 1.8.7 UI, showing code/document cards, linked selection, source/context actions, Complete response and export. The caption identifies fictional project data; the image is a UI preview, not installed-editor qualification. The package's explicit public-image allowlist uses the new versioned asset and retains historical screenshots for their original records.

See the [complete CLI/MCP/Workbench audit](../read-interface-parity.md) for command mappings, options, result contracts and regression coverage. Both `AGENTS.md` and `CLAUDE.md` now require shared implementations, complete response/input parity and native/transport regressions for future read-contract changes.
