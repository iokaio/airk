# AIRK 1.8.2 candidate

Unpublished source candidate, 2026-11-01, on `feat/optimizations`. Native and extension manifests/lockfiles are synchronized at **1.8.2**, as requested for this parser correction. It carries forward the [1.8.1 Workbench scrolling fix](release-1.8.1.md) and [1.8.0 storage/startup work and qualification limits](release-1.8.0.md).

A finite conversational grammar handles complete simple evidence requests before classifier fallback through the native `parse` operation shared by Workbench, CLI and MCP. “I want to know about struct Owner.”, explicit typed or quoted single identifiers, and definition/declaration requests use the existing bounded definition recipe. Symbol extraction preserves the identifier separately from its type word. Untyped capitalized, snake_case or qualified identifiers collect symbol candidates plus text search; ordinary lowercase or multiword topics use text search. Complete supported forms include “Find the…”, “Tell me about…”, “I want to know about…”, “What is…”, polite/modal variants, type words before or after names, and dotted/`::` qualified names. Unsupported and compound requests still require clarification or an explicit reviewed plan. General symbol requests may return multiple cited candidates; choosing among definition paths remains explicit. Existing definition/reference forms also normalize articles/type words, and lowercase or multiword definition targets retain the bounded name resolver. Uncertain classifier results expose the candidate, rejection reason and explicit-command examples. Learned classifier proposals remain review-only. Model calibration retains the accepted-intent precision requirement; changed score scales have separately calibrated thresholds. No automatic learned-execution qualification is implied.

The runtime grammar also recognizes supported developer, writer, architect and QA/tester phrasing for source ranges, outlines, file metadata/inventory, imports, document facts, references, changes and readiness. Test-related searches and references return broad textual candidates with a warning unless a literal test-path prefix is supplied; they do not report executed coverage. It passes the 476-case public source inventory and the 48-case later role regression (524 total). The latter initially measured 35/48 (23/36 supported and 12/12 unsupported); its [13 original misses](../../tools/parser-train/novel-role-plan-first.json) remain recorded. The corrected 48/48 is known regression evidence, not fresh unseen evaluation.

## Keep the question visible in Workbench

New pending, completed and failed turns now scroll to the **query bubble**, keeping the question above the timestamp, plan/evidence details and results. Oversized queries reveal their beginning. Manual transcript/nested reading positions and expanded details remain retained across tab hiding and status/save updates. The [1.8.1 first-result reveal](release-1.8.1.md) remains a historical record; this 1.8.2 correction changes the anchor to the question.

## Select and copy returned results

Structured results now have linked **Select all N** checkboxes at the top and bottom, with **Copy selected (N)** beside Select all in both rows. Select all covers every matching result already in the response, including records behind **Show 20 more**, and never fetches an unreturned page. Filtering preserves other selected records; clearing a filtered set removes only its matches. The controls share checked/mixed state and support native Tab/Space interaction. Zero-match/no-selection actions are disabled as appropriate.

Copy selected keeps the selected set, including hidden-by-filter selections. The structured evidence list removes redundant full-response copying; Save export remains. Raw JSON/Markdown and status/no-evidence output retain full-output copying where needed. Existing copy limits stay enforced: oversized selections show an instruction to select fewer results or use Save export, rather than silently dropping records.

To experiment in your own fork:

1. From the repository root, run `python tools/parser-train/export_datasets.py verify`, then `python tools/parser-train/export_datasets.py restore`. Inspect selected gzip rows without downloading anything. Restore refuses different existing bytes.
2. Follow the [parser-training fork guide](../parser-training.md) to install pinned Python dependencies. `python tools/parser-train/fit-saved.py --report tools/parser-train/qualification-broader-v5.json` replays the exact fitted bytes offline; add `--extra-training target/parser-train/my-examples.jsonl` for your own original labeled examples. Extra-data runs are explicitly unqualified local experiments, preserve input digests, reject frozen validation/calibration overlap and never replace the product asset.
3. For full corpus regeneration, prepare the pinned public vocabulary/query inputs and edit original role/phrase examples, keeping labels, expected tools, literal targets, family/role and provenance explicit. Do not train on held-out rows. Run `python tools/parser-train/broaden.py`; it regenerates the joint whole-family splits and prints the frozen development-report path. Run `python tools/parser-train/broaden.py --evaluate PATH_TO_FROZEN_REPORT` with that actual path. Review accuracy, accepted precision, abstention, unsupported acceptance, role results and native plan/slot tests separately. Reused public fixtures are known regressions, not fresh unseen tests.
4. Only after reviewing those results, use `python tools/parser-train/install_review.py PATH_TO_EVALUATED_REPORT --suggestions-only`. The installer can refuse the candidate. A successful review install updates the asset/manifest/goldens and keeps learned execution disabled. Rebuild and test the native parser; changed installable candidates need a new model identity, synchronized version and normal runtime provisioning.
5. Preserve prior reports/data. After review, `python tools/parser-train/export_datasets.py publish` refreshes the canonical data/catalog, followed by `verify`; it never stages, commits, pushes or uploads. Custom raw data, local retention, source clones and native/private index state stay ignored and outside runtime/VSIX payloads.
