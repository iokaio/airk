# AIRK 1.5.3 development record

Status: local test candidate, 27 October 2026. Publication requires protected-main CI and authorized release workflows.

Native workspace packages, extension manifest and both lockfiles are synchronized at 1.5.3. This patch carries forward the [1.5.2 changes](release-1.5.2.md). The service namespace and index format remain unchanged; existing semantic work can resume without rebuilding the lexical index.

- Publication preparation now uses a snapshot admitted by the matching collection writer. Long inference and DiskANN construction can exceed the 120-second query deadline while retaining their exact base revision and object leases. Releasing the writer invalidates its build snapshots. Queries keep their existing deadline; storage and graph budgets remain enforced.
- Semantic preparation checks cancellation between vector insertions and batches and records real candidate advancement for the watchdog without claiming that those vectors have been published.
- Explorer Search exposes **Semantic (by meaning)** and **Hybrid (lexical + semantic)**, with natural-language query guidance and semantic coverage on results. Semantic selection uses the existing native `vector` mode and saved-recipe contract; it never silently falls back to lexical search.
- Management › Projects and Indexing expose **Remove project…** directly. The native inspection and guarded unregister flow works from retained settings when the source folder has been deleted. Successful removal shows unregistered projects with preview and confirmed index-cleanup controls. Sources and saved settings are preserved; missing source folders are not recreated. Watcher unavailability remains visible until restoration or unregistering.
- The same Management tabs expose bounded **Unreadable directories** diagnostics. Traversal still stops on its first failure per root. Paths clear only after their root is fully scanned; the log records project availability transitions once rather than repeating failures on each retry. Deduplication survives service restarts for the same configuration. Source content and paths stay out of the bounded process log.

See [publication lifetime](../service-publication.md), [project retirement](../service-project-retirement.md) and [source watching](../service-source-watching.md) for the contracts.
