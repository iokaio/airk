# AIRK 1.5.10 local candidate

October 28, 2026. Unpublished changes on `feat/manageindices`, following the installed 1.5.9 investigation. Native/extension versions and lockfiles are synchronized. No publication or push is authorized.

Job failures now retain a separate local raw error chain, including failures deferred for retry. Management can open/save the raw job-error ring from Logs and open it directly from failed project/repair panels. The normal summary log and diagnostic report remain metadata-only. Earlier generic failures cannot be reconstructed. Finished repair plans show their aggregate success/failure instead of implying that “finished” means repaired.

Maintenance now checks unused current objects as well as retired index instances. It deletes at most 4,096 proven obsolete files per pass without first accumulating every orphan filename. Consecutive no-progress/failure limits remain bounded; successful deletion batches no longer exhaust the retry budget. Active-object deletion uses a read-only database snapshot, the collection writer and exclusive object gate, avoiding new WAL/quota allocation. Current readers, captured inputs and prepared journals remain protected. Storage shows the latest deletion count and remaining cleanup observations.

Quota inventory exhaustion now has a typed, specific cause with visited/limit counts in raw diagnostics. This is a plausible lead for the remote million-file state, not an established diagnosis: that retained state has not been supplied locally. A fresh isolated run with the shipped 1.5.9 runtime successfully indexed the local Bookbuilder corpus (8,122 files, 65,364 chunks, ten publications, about 15 minutes). It did not reproduce the remote retained state or qualify semantic indexing.

[Storage format names](../storage-formats.md) are independent of executable versions: index-v1 and service-v1. Fresh native installations use an unversioned runtime location and separate format-labeled data/state defaults. Existing absolute ownership locations and historical internal filenames remain compatibility aliases; this candidate does not silently relocate existing roots or delete unknown historical namespaces. Downgrades may rebuild derived indexes rather than requiring indefinite retention of obsolete data.

Local Windows validation: formatting, workspace/all-target/all-feature Clippy, repository checks, synchronized version checks and whitespace checks passed. The complete non-ignored workspace run recorded 1,428 passes, two failing cases and 17 ignored cases. The failures exposed a shared retirement/current-object deletion-budget issue and an assertion that still expected reader contention to be an error. After correction, the complete service-runtime target (21 tests), retention target, kernel/store libraries and focused ownership regression passed. The long 200-edit retention and backlog campaigns passed. Initial doctest dependency-resolution errors cleared in a separate serial workspace doctest run. The extension suite passed 350 tests with 12 native/environment skips; Python checks passed 173 tests with four skips.

The exact pair passed the two-project client campaign with semantic indexing, three simultaneous MCP clients, all 26 tools, mixed handshake/reconnect lifecycles, missing-source recovery and automatic obsolete-request recovery. An injected metadata failure retained its underlying EOF error and matching job identity in the raw log while the summary stayed metadata-only.

The managed 1.5.9-to-1.5.10 upgrade preserved the registration and original source. Its checker was corrected to expect the existing registry schema 8 rather than 7, and now distinguishes schema, registration and source failures. Activation interruption/abort/resume checks passed. The selected extension-to-native suite passed 18 tests covering diagnostics, semantic work, indexing/rebuilds, limits and the universal launcher, with one historical migration test skipped. That standalone-helper scenario needs older pre-service binaries and is not qualified by this modern runtime pair.
