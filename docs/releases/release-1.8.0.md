# 1.8.0 optimization candidate

This is an unpublished source candidate on `feat/optimizations`. The latest published stable release remains [1.7.6](release-1.7.6.md). No publication or cross-platform qualification is implied.

Native workspace/local lockfile versions, the extension manifest and both npm lockfile root versions and the generated offline template catalog are synchronized at **1.8.0**. The extension admits forward runtime upgrades across the supported 1.4 through 1.8 lines, including its own 1.8 line. Automatic downgrades, unknown lines and malformed versions remain refused. Storage-format identities are unchanged by this version preparation; see [versioning](../versioning.md).

The [optimization execution ledger](../optimizations.md) owns implementation progress and validation evidence. Candidate preparation alone implements no optimization. F01b adds optional content-free test observations that distinguish the first quick-status reply from retry recovery; native calls, retries and return behavior remain unchanged. The pinned native smoke retains at most 64 attempt observations and separately retains confirmation and dropped counts. Native stage and hash counts remain unmeasured, and no production latency improvement is claimed. Baselines and comparison use the selected AIRK and bookbuilder corpora with read-only source roots and isolated derived state.

Candidate preparation passed local Windows formatting, all-target/all-feature Clippy, all-feature workspace tests (1,484 passing executions, zero failures, 17 declared ignores), the extension suite (438 passed, zero failed, 15 skipped), version/script and repository checks. Both freshly compiled debug executables report 1.8.0. These are preparation gates, not performance measurements or sealed lightweight release-pair qualification. The [execution ledger](../optimizations.md#execution-ledger) records scope, review and remaining gates. Historical test counts in the 1.7.6 release record qualify that release only. Installed-editor, Linux/macOS and release artifact qualification must be recorded where actually observed; publication requires separate authorization and successful release workflows.


F01c adds an opt-in [isolated real-corpus measurement runner](../ci-and-builds.md#isolated-real-corpus-measurements). It verifies an independently approved lightweight release pair, keeps derived state outside both read-only source roots, preserves exact first status observations and timed failures, and separates indexing, sessions, retained-index reopen and unchanged-source reconcile. Reports expose aggregate measurements and opaque identities only. The default is one sample; comparison campaigns explicitly request 30. Local runner tests passed 42 with one declared skip; the full Python suite passed 267 with six skips. Two focused native status smokes passed against the fresh approved Windows release pair. These results establish no production optimization.

The measurement report separates workflow completion from observed probe outcomes, distinguishes a budget exhausted before submission from uncertain transport failure, and records cleanup stages without erasing failures after a forced reap. Original-fixture diagnosis observed that durable semantic-ready coverage can precede embedding-helper admission after service restart; this remains a native startup finding.

The first real-corpus baseline completed AIRK's 30 running-service and 30 reopen sessions, after 43 minutes 9 seconds to full semantic readiness. Bookbuilder's source index succeeded, but semantic work remained partial when its one-hour budget expired; later session/reopen phases were not reached. The report also retained a cleanup warning, followed by independent confirmation that owned test processes/state were gone and both source trees were unchanged. The [execution ledger](../optimizations.md#f01c-named-corpus-observations-october-31-utc) records measurements, routes, failed and unmeasured cases. These baseline failures remain open optimization/qualification work, not passing performance results.

Early F08(a/b) publishes authenticated service health before optional management observations finish, keeping service connection separate from index/helper readiness. First or changed service identity hides unconfirmed registry rows, and detailed-status replies are fenced by runtime, service, registry, project, trust and panel identity. Search delivers its full successful result once through the retained session notification and returns a small correlated completion acknowledgment. Native/MCP result values and schemas are unchanged. Visibility-aware polling and scalar status adoption remain later F08 work. Validation and review for this phase are recorded in the execution ledger; installed-editor latency comparisons remain unmeasured.

The F08(a/b) local extension gate passed compile/catalog parity, 88 focused tests and the full suite: 454 passed, zero failed, 15 declared environment/platform skips (469 total). Repository, version, documentation-classifier, instruction-parity and whitespace checks passed. These host/controller tests verify publication ordering and single delivery; they do not measure installed-editor speed or qualify native changes.

F02 reduces response preparation while retaining the existing wire contracts: scalar status shares decoded collection metadata within one authorized read, file inventory budgets use exact JSON string sizes without temporary serialization buffers, help sizing borrows its growing text, and immutable tool catalogs are built once per process. Dynamic scope and caller-supplied catalogs remain independently checked. Validation is recorded in the execution ledger; no native latency improvement is yet measured.

F02's focused native gate passed 28 outer tests. Formatting, workspace all-target/all-feature Clippy and the complete all-feature workspace test suite passed: 1,478 outer passes plus 13 reported child passes, zero failures, 17 declared ignores. The full extension/catalog gate passed 454 tests, with zero failures and 15 declared skips. Documentation checks and separate complete-diff/evidence review passed. Windows results do not qualify other platforms or the later startup/storage changes.
