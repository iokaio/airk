# Shared embedding runtime contract, protocol 1

This is the opt-in native service pool. The default extension/runtime packaging is still 1.3.2; the 1.4 cutover, resource policies and platform qualification remain in progress.

The service supervisor starts one verified sibling `airk-embed pool` process when starting its first project worker. Starting that process does not load MiniLM. The separate feature-minimal `airk` executable has no ONNX inference or transformer-tokenizer dependency. A paired version/platform/digest receipt selects the helper; no shell or executable PATH lookup is involved. Missing or failed pool startup leaves the project with lexical retrieval and an explicit unavailable embedding adapter.

Private service/helper pipes carry pool identity, scoped credentials, revocation and content-free observations. Project workers communicate with the helper's separate authenticated native endpoint. Model inputs, vectors and query text bypass the service. The helper opens verified model/tokenizer assets only; it cannot install/extract assets, publish collection evidence or run project management. Offline asset extraction remains an explicit separate helper invocation under the kernel's existing installation/quota contract.

The initial limits are four worker credentials, eight native connection slots, eight queued inference/control items, eight queued requests per project adapter, 64 routed model/tokenizer sessions, one loaded inference model and one separate calibration tokenizer. Authenticated requests are at most 4 MiB; setup/control frames remain at most 64 KiB. The adapter waits at most 120 seconds for a result. One helper execution thread serializes inference, passes at most two embedding workers to the existing library, and caps the supplied working-memory allowance at 512 MiB. Library internal-thread qualification and observed process-memory admission remain release work; that byte allowance is not an OS memory limit. Existing verified asset-size bounds also apply.

Every model opening verifies the requesting project's assets without compiling a redundant compatible inference session. The complete cache pipeline descriptor, including runtime/provenance contracts, selects reuse. A shared weight digest alone cannot alias a different pipeline. Retained asset verification takes an object lease without opening the index database; a retained-model cache keeps that lease until its actual model handle is dropped, including after a worker timeout. Incompatible state is dropped before loading its replacement. Interleaved requests select their own model binding; retained inputs and original-source provenance remain the kernel's revision-bound responsibility. Existing per-root/per-collection model files are preserved; shared global model-file installation remains part of the storage/deployment cutover.

The capability binds the service, pool, project registration and worker identities and is consumed once during connection setup. Its five-minute admission horizon is renewed every thirty seconds over private supervisor control while the same worker remains live. Expired, revoked or foreign ownership cannot be revived by renewal. Renewal preserves existing concurrency/memory charges and does not reset client authorization or idle retirement. The service distributes it only over private child control after project ownership is established. Native peer checks apply to both sides. Each request/result additionally binds project, worker, model-session nonce, request nonce and the digest of its serialized operation. The adapter verifies the entire result envelope before returning vectors or token counts. Credentials and input text are absent from diagnostics and command arguments.

Closing/revoking a worker prevents new admission and releases its routing metadata. Liveness witnesses also retire disconnected session records when a best-effort close notification cannot enter a full queue. Idle compatible model state is retired after sixty seconds with no sessions. Cancellation/disconnect does not free the execution thread while native inference still runs. A result goes only to its waiting scoped request, or is discarded. A failed project adapter does not terminate another project's inference or silently launch a standalone fallback.

The helper retains its own process-lifetime OS lease. On service restart, predecessor project **and inference** ownership must drain before any new resource allocation. This covers inference that outlives the last project process briefly. Normal shutdown requests drain and then terminates/reaps the helper after a bounded grace period. Pool failure affects embedding availability; committed lexical evidence and independent service health remain usable. Explicit `embedding_status` management returns process identity and bounded load/reuse/session counts without opening a collection database.

Windows validation uses [the native pool smoke](../scripts/check-service-pool.py) with a separately built immutable runtime pair and blocked proxy settings. Two original projects provision MiniLM offline, run supervised index jobs, share exactly one loaded MiniLM session and return hybrid citations through real stdio MCP bridges. Terminating that private fixture's helper preserves both projects' lexical retrieval, service health and original bytes. Native helper unit tests cover compatible reuse, foreign asset rejection, full-pipeline identity despite equal legacy weight digests, and interleaved incompatible vectors. Native control/ownership regressions also run without the helper on Windows and non-root Linux. Linux/Mac pooled-MiniLM and installed-platform qualification remain outstanding.

Renewal validation: eight broker-policy tests passed on Windows, including active-charge preservation and expired/draining rejection. Six real native process regressions passed on Windows and non-root Debian 12 x64, including the private worker renewal acknowledgement and foreign-generation rejection. The updated Windows development-pair MiniLM smoke also passed; it now compares original source bytes exactly.

The development pair builder now records `airk-build.json` with source-file fingerprint, Rust identity, profile and paired executable digests. It rejects source changes between the separate builds before publishing its staging directory. This is a reproducibility/provenance receipt, not publisher authentication or installed-platform qualification.
