# Shared embedding runtime contract, protocol 1

This is the native inference pool used by the default 1.4.0 extension/CLI service. Resource and platform qualification remain tracked separately from implemented behavior. Inactive cleanup owners receive no pool access and do not start the helper.

The service supervisor starts one verified sibling `airk-embed pool` process after admitting its first project worker. Starting that process does not load MiniLM. The separate feature-minimal `airk` executable has no ONNX inference or transformer-tokenizer dependency. A paired version/platform/digest receipt selects the helper; no shell or executable PATH lookup is involved. Missing or failed pool startup leaves lexical retrieval available. Worker activation and later capability updates perform no helper connection I/O.

Private service/helper pipes carry pool identity, scoped credentials, revocation and content-free observations. Project workers communicate with the helper's separate authenticated native endpoint. Model inputs, vectors and query text bypass the service. The helper opens verified model/tokenizer assets and handles explicit bounded offline model provisioning. It cannot publish collection evidence or run project management. Model setup transfers only a selected local path or bundled-setup request and an exact returned asset reference; model bytes never cross the service broker. Ordinary MCP reads and source scans never provision assets.

The initial limits are 32 worker credentials, 64 native connection slots, eight queued inference/control items, eight queued requests per project adapter, 64 routed model/tokenizer sessions, one loaded inference model and one separate calibration tokenizer. Authenticated requests are at most 4 MiB; setup/control frames remain at most 64 KiB. The adapter waits at most 120 seconds for a result. One helper execution thread serializes inference, passes the service-configured 1–4 embedding batch workers to the existing library, and caps the supplied working-memory allowance at 512 MiB. Tract math runs with an explicit single-thread executor inside each bounded batch worker. [Observed service-wide RSS admission](service-resources.md) is implemented; workload qualification remains open, and that byte allowance is not an OS memory limit. Existing verified asset-size bounds also apply.

The helper installs one immutable asset set under `<control>/model-files-1.4/sets/<digest>`. Bundled setup streams embedded bytes directly to quota-admitted files without a temporary extraction directory or collection-local copy. Main and helper compile identical canonical catalog metadata. Custom setup verifies an explicitly selected read-only directory and captures its exact bytes into the same global store. Per-collection policy can retain a custom reference independently of the runtime's bundled default. A durable `model_setup` job installs the bundled default; trusted console/CLI model configuration uses guarded native jobs. The public 1.4 adapter has no direct-store model fallback.

Published model references contain exact asset hashes, sizes, pipeline identity and a runtime scope digest, with no configurable global filesystem locator. The native worker binds its trusted control root, and retains that binding through selected snapshots, journal recovery and replacement builds. Foreign-runtime references and collection-local fallback are rejected. Publication verifies installed receipts and small model metadata; it does not claim that saved readiness proves current weight availability. Actual helper model opening and explicit full asset verification hash the actual weights. Source setup reads only metadata and constructs a lazy direct helper session; inference opens on the first semantic request, including when a workspace build unifies local-inference features. Before setup, vector status reports pending reindex/unavailable semantic coverage and lexical evidence can publish. After setup, the next index binds the model and queues semantic work. Missing helper/inference failures remain explicit and do not remove committed lexical evidence.

Every inference opening verifies installed assets before reusing a compatible session. The complete pipeline descriptor, including runtime/provenance contracts, selects reuse; a shared weight digest alone cannot alias a different pipeline. Existing retained-input development adapters take a temporary collection object pin while capturing into the same shared store, then release it. Sessions and the loaded model pin shared files until their actual handles drop, including after a worker timeout. This lets an old collection incarnation retire while compatible inference stays loaded. Incompatible state is dropped before loading its replacement; repeated bundled setup preserves an already loaded compatible model. Interleaved requests select their own binding. Original-source provenance remains the kernel's revision-bound responsibility.

The shared file adapter has a separate 1 GiB disk allowance and at most sixteen sets/staging directories. Copies charge before writing, verify streamed sizes and hashes, sync, then rename into an immutable receipt-bound directory. Exact installed receipts and bundled-default pointers support bounded interrupted-write resumption. Installed sets persist across idle retirement and helper restart, even with no active session. Cache retirement handles only uninstalled transient sets, after exact verification and no pins; installed-set pressure fails admission instead of deleting inputs. Unknown, modified, linked or oversized state is preserved and reported. The final pin retains OS ownership even if its cache adapter drops. Existing legacy provisioned/retained assets remain untouched. Transformer calibration inputs now use the same global owner and disk allowance, as described below; usage ledgers remain per collection.

The capability binds the service, pool, project registration and worker identities and is consumed once during connection setup. Its five-minute admission horizon is renewed every thirty seconds over private supervisor control while the same worker remains live. Expired, revoked or foreign ownership cannot be revived by renewal. Renewal preserves existing concurrency/memory charges and does not reset client authorization or idle retirement. The service distributes it only over private child control after project ownership is established. Native peer checks apply to both sides. Each request/result additionally binds project, worker, model-session nonce, request nonce and the digest of its serialized operation. The adapter verifies the entire result envelope before returning vectors or token counts. Credentials and input text are absent from diagnostics and command arguments.

Closing/revoking a worker prevents new admission and releases its routing metadata. A separate bounded 64-session retirement set preserves closes when the eight-item client queue is full; queued operations cannot reopen a session retired before execution. An overflow fails the connection closed. Liveness witnesses retire records after transport loss. Idle compatible model state is retired after sixty seconds with no sessions. Cancellation/disconnect does not free the execution thread while native inference still runs. A result goes only to its waiting scoped request, or is discarded. A failed project adapter does not terminate another project's inference or silently launch a standalone fallback.

The helper retains its own process-lifetime OS lease. On service restart, predecessor project **and inference** ownership must drain before any new resource allocation. This covers inference that outlives the last project process briefly. Normal shutdown requests drain and then terminates/reaps the helper after a bounded grace period. Pool failure affects embedding availability; committed lexical evidence and independent service health remain usable. Explicit `embedding_status` management returns process identity and bounded cached load/reuse/session counts with observation age without opening a collection database or waiting behind native inference.

## Helper recovery

The supervisor confirms helper exit and drains its native containment before starting a replacement. It permits three helper start attempts per service lifetime, or per explicit `start_embedding` request, with bounded exponential delay. Exhaustion leaves lexical retrieval and service health available. A trusted `stop_embedding` request checks the exact opaque helper incarnation and suppresses automatic replacement; `start_embedding` accepts a request to resume bounded startup and reports `embedding_starting`, not readiness. Poll `embedding_status` for the observed replacement identity.

Existing project workers receive replacement capabilities over their private control pipes without changing their project identity or fencing generation. The direct connector checks service, worker, project, runtime and endpoint role before accepting an update. A retained model session reopens its original exact model descriptor on the replacement connection, validates the model handshake and retires its old session. Compatible projects still share one loaded model in each helper instance. Neither the broker nor the private rebind message carries model inputs or vectors.

An in-flight request that loses its connection fails explicitly; it is never replayed automatically. Only a later request can reconnect. Each grant has three connection attempts with backoff; a duplicate grant cannot reset exhaustion. Tokenizer/calibration sessions and provisioning requests do not replay live filesystem inputs after failure: retry the trusted operation explicitly. Already failed or canceled semantic jobs also need explicit retry; helper recovery does not rewrite their receipts or automatically resubmit them.
