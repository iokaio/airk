# Bounded service process diagnostics

The opt-in 1.4 service records content-free lifecycle diagnostics independently of project indexes and the service registry. The complete service console and default client cutover remain under implementation.

The native CLI owns logging; core defines typed records and pages. A 64-entry background queue keeps diagnostic file writes off control/health handlers. Four JSONL files hold at most 1 MiB each under the owned control namespace's `logs-1.4` directory. A root-bound ownership receipt and writer lock protect this separate ring. Unknown, oversized, redirected or hard-linked state disables writing and remains preserved. Logging failure does not disable health, retrieval or shutdown.

Records contain schema, service instance, observation time, an enumerated lifecycle kind, optional project/job digests and a count. They never contain source/query text, raw subprocess stderr, exception strings, paths, credentials or client prompts. Service start/stop and requested/idle/signal exit boundaries, control failures/capacity, metadata unavailability and supervised process failures are observable. These records supplement the [transactional event ledger](service-events.md); they do not replace its exact paging or job receipts.

Health reports logging availability, dropped records and write failures. Queue loss is accumulated and, while writing remains available, emitted as a typed loss record. Shutdown flushes accepted records before the service ownership lock is released. This is best-effort bounded diagnostics, not a power-loss audit log. An absent stop record is not proof of current liveness or successful work.

`airk service logs --runtime-dir <control-directory> [--limit 1..32] [--format json|text]` reads cached diagnostics without starting the service or opening a project. The authenticated `logs` control request provides the same bounded page even if registry initialization failed. `runtime diagnose --install-dir <installation>` also includes recent logs, or an explicit unavailable flag, without requiring a healthy selected runtime.

Export reads at most 64 KiB and returns at most 32 typed records/48 KiB. It reports malformed records and a limited/incomplete tail. An unfinished record is never exported; a later writer preserves its bytes and delimits them before appending. Cached records are not index freshness or verification evidence. Log reads during rotation are best effort and can require a refresh.

The current opt-in ring lives inside the already protected control directory. Cutover must bind the native global log location to installation/state ownership and protect it against registered sources before writing there; the reported native log-location defaults are not yet used by this development ring. Logs and project data remain writable state outside immutable payloads and are preserved by runtime removal.
