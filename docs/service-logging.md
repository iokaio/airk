# Bounded service diagnostics

Version 1.5.10 adds a separate local raw job-error ring. Management › Logs offers **Open raw diagnostic log** and **Save raw diagnostic log…**, and failed project/repair panels link directly to it. `airk service logs --runtime-dir <control-directory> --raw` reads this ring without starting the service. It captures the exception chain at the worker's failure boundary, with exact project/job/grant/worker identities and operation. Deferred failed attempts are retained too. Each chain is limited to 8 KiB/32 causes with an explicit truncation flag; four 1 MiB files bound retained storage. An empty ring explicitly means no raw records were retained; earlier generic failures cannot be reconstructed.

Raw records can contain paths and exception values. They stay local and are excluded from the metadata-only diagnostic report, ordinary summary ring and public MCP responses. Review them before sharing. Their protected native ring is named `job-errors-1`, independently of the AIRK release version. Abrupt process death before reporting an error can still leave no exception chain; this is not a complete crash dump or subprocess stderr transcript.

Version 1.5.9 also records `job_failed` when the supervisor observes a failed job finish, even if its worker stays alive. The event contains the exact project, job ID and optional safe `code` from the durable receipt. Index preparation/discovery codes retain the observed stage and recognized SQLite, OS, metadata or inventory cause. Unknown causes stay unspecified; raw exception text is excluded. This corrects a gap in process-only logging and does not reconstruct failures from earlier versions.

The 1.5.3 candidate adds project-level `source_traversal_unavailable` and `source_traversal_recovered` transitions. Repeated directory-plan retries do not append duplicate failures; the remembered availability state survives watcher/service restarts for the same root configuration. Current bounded path details appear in Management › Projects and Indexing, separately from this path-free log. An incomplete root walk cannot clear its earlier unreadable paths. See [source watching](service-source-watching.md).

The default 1.4.0 native service records content-free lifecycle diagnostics independently of project indexes and the service registry. The service console exposes bounded diagnostics while connected or stopped; final qualification remains tracked in the completion checklist.

The native CLI owns logging; core defines typed records and pages. A 64-entry background queue keeps diagnostic file writes off control/health handlers. Four JSONL files hold at most 1 MiB each in `logs-1.4` beneath the installation's pinned log directory. A root-bound ownership receipt and writer lock protect this separate ring. Unknown, oversized, redirected or hard-linked state disables writing and remains preserved. Logging failure does not disable health, retrieval or shutdown.

Records contain schema, service instance, observation time, an enumerated kind, optional project/job digests, a count and an optional safe failure code. Codes contain at most 128 lowercase letters, digits or underscores. Records never contain source/query text, raw subprocess stderr, exception strings, paths, credentials or client prompts. Service start/stop and requested/idle/signal exit boundaries, control failures/capacity, metadata unavailability, failed jobs and supervised process failures are observable. These records supplement the [transactional event ledger](service-events.md); they do not replace its exact paging or job receipts.

Health reports logging availability, dropped records and write failures. Queue loss is accumulated and, while writing remains available, emitted as a typed loss record. Shutdown flushes accepted records before the service ownership lock is released. This is best-effort bounded diagnostics, not a power-loss audit log. An absent stop record is not proof of current liveness or successful work.

`airk service logs --runtime-dir <control-directory> [--limit 1..32] [--format json|text]` reads cached diagnostics without starting the service or opening a project. The authenticated `logs` control request provides the same bounded page even if registry initialization failed. `runtime diagnose --install-dir <installation>` also includes recent logs, or an explicit unavailable flag, without requiring a healthy selected runtime.

The recent view reads at most 64 KiB and returns at most 32 typed records/48 KiB. Local CLI `--all` exports the complete retained ring, with at most 4 MiB input and 8 MiB serialized output; it does not enlarge the service IPC response. Both report malformed records and an incomplete tail. An unfinished record is never exported; a later writer preserves its bytes and delimits them before appending. Cached records are not index freshness or verification evidence. Log reads during rotation are best effort and can require a refresh.

Fresh installed layouts now pin the log directory in matching install/state ownership receipts. Native installations use the account-bound log default reported by `runtime location`; custom state layouts use their state directory's `logs` child. This includes the separate native macOS Logs location. `runtime diagnose` exposes the saved layout binding. Logging and cached export resolve that same binding, preserving the root-bound receipt, finite ring and independent health telemetry. Missing, changed or redirected binding metadata makes logging unavailable instead of creating a ring in another location.

The source-isolation ledger protects an external log path alongside installation/state roots and retains proven private paths if a receipt later disappears. Raw development namespaces and explicit adoption of an existing development control directory retain their original protected location; they do not silently relocate a ring or start writing into a previously registered source tree. This is development-state handling, not support for opening released 1.3 collection stores. Logs and project data remain writable state outside immutable payloads and are preserved by runtime removal.
