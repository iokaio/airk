# Cached project inspection for the service console

This is an opt-in native development path for the [1.4 service plan](airkservice-architecture.md). The default extension remains on 1.3.2 until cutover. Inspection and maintenance-plan UI integration are in progress.

An explicit trusted `inspect` job selects and pins the registered project's current incarnation, observes its readable revision and saved-settings digest, and records bounded discovery/semantic summaries. Root-location availability is separate from retained-index availability. A missing source can therefore report an unavailable location alongside a readable committed index. Location checks do not establish permission to read every source file or current extraction coverage.

Inspection captures no source files, installs no model, performs no rebuild or retained-file retirement, and exposes no new MCP capability. Summary failures use a fixed enum; raw exceptions, paths, source passages, query text and model inputs are excluded. The snapshot has an 8 KiB bound. Its durable per-project observation has a 9 KiB bound inside the existing finite service ledger.

Only the current lease-bearing generation may record an observation for its exact running `inspect` job. Cached observations survive job receipt rotation and service restart. The `inspection` management read opens only the ledger and explicitly returns `cached: true`; it does not start a worker or refresh the index. The response retains observation time and originating worker identity and reports the project's current fencing generation, so an older generation remains identifiable. Absence is unobserved state, not health.

Pause continues to hold source-changing and ordinary maintenance jobs. An explicit read-only inspection can run for an idle paused project without resuming those jobs. A running job still owns the project's sole execution slot; inspection waits rather than running alongside it or canceling it. Paused active work can therefore keep inspection pending. The console/planner must disclose that wait or skip it under its finite planning policy.

The maintenance guard binds the project, incarnation, exact publication, saved settings, index state and captured recovery requirement. It excludes observation timestamps and changing display counters. A settings change invalidates it even before another publication. Execution must recapture and compare the guard and separately recheck source permissions; a cached guard does not authorize mutation. Root availability changes alone do not manufacture a new index revision.

Ready inspection state describes a readable named index at the observation time. It does not establish complete retained-object verification, source freshness, complete language understanding or vector readiness. Those remain independent observations and explicit verification work. Disk estimates/reservations, plan approval, bulk execution and console presentation are still being integrated.
