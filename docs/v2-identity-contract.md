## Canonical identities

Incarnation, artifact handle, symbol key and document key are separate 128-bit types, serialized as exactly 32 lowercase hexadecimal characters. Digests are exactly 64 lowercase hexadecimal characters. Parsers reject uppercase, abbreviated and malformed encodings. Kernel supplies allocation bytes; core never accesses randomness, files or clocks. A syntactically valid incarnation alone is not proof of collection ownership. Kernel must generate an independent random incarnation for the first successful v2 publication and bind it to the collection/root.

Exact tokens serialize as `airk-r1:<incarnation>:<generation>:<revision>`. Generation is canonical unsigned decimal (`0` allowed, no leading zeros or plus sign), bounded by `u64`. Token length is at most 126 bytes. `validate_against` rejects a foreign incarnation, future generation and equal-generation/different-revision fork. Earlier-generation tokens still need retained ancestry verification; this check deliberately cannot establish it. Checked sequence increment rejects overflow.

Artifact, symbol and document handles have distinct Rust types despite identical string encoding. They are collection-local assigned identities; native syntax IDs and imported producer IDs are not converted into these handles merely by hashing names or paths.

## Digest framing and publication order

`framed_digest(domain, fields)` hashes the ASCII bytes `AIRK-DIGEST-1` followed by a zero byte, then the domain followed by each field. Every domain/field has an unsigned 64-bit big-endian byte-length prefix. No delimiter escaping or concatenated ambiguous fields are permitted. Callers own canonical field encoding; the helper does not promise arbitrary JSON values have canonical ordering.

`revision_digest(retrieval_specification, canonical_inventory)` uses domain `publication-revision/1` and those two exact byte fields. Fixed vector: specification UTF-8 `engine1`, inventory UTF-8 `{}` gives `7dd5054a34b9170137a2d4c629737613f1d01f955f527304ee5d1e93cc1b2df9`. This vector was independently computed with .NET SHA256 and is asserted in the Rust test.

The final inventory binds lineage/configuration/payload digests but excludes its own revision and final manifest/catalog checksums. `PublicationObservation` contains generation, parent token, reason and observation time, never its own digest. Build inventory first, compute revision, build derived components, and finally checksum the manifest. `PublicationReceipt` binds exact token plus inventory/manifest digests. Only the root transaction or validated maintenance state can make a receipt authoritative. A receipt does not prove surviving intervening ancestry. Legacy revision verification continues to hash original legacy bytes with its original algorithm, never this new function or a reserialized snapshot.

## Bounded change primitives

File stamps independently track first/path/content/evidence generation; validation requires each changing stamp to be between first observation and target generation. Events preserve before/after path, source hash and profile, dimensions, cause and conservative continuity basis. Empty endpoint events allow revision-level invalidation. Event validation bounds dimension count, rejects duplicates, validates paths and rejects future events. It does not classify a missing path as a deletion.

`FileState` freezes artifact ID, four stamps, source/profile/payload/evidence digests and root/path binding. Payload digest is the content-addressed payload reference, without a filesystem path. `LineageEnvelope` freezes version/incarnation, current observation, independent coverage floors, retained publication headers, ordered events and resolver projection. Each older `RetainedPublicationHeader` keeps its exact token, parent token, observation timestamp and publication reason. The current observation remains digest-free. Aggregate admission includes one observation and five floor records in addition to every event/header/resolver, keeping all records within the shared limit. Parent sequence must be exactly one before its child, with exact token equality whenever that parent's header survives. Older headers are scoped, strictly ordered and unique by generation; events are strictly ordered by their pair key and must refer to the current observation or a retained header. First migration may have no v2 parent; a parentless entry cannot have earlier retained ancestry.

Keeping timestamps with older headers makes group age available after serialization and reopening. Publication sequence defines ordering even if clocks move backwards. `observed_age_seconds` uses saturating subtraction: a future timestamp relative to the supplied clock has zero observed age, never an underflow or an invented earlier order. Publication/maintenance performs conservative whole-group expiry, advances the affected coverage floors and retains a gap when budget constraints require it. Retaining an old event requires its header; a receipt alone is not an age/ancestry substitute.

`ChangeSubject` distinguishes a bounded global domain identifier, artifact ID, symbol key with artifact ID, and document key with artifact ID. Global domain identifiers use at most 128 ASCII letters/digits or `._/-`; global records have no file endpoints. Before/after `ChangeDetail` carries at most 14 typed dimension digests, optional intrinsic document/line location, optional complete region-location binding digest and complete provenance digest. These fields preserve body/signature/document/provenance changes without excerpts or display-string identity. Original embedded/notebook mapping details remain in separately bounded evidence reads; their digest binds that representation in the event. Every detail contributes to the shared serialized lineage budget, and typed subject distinctions survive serialization. Intrinsic locations have positive coordinates, ordered line ranges and bounded sheet names.

Resolver records bind an artifact and prior root/path/source/profile to an optional target. Only `ExactMove` has a target, and it requires unique-compatible-content basis, equal source/profile and a changed root/path. Terminal states distinguish observed deletion, removal from index, ambiguous and unknown. Similarity/equivalent candidates are not automatic resolver targets. Kernel must additionally prove alias eligibility, uniqueness, complete observation and cycle freedom before storing forwards; structural validation alone does not prove continuity. Endpoint/root strings are bounded; canonical filesystem-root validation belongs to kernel. Records contain no source excerpts.

Coverage records keep separate files, code, documents, ancestry and resolution floors. `complete_after` is an exclusive lower floor: the covered window is `(complete_after,target]`. Reasons distinguish unavailable baseline, expiry, overflow, unsupported detail, omission and purge. Kernel must still compute completeness for the requested baseline/filter; a numeric floor alone is insufficient proof.

Remembered selectors distinguish path, citation source hash, artifact, symbol and document identities. At most 64 total selectors and 32 KiB for the entire serialized selector array are admitted; each path/prefix is at most 4,096 UTF-8 bytes. Empty requests require `since`. Paths reject absolute/drive/backslash/NUL and dot traversal forms. These lexical checks do not replace root/alias scope validation or filesystem-boundary checks. Lineage admission counts events, ancestry and resolver/detail records together: 10,000 total and 16 MiB actual serialized bytes, with a 90-day age ceiling enforced by the publication/maintenance owner. Reserve room for gap/global records before admitting details.

`ChangeCursor` is an internal versioned payload binding exact target, optional baseline, canonical request digest and separate list positions. The request digest covers selectors in input order, filters, detail options and all query-shaping inputs. The `Changes` stage emits coalesced change records in deterministic `(generation,event_id)` order using `after_change` as an exclusive position; `None` starts that list. Each coalesced record's key is its final contributing event, with event IDs unique within each publication. Once exhausted, the cursor advances to `Validations`, preserving its change position and using `next_validation` as the next selector ordinal. Exactly one bounded validation record, including bounded candidates, corresponds to each remembered selector in request order. A page may finish changes and begin validations, with each list still returned separately. Changes-stage cursors require validation position zero. Validation-stage cursors require an unconsumed selector; completed responses emit no cursor. A record that cannot fit must return the bounded budget error rather than a non-progressing cursor.

Binding validation rejects changed target/filter/baseline, future change positions and out-of-range validation positions. Kernel owns opaque encoding, authenticity where needed, retained-target lookup and verifying that the change key exists and belongs to the requested window; this struct is not an exposed trusted cursor. Cursors hold no cross-request lease, and expiry must not silently select current evidence. This ordering supports change-only, validation-only and combined requests without using one position for independent lists.

## Neutral embedding cache contract

[embedding.rs](../crates/airk-core/src/embedding.rs) defines contract version 1 without inference or storage activation. `EmbeddingDescriptor` binds full immutable model assets, tokenizer assets/options, preprocessing, pooling, normalization and inference/runtime/options through independently supplied SHA256 digests, plus dimensions. Implementations must digest complete canonical settings and referenced bytes; a display name, file path or model name is insufficient. An absent stage still has an explicit digest for its versioned no-op specification. Descriptor identity uses fixed binary field ordering and domain `embedding-descriptor/1`.

`embedding_key` hashes the descriptor identity and exact model input bytes under `embedding-input/1`. Input means final chunk formatting/prefix/context bytes before tokenization, not merely source text or a source digest. Inputs are at most 4 MiB; dimensions are 1 through 2048, matching current retrieval ceilings. `CachedEmbedding` binds the key and vector checksum. Checksum domain `embedding-vector/1` hashes key plus IEEE754 f32 bits in big-endian order. Validation rejects wrong keys/versions/dimensions, nonfinite values, values beyond the existing retrieval magnitude bound of `1e10`, and changed vector checksums. JSON decoding has a 128 KiB pre-deserialization bound, then complete validation; adapters using another encoding must enforce an equivalent bounded read. Signed zero bits remain distinct; validation does not silently normalize vectors.

The `EmbeddingCache` trait supplies lookup/store; validated `lookup_embedding` and `store_embedding` helpers form the retrieval-facing path. Kernel passes a collection-scoped implementation, so retrieval never depends on store. Store owns quota, atomic writes, reader protection, corruption reporting and dependency GC. Cache miss is `None`; corruption is an error, never a stale hit or an authorization for remote inference. Tests use an original in-memory fixture to verify misses, exact reuse and corruption rejection; this is not a production memory cache. The existing `EmbeddingProvider` remains unchanged. Parser/inference counters, production persistence and real inference reuse remain phase 5 work.

Core continues to depend on no other AIRK crate. Existing snapshot fields and response envelopes are unchanged until phase 2 integration.

## Phase 3 implementation contract (D5)

Phase 3 activates bounded file observations and read APIs. Newly written lineage envelopes use version 2; readers accept versions 1 and 2. Version 2 endpoints retain an optional original collection citation path alongside the physical root and relative path. This preserves prefix filtering and remembered-path lookup after an alias is removed or rebound. Version 1 endpoints without the field remain readable; their citation can only be reconstructed when the pinned root map identifies it unambiguously. A remembered alias never authorizes forwarding to a different physical binding.

Completed scans carry authoritative disappearance reasons separately from truncated diagnostics. Same-path observations take precedence. Cross-path extraction reuse verifies source bytes and the full effective profile before loading a retained payload; it does not establish identity. Automatic file continuity requires a complete scan, one old and one new compatible occurrence, stable root bindings, observed disappearance and informative content. Copies, duplicates, empty/tiny content and boilerplate remain distinct handles or explicit candidates. Resolver chains compress to the current compatible endpoint; content/profile changes, terminal disappearance and retired roots stop forwarding.

Publication appends bounded metadata only: no excerpts or source history. File, resolution and ancestry coverage expire independently, by whole publication groups. Code and document detail remain explicitly unsupported until phase 5. Single-publication detail overflow retains bounded global invalidations and advances affected completeness floors. The current limits are 10,000 aggregate lineage records, 16 MiB encoded lineage and 90 days; reconciliation reserves space by limiting new file details/resolvers to 8,000 records and 12 MiB.

`changes`/`airk_changes` accepts an exact baseline and/or up to 64 remembered selectors. The kernel validates collection incarnation, sequence and known forks before answering. Retained ancestry proves a baseline; older missing ancestry produces `baseline_unavailable`, never an invented empty complete delta. Coalescing occurs over the entire window before pagination and preserves transient, reverted and intermediate-path observations. Cursors bind the exact target and all request inputs; each page leases that target without holding a cross-request lease. Retired targets return `cursor_expired`. A surviving receipt with missing representation is treated as corruption; cleanup-pending retirement without durable retirement proof remains an explicit phase-4 recovery integration case.

Changes pages admit 1–100 records and 1–65,536 record bytes, with at most 16 KiB additional framing. Optional candidates are bounded to eight and trimmed with `candidates_truncated` when necessary. An indivisible mandatory record that cannot fit returns a budget error. Scheduler freshness is observed separately and never verifies live sources or triggers indexing.

Conditional file-info/read/context/outline responses preserve existing payload fields and add `read`. V2 responses carry the exact pinned publication. Validators bind payload/evidence/profile identity, physical source location, operation parameters and rendered bounded payload, excluding the publication generation. Unrelated publications therefore preserve a validator; source, profile, mapping/provenance, selection or representation changes invalidate it. Matching `if_evidence` returns `not_modified` without payload. `known_hash` checks only source-byte identity. Exact live paths take precedence; moves require explicit `follow_moves` and complete compatible resolver evidence. Legacy ordinary reads remain available with no publication token or validator; conditional identity options require successful migration first.
