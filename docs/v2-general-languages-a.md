# General language adapters A

The `general-facts/1` adapters extract bounded written evidence. Native grammar facts use `airk-tree-sitter/<adapter>` with `Syntax` basis. Literal Elixir macro interpretations use `airk-language-structure/elixir` with `StructuralRule` basis. Neither form resolves referenced declarations, invokes a compiler, evaluates a macro or executes source code.

| Profile | Extraction shape | Limits of interpretation |
| --- | --- | --- |
| Dart (`.dart`) | Library/import/export/part directives; classes, mixins, extensions, enums, selected functions/methods/getters/setters and fields; selected call/cascade grammar nodes | No Flutter binding, inferred types, module loading or resolved cascade receivers. Anonymous extensions and complex declaration forms can lack a named fact. |
| Scala (`.scala`, `.sc`) | Packages and complete written imports/exports; classes, objects, traits, enums, functions, types, named givens, simple val/var bindings, extensions and selected calls | Original fixtures separately exercise braced syntax and Scala 3 indentation/enums. This is not dialect enforcement or compiler inference. Destructuring bindings and unnamed givens do not invent names; infix notation is not a complete call graph. |
| Elixir (`.ex`, `.exs`) | Literal module/function/macro heads, written arity and guards; alias/import/use/require candidates; selected written calls | Definitions are structural interpretations of ordinary call nodes. Quoted macro bodies are omitted and mark coverage partial. Arity counts written arguments, without expanding defaults or macros. No OTP/Phoenix behavior or module resolution. |
| Objective-C (`.m` with strong bounded marker evidence, or explicit policy) | Interfaces, implementations, protocols, categories, selector spellings, properties/imports, selected C calls and bracket messages with written receivers | `.m` is ambiguous and suffix alone must not select Objective-C. Message evidence retains original source, not a resolved method handle. Attributes, preprocessor conditions and runtime dispatch are not evaluated. |
| Objective-C++ (`.mm`) | Independently parsed Objective-C islands and disjoint clean C++ namespace/template/class/function/call constructs | Always partial. Both parses share one traversal allowance. C++ candidates overlapping Objective-C islands are omitted, including islands with errors. Error-containing Objective-C islands do not authorize recovered interior facts. General interleaving, templates within Objective-C declarations and compiler semantics are not claimed. |

Structured source parsing is bounded by 4 MiB (larger UTF-8 sources use [partial text-only extraction](ingestion-limits.md)), 500,000 visited nodes, 10,000 facts, bounded pending traversal storage, 4 MiB display detail and 16 MiB serialized evidence. Dual Objective-C++ parsing shares the node/fact allowances. Facts retain original UTF-8 byte spans and line positions; CRLF is not normalized during extraction. Comments and string contents do not become declarations or calls. Syntax errors remain visible as partial coverage; declarations recovered immediately before adjacent syntax errors are conservatively omitted.

Native named Dart, Scala and Objective-C declarations carry complete name fingerprints and owner-qualified identity evidence. Signature/body fingerprints are populated only when an exact grammar span is available. Hashing precedes display truncation and shares a 64 MiB work allowance. Documentation fingerprints remain unknown; an absent fingerprint is not proof of unchanged documentation. Truncated owner metadata prevents a fabricated complete qualified identity. Structural Elixir declarations do not receive native declaration keys. Objective-C++ can expose queryable observed keys, but partial coverage prevents an automatic declaration-continuity claim across edits.

Original repository fixtures exercise language-specific facts, comments/strings/errors, quotes, CRLF/Unicode, fact/source limits, disjoint Objective-C++ syntax and fingerprint changes beyond display limits. Kernel fixtures exercise retained source bytes, bounded fact/key queries, warm and rename parser avoidance, unrelated-file reuse under policy changes, and line-shift key preservation for qualified native declarations. Test execution receipts are recorded in the implementation ledger; this document does not assert unrun cross-platform or editor qualification.

Dependencies are pinned to Dart 0.2.0, Scala 0.25.1, Elixir 0.3.5 and Objective-C 3.0.2. Objective-C++ additionally uses the existing C++ 0.23.4 grammar. Dependency notices record exact licensing; the Objective-C crate's omitted license is supplied from its exact upstream revision. There is no additional language runtime requirement.
