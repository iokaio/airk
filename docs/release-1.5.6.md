# AIRK 1.5.6 development record

27 October 2026. Work on fix/management; not a publication record.

Management is consolidated into one project page with three common settings, contextual health/recovery, phase progress, published availability, durable native request outcomes and collapsed advanced sections. Existing route links open the appropriate section. Unknown totals and stale worker samples remain explicit. Storage cleanup stays separately previewed and approved.

The semantic-enable bug is corrected: enabling previously saved only the switch and could leave a publication without a model indefinitely. Model availability is now verified/provisioned first; failure preserves an existing disabled policy. Configuration completion requests source and semantic continuation. The regression failed against the old vectors branch and passes with the fix.

A second stale-status bug is corrected: successful source/model/semantic work now refreshes the fenced cached inspection. Refreshing Management no longer depends on a separately requested Inspect job to see published changes.

Initial registration now saves setup and watching in the native transaction, instead of depending on subsequent extension enqueue calls. Setup survives client/service restart, duplicate active registration preserves settings, and model failure leaves text indexing scheduled. Removed projects clear pending setup and retain the guarded cleanup/re-registration barrier.

See [index management](index-management.md) and the [extension guide](vscode-extension.md). Cargo, npm and extension manifests are synchronized at 1.5.6; this patch does not change the service-1.4 data namespace or require a blanket rebuild.

Automatic recovery now belongs to the native service. Eligible worker/helper failures use persisted, bounded retries; source and storage waits retain the original accepted job and resume after their prerequisite returns. Typed resource waits and pause do not count as indexing stalls. Recovery preserves source bytes, registered identities and usable published evidence. Exhausted startup circuits settle newly queued work instead of leaving it pending indefinitely.

Common search-mode and evidence-detail preferences are accepted before native inspection and continue with the editor closed. Management distinguishes the requested setting from the saved setting while configuration is queued. Lost acknowledgements are reconciled through read-only request lookup; missing receipts never authorize a replacement mutation. The registry transactionally migrates format 7 to 8 without changing the data namespace. See [automatic indexing recovery](index-self-healing.md); the [original proposal](index-self-healing-proposal.md) is retained as a dated design record. Optional artifact quarantine remains deferred.
