# Architecture

AIRK is an independent local indexing/retrieval kernel. Source workspaces are authoritative; all index state is derived. It does not reason, generate answers, manage agents, route model calls or require an external database.

The [October 17 release summary](releases-2026-10-17.md) covers the 1.1.0–1.1.2 changes and upgrade behavior. This page describes the resulting component boundaries; release publication and workload qualification are recorded separately.

~~~mermaid
flowchart LR
  W[Workspace files] --> I[Native ingestion and format facts]
  I --> K[Collection-scoped kernel]
  K --> S[Collection disk state]
  S --> R[Tantivy lexical and SQLite fact retrieval]
  V[Default local embeddings and disk-backed DiskANN] --> R
  C[CLI or optional extension] --> K
  A[Coding agent] --> M[Read-only stdio MCP]
  M --> K
  R --> K
  K --> E[Bounded evidence and original locations]
~~~

## Dependency boundaries

| Crate | Responsibility | AIRK dependencies |
|---|---|---|
| airk-core | Artifact/query/fact/citation contracts; storage and embedding traits | None |
| airk-ingest | Ignore-aware discovery, hashing, native grammars, document extraction/chunking | core |
| airk-store | Content-addressed sources/extractions, compact catalogs, SQLite facts/relationships, usage ledgers, durable intents, locks, quotas, relocation and retention | core |
| airk-retrieval | Persistent Tantivy, local word-vector/ONNX inference, DiskANN file provider, rank fusion and response budgets | core |
| airk-kernel | Collection-scoped publication, retrieval, coverage, scheduling, usage and maintenance services | core, ingest, store, retrieval |
| airk-mcp | Schemas, official SDK transport and result conversion | core, kernel |
| airk-cli | Commands, native client setup and lifecycle | core, kernel, mcp |

Core must remain free of parser, filesystem, inference and transport implementations. Adapters call kernel services rather than bypassing validation or collection scope. MemoryStore is an available in-memory snapshot adapter; the CLI kernel uses FileStore and immutable retrieval components.

The isolated [single-current-index foundation](current-index-foundation.md) adds neutral authenticated graph contracts in core, a mutable DiskANN provider in retrieval and owner-scoped journal, gate and quota support in store. It qualifies incremental graph updates and process-death recovery. Normal indexing and request routing still use the generation publication described below. S8 replaces that runtime and its historical APIs at a rebuild-only boundary, with no old-format reader or migration.

The [v2 publication contract](v2-publication-contract.md) defines the current authoritative inventory, path-free native payloads, exact revision tokens, receipt-bound publication. Bounded file/code/document changes, remembered-evidence validation and conditional reads use the [identity and change contract](v2-identity-contract.md). Obsolete derived formats require an explicit rebuild; no compatibility reader or migration is used by the kernel. The [execution ledger](architecture-v2-ledger.md) distinguishes implemented behavior from completed qualification gates.

## Current indexing and retrieval

A configured owner root/collection selects one catalog directory. Explicit additional source roots receive unique citation aliases retained in the published inventory. Indexing acquires a collection writer lock, walks eligible sources across those roots under shared budgets, reads capped bytes and computes SHA-256 identities. Effective profile selection precedes verified extraction reuse. Protected reads, hashing, selection and reuse remain on the coordinator; eligible captured inputs can enter a bounded pool for pure extraction. Workers return validated path-free payloads, and coordinator binding/retention callbacks preserve captured discovery order. Each source and payload is retained as a content-addressed object; the scanner keeps compact metadata and at most the bounded in-flight batch. Full reindexing bypasses reuse. Removed, excluded or unsupported sources disappear from the next successful inventory.

Collection extraction policies version 3 can select Essential, Balanced or Detailed evidence. Older saved policies retain Detailed semantics; new collections default to Balanced. Reduced levels bind their selection into effective extraction profiles and publish the selected level in the immutable inventory. Qualified common grammar adapters avoid rich facts/fingerprints in Essential and generic call evidence in Balanced while retaining recognized framework cues. Qualified Essential prose paths collect heading context without factual classification; Detailed continuity uses a unit-only collector. Specialized adapters retain full extraction followed by selection until equivalent output is qualified. Fact and syntax references are normalized in separate namespaces before continuity generation and persistence; chunks keep original locations. Native structured-query responses disclose the published selection and deliberate omissions. Explicit imported analysis and historical retention remain separate. SQLite fact/relationship secondary indexes are built after bulk insertion within the same transaction. Current catalogs use normalized physical rows with integer file/producer references and binary source hashes; SQL views reconstruct the bounded fact/relationship read interface. Obsolete catalogs require rebuilding.

Native grammar profiles produce selected definitions/imports and structured keys. Markdown, delimited data, XML/SVG and OOXML have explicit format adapters. Published chunks follow declaration/document boundaries where available, with an 8 KiB and 160-line ceiling and exact coverage of intervening text. UTF-8 characters and CRLF pairs remain intact. Document chunks preserve page, paragraph, table, worksheet or slide locations; their line spans refer to normalized extracted text, not source-file lines. DOCX tables and XLSX stored cells retain structured row/cell facts. [The format matrix](formats.md) states exact extraction and formula/date limits.

Indexing streams one retained artifact at a time into private Tantivy, DiskANN when local embeddings are enabled and ready, and exact-fact SQLite components. A collection-bound vector policy defaults to enabled; the panel saves opt-outs under the writer lock and requests indexing. Default CLI/MCP searches use hybrid retrieval unless opted out. The trusted extension prepares pinned model assets before indexing; native/MCP reads never download. Missing vector readiness is reported explicitly, not converted to a lexical default. Each immutable generation contains its compact inventory, normalized facts/relationships and optional bound producer analysis. Once components are synced and reopened, their directory is published and a small root SQLite WAL transaction commits the selected component header and inventory digest. Component IDs hash the compact inventory, engine specification and optional model digest; artifact references transitively bind text, facts and locations. A model change advances the generation even without a source edit. Discovery/read/corpus-limit, quota, component-build and transaction failures retain the prior published revision. Unsupported extraction is reported per file and omitted; diagnostic details are bounded. Full synchronous commits and bounded busy waits are configured; power-loss and network-filesystem durability remain unqualified.

Preparation journals receipt-bound ownership before the immutable rename. Dead-reservation recovery preserves committed receipts; uncommitted components are authenticated against their receipt and expected head and require an exclusive reader lease before detachment into owned staging. Unknown state, changed heads, corruption and live readers prevent reclamation. This permits safe same-revision retries after interrupted publication. See [recovery](operations.md#recovery).

Obsolete receipt-backed indexes and bounded SQLite coordination state are identified before catalog hydration. The current boundary uses `native-facts/9`, native adapter suffix `/sizing-1/detail-2`, unchanged chunk strategy 3 and retrieval engine markers `generation-9`/`detail-projection-2`. Standalone payload contract 1 and mapped composite contract 2 are current representations, not compatibility readers for old indexes. `airk index --full` excludes readers, records a durable reset intent, removes managed derived state and rebuilds with a fresh incarnation. Source files and saved root/extraction/vector/scan/quota configuration are preserved; obsolete history settings and checkpoints are discarded. A failed reset remains unavailable until an explicit retry completes. JSON-only state without bounded ownership metadata requires explicit removal of that derived state; it is never interpreted as current evidence. Unsupported/corrupt coordination metadata fails closed. Tests cover revision pinning, rollback, interrupted reset, digest verification, lazy file reads and retained-object garbage collection. [Storage contracts](collections.md) give layout, caps and recovery details.

New lexical searches read persistent Tantivy postings and stored citations, matching all normalized terms with path filters and deterministic path/chunk ordering. Search and status select the small committed component header without loading retained source bytes. File lists and fact discovery expose revision/filter-bound keyset cursors, with explicit expiry on current publication changes and serialized-record budgeting. Compact outlines retain names, kinds, original locations, spans and durable keys; rich detail remains available through fact reads. [Discovery contracts](discovery.md) define oversized-record and retained-outline behavior. File lists and coverage read compact metadata; file/context services pin a catalog and deserialize only the requested artifact. Exact-fact queries begin a read transaction before selecting the active revision and acquire that generation's lease before opening its immutable SQLite indexes. Rich code evidence records scope/signature/written types and selected framework cues. Syntax targets remain candidates; optional hash-bound SCIP producer assertions are distinct from AIRK's textual references and native parsing. The SCIP adapter explicitly requires a single owner root until its producer contract supports aliased source roots.

Immutable catalog publication can copy native rows from an authenticated, leased prior catalog when the entire per-file inventory record is unchanged. Changed inputs and imported producer assertions are constructed afresh. File and producer IDs are private to each catalog and remapped during reuse; they never replace public evidence identities. The base is re-authenticated after copying, and publication still uses a private quota-capped database and atomic pointer commit. This avoids reloading/rebinding unchanged fact payloads but still writes a new catalog and builds its indexes; lexical generation construction remains separate.

A process-local cache reuses successful inventory/SQLite semantic validation for at most sixteen revision/path entries within a 512 KiB key budget. It holds no generation leases, database connections or decoded corpus inventory. Every exact query still authenticates the current manifest and hashes every component before using that result; same-size edits, replacements, unexpected sidecars and different receipts cannot be accepted through timestamp caching. Model-bearing generations retain full verification, including shared model objects. Query-duration leases and pointer transactions still select one coherent publication. Cleanup can reuse the same semantic validation while authenticating current bytes.

Semantic inputs are separate from lexical citation partitions. Ingest captures transient written declaration/heading seeds independently of optional facts, or derives them from full raw evidence for unqualified producers. Region-local coordinates are verified and converted into a required, versioned projection before detail filtering. The projection covers gaps and preserves native slabs and mapped regions even when Essential retains no facts; seeds themselves are not persisted. Retrieval uses bounded token windows and written context, coalesces short siblings within one owner/native location and preserves complete body coverage. An authenticated Tantivy `vector-map/` component binds graph nodes to occurrences and exact source members. Graph nodes may outnumber lexical chunks when a long chunk needs several windows. Search reconstructs each selected occurrence from its authenticated lexical members, returns the original body without synthetic context and counts that body once against the hit limit. When the byte budget requires a smaller window, query terms guide selection inside that body; a bounded source-map projection preserves mapped/native locations. Each lexical ordinal receives at most one semantic fusion vote, and member count does not multiply an occurrence's rank. Path-scoped fan-out, postings, decoded bytes and member counts are independently bounded with explicit truncation. A 64-member input bound can force additional windows for unusually fragmented display partitions; the semantic projection itself is independent of detail. See the [optimization plan and qualification ledger](indexingenhancements.md).

Vector queries use Microsoft DiskANN 0.59.0 construction/search algorithms with AIRK's independent provider reading bounded graph/vector records from local files. Embedding adapters support normalized static word vectors and bounded CPU ONNX BERT inference with an explicit WordPiece tokenizer, attention mask and pooling contract. Model assets are provisioned by trusted extension setup or an explicit native operator, license/digest-bound and retained as immutable collection-local objects. New publications authenticate fixed per-asset references; obsolete inline-model indexes require rebuilding. [Shared model ownership](v2-model-objects.md) defines quota, lease and GC behavior. Transformer plans are compiled lazily and retained with the pinned query cache; lexical/status calls do not compile a model. Missing/corrupt assets fail explicitly. Positive embeddings are retained in [immutable binary packs](embedding-cache-packs.md) with authenticated header/index and record digests, bounded index reuse, quota-charged compaction and receipt-owned live references. Numerical pipeline identity is independent of that storage format. Hybrid mode applies reciprocal-rank fusion to bounded lexical/vector lists from the same generation. See [local models](local-models.md) and [ONNX qualification](onnx-models.md).

Multiple agent connections read the same collection through separate MCP workers, sharing disk state and retaining independent caches. Read operations do not acquire the collection writer lock. Searches and lazy catalog handles pin immutable generations with operating-system reader leases; later operations refresh their selected generation without reconnecting. Explicit pruning skips active or leased generations, then retains every content-addressed object referenced by any surviving inventory. Collection removal acquires every generation lease and refuses active readers. [Shared-collection behavior](collections.md#multiple-agents-sharing-one-collection) explains configuration and multi-call revision limits.

Every evidence envelope carries collection, generation, hash and original source location. Payload budgets count text or names/paths; metadata/framing is additional. Reads use indexed bytes so citations cannot silently pair with changed live files. Freshness requires indexing. Native [coverage](index-coverage.md) uses shared ingest eligibility rules and content hashes, with explicit partial/failure/capacity counts. Inventory work is bounded and explicitly scheduled; ordinary MCP reads and footer repaints do not traverse sources.

## Scheduling, retention and scale

[The collection design](collections.md) combines disk-backed DiskANN, persistent Tantivy and exact structured facts. DiskANN is not a substitute for lexical or structural indexing. The provider's bounded record reads and synthetic recall tests do not establish larger-than-memory performance, physical SSD I/O, process RSS or production semantic quality.

One deployed container per user/machine stores independently scoped collections in one persistent volume. MCP clients use docker exec to create workers inside that host; caches remain per process. The [native scheduler](native-scheduler.md) persists indexing intents in SQLite and serializes work across a shared data root with an operating-system worker lock. Requested/completed revisions, full-rebuild requests, pause and failures survive helper exits. An explicit foreground watch worker drains the queue and periodically reconciles registered roots without an editor, retaining bounded scan watermarks. No operating-system service is installed automatically.

Native operation targets Windows, macOS and Linux with the same collection contracts. The extension remains a thin helper client: its debounce/idle/save controls batch notifications before native submission, and it displays coverage/usage without owning another index. Notifications still in the editor buffer are reconciled after reopening. Native writer locks and reader leases remain authoritative for publication and pruning.

[Searchable retention](retention.md) protects the active publication, zero to eight configured predecessors and live readers. Writer-only maintenance uses durable retirement intents and authorization proofs before detaching generations; object GC verifies surviving roots. Automatic policy can clean up before low-headroom builds and after publication, and allows one fresh publication attempt after typed quota pressure. Cleanup failure is reported separately from publication success. Idle scheduled workers and quiet editor intervals can continue pending cleanup; MCP reads and status repaints never trigger deletion. New collections default to automatic retention of the active generation only; saved policies remain authoritative, and legacy collections without a policy remain manual. Readers and selected history may retain additional data. Opt-in [historical content and checkpoints](v2-history-controls.md) retain exact committed evidence in separately authenticated lightweight packages. Historical file/info/context/outline reads never fall back to live or current bytes; historical search is unsupported.

[Storage quotas](storage-quotas.md) reserve shared root and per-collection logical bytes before participating writers grow files. Retrieval providers accept a neutral charging callback, preserving their dependency on core rather than store. Private SQLite catalogs have reserved page caps, while active-pointer, scheduler and usage journals retain explicit allowances. The ledger counts temporary and retained generations together, recovers abandoned reservation staging and refuses policy changes that revoke live allocations. Filesystem allocation overhead and external writers are outside this application quota.

Default quotas allow 100 GiB per collection within a 500 GiB root ceiling, preserving existing saved policies. Physical admission keeps additional headroom and tolerates bounded transient inventory races; physical free space remains a point-in-time observation. Live writer contention keeps scheduled indexing queued. Capacity failures block automatic retries until explicit recovery rather than allowing new events to restart the same failure loop.

[Explicit relocation](storage-relocation.md) freezes the shared root lifecycle and every writer/reader lease, hashes and verifies a private destination, then activates it using recoverable source/destination markers. Old managed state remains retained, and source workspaces are unchanged. Current clients fail closed on a retired or pending root; configuration must deliberately select the new destination. This preserves identity instead of silently rebinding a live collection.

Component construction streams retained artifacts individually; ingestion defaults to one extraction job and can use a bounded batch through `AIRK_EXTRACT_WORKERS=1..4`. Admission uses one eighth of detected memory capped at 4 GiB (512 MiB unknown), a 256 MiB coordinator allowance and 580 MiB per worker for source, parser and result/validation work. With four requested, 8/16/32 GiB machines admit 1/3/4 workers; default request remains one pending qualification. Native document expansion and sources above 4 MiB run serially. Queued, running and ready jobs together cannot exceed the admitted count, and results preserve the scan's captured order rather than worker completion order. No filename-sorting or cross-run discovery-order guarantee is implied. Shutdown closes channels and joins bounded in-progress work. These are admission heuristics, not RSS limits. Extraction work reporting sums per-job wall time rather than CPU time; binding and storage stay on the coordinator. See [worker limits](ingestion-limits.md#bounded-extraction-workers).

Compact inventory and optional producer analysis remain memory-resident within their metadata limits. Automatic [collection limits](ingestion-limits.md) independently use one eighth of detected memory, capped at 2 GiB eligible source (512 MiB if unknown), twice that for extracted text and four times that for pass reads. The largest automatic profile admits 256 MiB/source, 100,000 files and 1,000,000 discovery entries across aliases; explicit saved policies remain authoritative. Unsupported candidates still consume read/discovery budgets. Exhaustion retains the previous generation. Per-file extracted text is capped at 32 MiB, inventory at 512 MiB and individual extracted-object JSON at 256 MiB. UTF-8 sources above 4 MiB use explicitly partial text-only extraction to avoid expanding structured parser workloads. Native parsers are not forcibly preempted by the extraction pool; configured ceilings are not qualified workloads or hard wall-time guarantees. [Scale measurements](scale-qualification.md) distinguish actual evidence from permitted limits.

Further adapters belong inside their owning crates: ingest format/syntax adapters; store source blobs/manifests/publication/retention; retrieval lexical/vector/fusion; kernel scheduler/inspection; MCP fact contracts. Add another crate only for a real independent dependency boundary.

The native `tools` commands inspect the MCP router's schemas and invoke its existing server through an in-process, bounded duplex transport. This keeps dispatch, validation, result envelopes and usage accounting in the MCP adapter; the CLI adds argument-file parsing and an interactive console. The extension launches that console directly with the verified helper and fixed collection arguments in the Terminal panel. It does not interpolate commands into an operating-system shell or duplicate tool implementations.

[The code-indexing recommendation review](code-indexing-options.md) led to richer Tree-sitter facts, typed relationships, bundled SQLite and optional revision-bound SCIP imports. [The implementation contract](code-facts-and-relationships.md) documents producer/source/build binding, conservative invalidation and bounded queries, including explicitly invoked local LSP/Ctags adapters. Producer assertions remain distinct from native syntax and do not establish complete resolution. SQLite supplies exact structured evidence alongside Tantivy and DiskANN; no external code-graph engine implementation was adopted.

## Local usage and reporting boundary

[Local usage reporting](usage-reporting.md) uses core contracts, a bounded transactional store ledger and kernel estimation/report services. CLI/MCP serialization hooks record one observation per outer request. Aggregate counters are the default, scoped by collection/root binding without query/source content or external telemetry; diagnostic events require opt-in. The CLI exports JSON/CSV/Markdown and the extension displays the selected collection's report. Signed context estimates identify their baseline and response framing. Historical recording loss, provider consumption and billed savings remain unobserved; nonempty reports are labeled partial.

Version 1.1.3 adds one bounded cumulative native aggregate in the usage ledger, atomically updated with daily recording and cleared under the same lifecycle lock. Explicit session imports can associate bounded retained request IDs without retaining session names or query content. The extension renders those native reports and supplies guarded report controls. Content-free client-counter conversion and matched-task evaluation live in contributor scripts outside the kernel; no agent execution or external service is introduced. See [usage evaluation](usage-evaluation.md).

Version 1.1.4 stores per-source full-context JSON byte counts in each new immutable catalog. The `source-context-1` retrieval specification binds the additional rows to a distinct publication identity. Counts include nested MCP escaping and are reused only for unchanged sources from an authenticated previous catalog. Usage comparisons lease the exact response revision and read bounded size rows, retaining the existing component-integrity checks. Obsolete catalogs require rebuilding; absent or mismatched sources/revisions and limit failures become fixed reason counters, never live-source substitutions or fabricated savings. Conditional replies without an evidence payload are excluded from comparison.
