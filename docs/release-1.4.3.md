# AIRK 1.4.3 storage-recovery candidate

October 25, 2026. Unpublished Windows x64 local candidate, requested after the installed 1.4.2 storage failure. Native workspace, local crate lock entries, extension manifest and npm lock entries use **1.4.3**. The `service-1.4` namespace, project registrations, source/index locations, resource overrides and quota policies remain compatible. The [1.4.2 record](release-1.4.2.md) retains the preceding candidate's build and qualification evidence.

The service writer previously enforced a fixed 64 MiB WAL despite admitting much larger publications. Atomic replay could hit that cap and leave a recoverable Applying publication repeatedly failing with `sqlite_storage_full`, even with free disk space. WAL and shared-memory budgets now scale with admitted main-database capacity and are charged to a durable quota allowance before writer opening or recovery. Physical file and VFS enforcement remain in place. Reservations are conservative logical bounds, not preallocation; insufficient configured quota can still block admission.

Retained reads accept the preceding smaller allowance only under its original file/VFS bounds. The first upgraded writer enlarges the allowance before replaying preserved inputs. Capacity estimates now use SQLite's logical page count, including committed pages still in WAL, rather than checkpoint-dependent main-file lengths. No source/index deletion or forced reindex is used by this correction.

Generated regressions exercise a publication above the former WAL cap, interrupted Applying recovery with a pinned old snapshot, complete mapped-value verification, and legacy-grant upgrade.
