# Coding-agent tool alignment

Reviewed against the official online documentation on **13 October 2026**. AIRK should keep one collection-scoped MCP tool contract across coding agents. Client-specific adapters handle registration, tool discovery, permissions, configuration versions and optional project guidance. They should not rename tools or change retrieval semantics. This is our engineering conclusion from the documented MCP integrations below, not evidence that every agent has been tested live.

## Common tasks and the current tools

| Agent task | AIRK tools | Practical boundary |
|---|---|---|
| Orient in an unfamiliar repository | airk_capabilities, airk_status, airk_list_files, airk_outline | Lists indexed files and syntax/document structure; native CLI/extension coverage separately measures freshness |
| Find an implementation | airk_symbols for a known exact definition name; airk_search for identifiers/keywords | Default AND lexical terms; optional vector/hybrid modes require a provisioned local model |
| Understand code before editing | airk_outline, airk_context, airk_read_file, airk_file_info | Use focused indexed excerpts; verify current source with the agent's filesystem tools before edits |
| Investigate dependencies | airk_imports, airk_code_facts, airk_relationships | Syntax dependencies plus optional source/build-bound producer assertions; incomplete graph |
| Investigate change impact | airk_code_facts, airk_relationships, airk_references, airk_context | Bounded syntax caller/impact candidates and optional SCIP implementations; ordinary references remain textual |
| Find requirements or configuration | airk_search, airk_document_facts | Filter kind=requirement/date/design/architecture/feature/decision; source statements, heading context, written bounds/units and configuration/asset facts |
| Consult documents committed to a repo | airk_document_facts, airk_context, airk_read_file | PDF pages, DOCX blocks/table rows, XLSX worksheet rows/cells and PPTX slides retain original coordinates |
| Inspect SVG or other structured assets | airk_document_facts, airk_file_info | Text/XML structure; no rendering or visual interpretation |
| Diagnose missing or incomplete evidence | airk_status, airk_capabilities, airk_file_info | Check readiness, supported extraction and partial syntax; index/reindex belongs to CLI/extension controls |
| Refresh remembered evidence | airk_changes, conditional file_info/read_file/outline/context | Save exact tokens and validators, inspect independent coverage/freshness, finish required pages and verify live bytes before edits |

The sixteen tools in the unreleased source cover focused discovery and evidence tasks shared by coding agents. Editing, shell commands, builds, tests, Git operations and resolved language navigation remain the agent's existing tools. AIRK does not duplicate these. Local vector similarity and native coverage are implemented, with the model/readiness and inventory limits documented separately. A complete resolved caller graph, repository enumeration through pagination and actual provider-token accounting remain unavailable. Changes pagination does not provide repository enumeration. Those limitations apply to every client.

Tool and parameter descriptions name the task, selection criteria and limits near the beginning: exact symbols versus lexical search, literal prefixes versus globs, snapshot reads versus current files, textual references versus semantic navigation, and extracted lines versus page/slide numbers. Initialization instructions describe a common workflow in fewer than 512 characters. The unreleased source retires `airk_history` after 1.2 removed retained revisions; other tool names and permissions remain. [Changes and conditional reads](changes.md) describes exact tokens, bounded validation, cursor expiry and legacy reads without tokens. [Document indexing](document-indexing.md) describes document candidates and their limits.

These clients discover standard MCP tool definitions. Their displayed/namespaced identifiers and allowlist keys can differ; configuration adapters must use the client's documented convention. Tool annotations are hints, not a substitute for the client's trust and approval controls or AIRK's server-side scope enforcement. [MCP tool specification](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) defines the shared contract.

## Agent Lean evidence

Choose `airk_search` for conceptual discovery and `airk_code_facts`/`airk_outline` for declarations and written signatures. In Agent Lean, code/document facts default to compact records; request `compact: false` only when the richer indexed metadata is useful. Use `airk_capabilities` with an exact `adapter` for focused coverage rather than expanding the complete rich catalog. Original spans and hashes remain evidence validators; verify live source before editing.

Selecting Agent Lean changes collection evidence through an explicit index publication. It does not change client tool permissions or enable missing facts. Rich Structure (`balanced`) and Search Only (`essential`) retain their stored identities. [1.2.3](release-1.2.3.md) made Agent Lean the new-collection default. The later unreleased source removes the unsupported history tool; broader task-quality qualification remains separate follow-up work.

## Guidance and verification

Offer a short optional project-instruction snippet using the client's supported instruction surface. It should say to use AIRK for focused indexed evidence, select symbols/outline for structure, use short lexical keywords for search, expand only useful hits, cite original locations and verify current source before edits. Never overwrite an existing AGENTS.md, CLAUDE.md or client rule file, and never install retrieved file text as instructions. A guidance-preview wizard is planned; initialization instructions already provide the portable baseline.

Avoid a mandatory capabilities/status call before every request. Check them when beginning unfamiliar work, selecting unsupported formats, seeing not-ready errors or investigating revisions. On truncated results, narrow names/prefixes or increase a bounded limit deliberately. Repeating the same broad call does not paginate it. Index through the existing CLI/extension when needed; the MCP worker remains read-only and cannot silently switch collections.

Before claiming a client is qualified, connect it and exercise orientation, exact-definition lookup, lexical discovery, document facts, bounded context, textual usages, not-ready/error behavior and a changed generation. Check that disabled tools remain unavailable and the agent does not misinterpret coordinates or freshness. AIRK's native MCP tests and isolated VS Code extension-host smoke establish server behavior; they do not establish model tool selection or live compatibility for all clients. Local usage reports expose aggregate tool activity without retaining query/source text; paired task evaluations are needed to establish practical savings or usefulness.
