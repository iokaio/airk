# Third-party dependencies and design inspiration

AIRK includes no vendored source from Munarium, VCP or `temp/`. The [inspiration record](docs/inspiration.md) describes the design inputs.

Runtime/build dependencies are resolved by [Cargo.lock](Cargo.lock). Important direct families include Serde, Clap, Tokio, the official MCP Rust SDK, Tree-sitter/native grammars, Ignore, SHA-2, Tempfile, Quick-XML, Zip, PDF-Extract, CSV, Pulldown-Cmark and Regex. The exact catalog uses Rusqlite with bundled SQLite, pinned as described below; SCIP 0.10.0 and Protobuf 3.7.2 provide official format bindings, and URL normalizes project file URIs. Lexical retrieval uses FTS5 in the same bundled SQLite engine. Vector retrieval uses Microsoft's MIT-licensed DiskANN 0.59.0; AIRK supplies its own portable disk provider. Tantivy and dependencies used exclusively by its adapter are removed from the 1.3.0 dependency graph. Each dependency retains its own license terms. No external code-graph engine is bundled. AIRK 1.6.0 redistributes two INT8 exports of the sentence-transformers/all-MiniLM-L6-v2 ONNX weights and tokenizer at revision `10dbd2f06a8baf40ad285b037edda610c1b9a57c`, under the model publisher's Apache-2.0 declaration. The pinned catalog records asset digests and source provenance. The model license is retained in [third_party/models/minilm-LICENSE.txt](third_party/models/minilm-LICENSE.txt), embedded in the helper and included with catalog provenance in generated distribution notices. Custom models require their own recorded license and digest.

Rusqlite and libsqlite3-sys use upstream commit [`2a71e35d94b2a02f7dd4a0c4cfd59c339370e747`](https://github.com/rusqlite/rusqlite/commit/2a71e35d94b2a02f7dd4a0c4cfd59c339370e747), whose package versions are 0.40.1 and 0.38.1, with SQLite 3.53.3. The registry 0.40.2/0.38.2 pair bundles SQLite 3.53.2 and lacks the [extended-local-path Windows WAL locking fix](https://github.com/sqlite/sqlite/commit/2429af2e0ce2e4c643786f8d2533f79d974e3270). This exact source pin retains upstream MIT license texts and SQLite's public-domain notice; no upstream source is copied into AIRK. Replace the pin only with a bundle containing that fix and rerun the canonical long-path concurrency regression.

**Registry review, 2026-10-21 ([issue #32](https://github.com/iokaio/airk/issues/32)):** crates.io still lists 0.40.2 and 0.38.2 as the latest stable releases. The published `libsqlite3-sys` archive's SHA-256 is `f1d20bef17f513b9b3004532233187769cd072d790971f4e4da0e346eb6401e8`; its bundled source identifies SQLite 3.53.2. A registry-only replacement containing the required fix is therefore unavailable at this review date. The Git source remains pinned in both the manifest and lockfile pending a suitable published release; this finding is not recorded as fixed in 1.2.5.

Native filesystem events use Notify 8.2.0 (`CC0-1.0`) with Notify-Types 2.1.0 (`MIT OR Apache-2.0`), Linux Inotify 0.11.5 (`ISC`) and macOS FSEvent-Sys 4.1.0 (`MIT`) where applicable. Local ONNX inference uses the `ort` 2.0.0-rc.10 Rust adapter (`MIT OR Apache-2.0`) and Microsoft ONNX Runtime 1.22.1 CPU libraries (MIT). The runtime archive and every redistributed library/notice are pinned in `ort_runtime_catalog.json`; its original LICENSE and ThirdPartyNotices travel beside the helper. Hugging Face Tokenizers 0.23.2 (`Apache-2.0`) supplies local tokenizer processing. Their transitive dependency notices remain in the generated inventory, including native code notices shipped by tokenizer packages. Optional externally installed language servers, compiler providers and OCR executables are not bundled by these Rust dependencies and require their own distribution/license review if a distributor adds them.

[scripts/license-notices.py](scripts/license-notices.py) produces a locked dependency inventory with package/version/license/source and copies dependency license/notice files into a release bundle. The Docker build includes that bundle alongside AIRK's LICENSE and NOTICE. Native release packages must do the same. This Markdown page is an overview, not a substitute for third-party license text.

Repository-format extraction adds pinned Tree-sitter HCL 1.1.0 (Apache-2.0), Dockerfile-Updated 0.2.0, Proto 0.4.0, GraphQL 0.1.0, CMake 0.7.1 and Make 1.1.1 (MIT). These share the existing Tree-sitter 0.25.10 runtime. Dockerfile and Make omit license texts from their registry archives; their exact upstream revision texts and SHA-256 digests are pinned in `third_party/licenses/sources.json` and included in generated notices.

Composite extraction adds Cortexkit-Tree-Sitter-SCSS 1.0.1 and Tree-Sitter-Razor 0.1.0 (MIT), using the same Tree-sitter runtime. SCSS's omitted license text is pinned to its upstream revision under `third_party/licenses`; Razor includes its license in the crate archive. Neither dependency supplies a framework compiler or runtime.

The bundle also includes `bom.cdx.json`, a CycloneDX 1.6 SBOM of Cargo's resolved graph, including workspace, development, build and conditional-platform packages. It records package URLs, declared license expressions and dependency edges. It is not an inventory derived from a linked executable, an attestation, a vulnerability scan or a complete container/base-OS inventory.

Some registry packages omit standalone license texts. Pinned upstream texts and their exact URLs/digests are recorded under [third_party/licenses](third_party/licenses). The refresh script retrieves only legal records, not implementation source. The r-efi records include its pinned AUTHORS files, which contain MIT permission and copyright notices. The rsqlite-vfs text comes from its VCS-pinned parent workspace. WinAPI 0.4.0 target texts come from publication commit `9497609ef44cc9bcd16cd2411c0ee6ccaf5483aa`; all 1,389 i686 and 1,418 x86_64 distributed payload files match that commit's Git blob hashes, with package/version manifests matching too.

Where upstream supplies no separate text, the bundle preserves the publisher's package license/author declaration and flags it for release review. The remaining flagged packages are PDF-Extract, Adobe-CMap-Parser and Type1-Encoding-Parser. htmlescape left the resolved graph with the Tantivy removal first implemented in the unreleased 1.2.5 candidate; its dated provenance record below remains historical. Their inspected upstream trees contain no standalone legal file; substituting another project's copyright grant would be incorrect. Do not call this a completed legal release audit or fabricate copyright notices to fill gaps.

The October 18, 2026 review rechecked complete upstream Git trees at the four locked package revisions. All four still lack standalone texts. Their original publisher manifests match the downloaded crate archives byte-for-byte; exact URLs, SHA-256 values and the unresolved disposition are retained in [sources.json](third_party/licenses/sources.json) and included in generated declaration records. htmlescape 0.3.1 is now pinned to `1699b539179798e705ad8464128492a0a0092876`: all 12 distributed payload files match that revision's Git blob hashes, excluding Cargo's generated `.cargo-ok` marker. This is provenance verification, not legal approval or a replacement license grant.

Extension build tools are locked separately in [packages/vscode/package-lock.json](packages/vscode/package-lock.json). They include TypeScript, VS Code/Node API types, Microsoft's VSCE, and the MIT-licensed [esbuild](https://github.com/evanw/esbuild) 0.28.2 bundler with its platform binaries. These are development tools and are excluded from the VSIX.

The extension ships Microsoft’s MIT-licensed [jsonc-parser 3.3.1](https://github.com/microsoft/node-jsonc-parser) for targeted configuration edits that preserve JSON comments and unrelated settings. Its pinned runtime files and original `LICENSE.md` are explicitly staged under `node_modules/jsonc-parser`; parser development files are excluded.

The AIRK Explorer webview bundle `out/explorerWebview.js` includes [Preact](https://github.com/preactjs/preact) 10.29.8 (MIT, Copyright (c) 2015-present Jason Miller). The build places Preact's complete license text in that bundle's leading comment, and packaging refuses a bundle whose notice does not name the pinned version.

The VSIX also embeds the native helper's Rust dependency notice bundle and AIRK legal files.

Review the generated inventory for missing/custom licenses and distribution obligations before publishing. Regenerate it when dependencies change. Compiler/system libraries and base-image packages are separate distribution inputs requiring an SBOM/license review at release qualification.
