# Workbench intent model

The current 1.8.2 review asset is **intent-broader/5**, with feature specification 2 and explicitly confirmed learned proposals. Its selected fit uses **48,000 rows**, separate from the 96,000-row candidate pool. The [public exact datasets](data/README.md), [manifest](manifest.json), [qualification report](qualification-broader-v5.json), [exact replay receipt](replay-v5.json) and [fork guide](../../docs/parser-training.md) describe the inputs and measured limits.

`python tools/parser-train/train.py` rebuilds the historical smoke classifier into ignored local model storage using the pinned development dependencies in `requirements.txt`. Training is offline and uses original fictional templates, identifiers and paths; it does not read the user's workspace, clone repositories or retain source text. Expanded synthetic examples are saved locally under ignored `target/parser-train/data/` as hash-named JSONL files, in actual training order. A content-addressed copy under ignored `.parser-train/` survives `cargo clean`. Earlier corpora are preserved. `python tools/parser-train/retention.py` also retains vocabulary, candidate models, reports and sample manifests, excluding clones, source samples and native index state. Reviewed exact generated inputs are additionally included as deterministic gzip files under the narrowly allowed `data/` source directory. The manifest records the dataset path/hash/row count, seed, feature specification and exact asset digest. Python and Rust share feature goldens in `fixtures.json` and `fixtures-v2.json`.

The binary has a 96-byte little-endian header: eight magic bytes, four u32 specification/count fields, two i32 thresholds, the SHA-256 label-catalog digest and SHA-256 payload checksum. Its payload contains 65,536 × 13 signed int8 weights in bucket-major order and thirteen i32 biases. Feature specification 1 uses deduplicated hashed word unigrams/bigrams, boundary-marked character 3–5 grams and three shape flags. Specification 2 adds capitalized, CamelCase, snake-case, qualified-name and backtick flags. It retains specification-1 extraction and goldens; prediction selects the validated header's feature specification. FNV-1a hashes UTF-8 bytes into 65,536 buckets. Runtime accumulation uses i32 with bounded 4,096-byte input and stable label-index tie-breaking. There is no embedding layer or runtime training dependency.

The embedded local-review candidate is **not qualified for automatic intent execution**. Its exact asset identity and confirmation-only scope are in `manifest.json`; the initial 12,480-example smoke record remains in `manifest-smoke.json`. Historical public-vocabulary campaigns and the /2 review checkpoint remain identifiable in [qualification.json](qualification.json), [the initial record](qualification-initial.json), [qualification-broader.json](qualification-broader.json) and [TRAINING.md](TRAINING.md). No model was enabled for automatic learned execution. Runtime predictions supply suggestions after deterministic parsing abstains; explicit commands, validated recipes and explicit agent plans provide executable behavior.

Use `harvest.py --acquire` for the pinned sparse public checkouts, then `harvest.py --extract target/debug/airk.exe --sample` with a CLI built using `cargo build -p airk-cli --features parser-training --locked`. The development-only `dump-vocab` command does native extraction without vectors; the normal CLI excludes that command. `qualify.py` generates and saves all splits, compares 10k/20k/40k models on validation, selects calibration thresholds and measures the frozen candidate. `--development-only` skips final fixtures; `--promote` refuses unless every gate passes. Fit dependencies are pinned in `requirements.txt` and excluded from the product. Reproduction uses the retained exact vocabulary, repository pins, templates, dependency versions and seed; a fresh native index may have a different publication identity, which is recorded rather than rewritten.

Before enabling learned automatic execution, review the separately authored labels, improve rejection and enforce the design's acceptance floors. Calibration prioritizes at least 99.5% accepted-intent precision over coverage and records a missed 10% ask-rate target instead of weakening thresholds. The safety fixture measures raw classifier acceptance, not actual executions: runtime remains suggestion-only. Keep raw local corpora, clones and harvested vocabulary ignored. Only explicitly reviewed allowlisted generated examples, exact provenance records and licenses enter `data/`; source bodies and native state stay excluded. A promoted model requires a new asset/version identity and review of its manifest, attribution and shared goldens.

`python tools/parser-train/online.py` downloads only the pinned CodeSearchNet query resource and CLINC150 data with their licenses and READMEs. `online.lock.json` records exact revisions, URLs, attribution, sizes and SHA-256 hashes; reruns verify those pins. Downloads and licenses are retained locally under ignored `target/parser-train/online/` and `.parser-train/`. No upstream code corpus is downloaded. CoSQA was researched but not incorporated: its authors distinguish MIT implementation code from the dataset's Computational Use of Data Agreement.

`python tools/parser-train/broaden.py` fits the broader candidate and freezes a hash-named development report without evaluating the final fixtures. It groups original variants into phrase families, holds whole families out for validation/calibration, groups public search topics by normalized query, preserves CLINC's official train/validation/test separation, and excludes cross-split normalized duplicates and ambiguous self-description categories. Unsupported training targets are thirteen zeros: the runtime label catalog and feature format remain unchanged. `--evaluate PATH_TO_FROZEN_REPORT` evaluates the saved model without refitting or adjusting thresholds. The existing 150/repository/safety fixtures are regression measurements, not new blind tests. Run `python -m unittest discover -s tools/parser-train -p test_broaden.py -v` for split, calibration and rejection contracts.

The local-review asset is installed explicitly with `python tools/parser-train/install_review.py tools/parser-train/qualification-broader-v5.json --suggestions-only`. It checks measured accuracy, zero wrong accepted classifications on the retained 150-request fixture, repository/role/public rejection gates and integrity, preserves the previous binary and model records, and writes model-specific Python/Rust inference goldens. This installs an inert-proposal model, not an automatically executing classifier. The native runner still requires an explicit plan submission after a learned proposal. `train.py` saves smoke artifacts locally rather than replacing the reviewed product asset.

The **1.8.2 conversational follow-up**, recorded on 2026-11-01, adds whole-family split examples for `Find the`, `Tell me about`, `I want to know about` and related information requests. It varies type-before/type-after names, single-capitalized identifiers, snake case, qualified and quoted targets, topics and paired unsupported actions. `conversational.py` keeps these new families separate from the historical protocol-2 list. The initial /3 campaign recorded actual family/prefix/label counts, and a 62-row known conversational regression alongside the unchanged repository, 150-utterance and safety fixtures. Known regression text is excluded from fitting; those labels do not choose models or thresholds, and the fixture is not described as blind evaluation.

The offline /3 experiment improved conversational intent accuracy from 20/48 to 45/48 supported requests, but regressed the retained 150-utterance fixture from 146/150 to 143/150 and introduced one wrong accepted classification. The existing review installer refused it. [qualification-broader-v3.json](qualification-broader-v3.json) retains those results; the /2 asset was preserved at that checkpoint.

The subsequent **/4 review model** corrects conflicting generic-topic labels and uses feature specification 2. Generic untyped discovery trains as text retrieval; explicit types, declaration requests and quoted identifiers train as definition lookup. Its [qualification record](qualification-broader-v4.json) shows 47/48 correct supported conversational intents versus the prior model's 23/48 on the same policy-corrected known fixture. Retained 150-request accuracy is 142/150 versus 146/150, with zero wrong accepted classifications on both models. Curated unsupported acceptance improves from 1/20 to 0/20, while public unsupported acceptance increases from 4/1,000 to 5/1,000 and supported calibration abstention rises from 14.7% to 21.8%. The ask-rate gate still fails. This measured candidate was installed at that checkpoint for explicitly confirmed proposals only; **automatic learned execution remains disabled**. AIRK 1.8.2 handles supported simple conversational requests through bounded deterministic parsing, including symbol/text combination where needed. The model's raw accuracy does not establish complete plan correctness or a general latency/quality improvement.

The final **/5 role expansion** uses [476 original developer/writer/architect/QA cases](role-queries.json) and a [joint whole-family split map](role-phrase-splits-v5.json) spanning baseline, conversational and role sources. Validation selected 40k supported plus 8k unsupported fit rows from a 96k pool. The exact fitted file is [included compressed](data/broader-fitted-v5-696b34a3fb904217.jsonl.gz); its raw SHA-256 is `696b34a3fb904217bdd658eef3021758c058167b6efe026f5b253077a886150d`. All 323 eligible role source cases appear in the selected fit, supplying 27,704 of its 40,000 supported rows. Actual fitted prefix counts include 1,913 supported `Find the` and 386 supported `Tell me about` requests, plus paired unsupported cases. These are expanded examples, not that many independently authored phrase families.

On the same new role-family validation examples, /5 intent accuracy improves from /4's 83.50% to 97.95%; the calibration role subset improves from 79.79% to 92.23%. Retained 150-request accuracy is 144/150 with zero wrong accepted classifications. Curated/public unsupported acceptance is 0/20 and 0/1,000. Tradeoffs remain explicit: overall supported calibration abstention increases to **52.125%**, and known conversational intent accuracy falls from 47/48 to 40/48. These results do not qualify automatic learned execution; deterministic parsing handles supported common requests directly. [TRAINING.md](TRAINING.md) records all failures, per-role observations, the post-fit reporting recovery and exact replay.

After [verify/restore](data/README.md) and installing `requirements.txt`, `python tools/parser-train/fit-saved.py --report tools/parser-train/qualification-broader-v5.json` fits the exact selected bytes without vocabulary extraction or network access and requires the same asset digest. The [observed replay receipt](replay-v5.json) matches the installed /5 asset exactly. Add `--extra-training YOUR_ORIGINAL_EXAMPLES.jsonl` for a separate unqualified local experiment that preserves the product asset; see the [fork guide](../../docs/parser-training.md). Full corpus regeneration still uses the pinned vocabulary/query inputs.
