# Installer wrapper contract

The native setup role owns I4 operations, ownership, placement admission, recovery and readiness. Wrappers retain the same canonical operation and verified external setup image across prepare, placement and completion. They do not infer successful installation from file placement.

## Headless and failure boundary

All public wrappers accept exact `--silent`. This means no prompts or stdin reads; certificate trust defaults to skip. A required user-consent operation refuses with an actionable nonzero result. Existing platform silent aliases remain accepted. A failed post-placement setup or PATH update returns nonzero, even when the platform installer has placed files successfully. Windows reserves exit 11 for this finalization failure.

Before native execution, wrappers create a fresh private persistent recovery directory outside installer temporary storage. The verified setup image, operation request and native diagnostic paths survive failure. An existing folder is never adopted or recursively deleted. Canonical I4 JSON uses UTF-8 without BOM, compact field order and one trailing LF; ordinary Unicode remains literal. Native Core remains the schema owner.

Windows uses Inno Setup GetCustomSetupExitCode for sticky post-install failure; PrepareToInstall failures retain its native nonzero exit. See the [official event contract](https://jrsoftware.org/ishelp/topic_scriptevents.htm) and [silent flags](https://jrsoftware.org/ishelp/topic_setupcmdline.htm). Wrapper fixtures exercise compiled Inno events with inert payloads and isolated AppIds; they do not qualify native installed journeys.

After native completion and the PATH update, Windows invokes the native `--seal-inno` mode with the retained original operation request. Core's `airk-inno-handoff/1` binds the current I4 identities and both uninstaller EXE and DAT bytes; an EXE signature alone does not bind the compiled Pascal script. A seal failure is a finalization failure with exit 11. Inno 6.7.1 saves and closes its uninstall log before `ssPostInstall`; the compiled inert wrapper test compares both files at that event, `ssDone` and process exit. The native helper owns receipt validation and serialization; Pascal does not mirror its schema.

## Portable packages

Each of the four supported native targets has a separate portable ZIP. Its `runtime/` is the unchanged canonical C7 native candidate, preserving its complete roster. Root README.txt, manual.html and payload-inventory.json explain `airkctl service setup --portable --program <absolute runtime>` and existing service start/status/stop/uninstall. A strict portable manifest binds every packaged file except itself. The original native ZIP remains unchanged. The native CLI verifies the C7 pair, signatures and actual image bytes and passes the bounded inventory to the existing native setup owner. Portable setup does not add PATH, login startup or certificate trust.

From 1.9.0, portable recovery is `airkctl service setup --resume <absolute retained operation-request.json> --portable`. It uses the original request, roots and ownership; users must not edit its JSON, add location overrides, use a PID as authority or replay private native roles. Recovery preserves the original receipt on an unknown outcome. Native NTFS admission refuses extra alternate streams; wrappers do not implicitly strip streams or unblock files.

All wrappers require both empty native location-problem and blocker lists before preparation/placement. Headless macOS explicitly skips login startup as well as certificate trust; the service starts once, and startup after a later login remains an explicit supported/manual action. Windows and Linux retain user-level login startup defaults, which do not request OS consent. Optional native startup support is not inferred from a placed app bundle.

## Original-operation wrapper recovery

Standalone Linux and macOS wrappers accept `--resume <absolute original operation-request.json>` with no location, acknowledgement or setup-option overrides. Inno accepts `/AIRKOPERATION=<absolute original operation-request.json>` for installation or its original uninstaller for removal. The exact original installer payload must match the retained inventory. Core remains the only I4 decoder: the native setup owner authenticates original custody, admitted time, roots, receipt and exact inventory/image, then projects bounded UTF-8 scalar values through `--recovery-field`. Shells consume scalars as quoted data; Inno reads fixed native-written `recovery-<field>.txt` files only after successful helper exit. No wrapper edits or reserializes the request, extends its TTL or grants authority from a PID.

Native `placement-required` and `completion-required` are independent: unfinished placement resumes prepare/placement/completion; a durably placed and reverified candidate with unfinished native work skips replacement and resumes only completion; a successful native operation skips native replay and finishes only the owned PATH link or Windows PATH and EXE/DAT seal. An unfinished original trust request requiring consent refuses unattended recovery and directs the user to interactive recovery. Unix wrappers also resume original `airkctl` removal requests through `completion-required` and the same native removal owner; there is no separate OS tracked-file cleanup there.

Windows removal resumes the exact original uninstaller and matching DAT with `/AIRKOPERATION=... /AIRKRECOVERYIMAGE=...`. The retained image must match the wrapper's pinned executable digest; native admission independently verifies original custody. A native-reconciled closed successful removal skips native replay but still performs owned PATH and Inno tracked-file/registry cleanup. A new native success never substitutes for complete outer uninstaller cleanup. Partial failure retains the original request, full native recovery runtime, uninstaller pair and wrapper diagnostic. Fresh removal uses the existing native admission path; neither recovery projection nor a file name alone authorizes removal.


A native-owned producer lease spans preparation, file placement, native completion and outer wrapper cleanup. Unix wrappers use `--wrapper-lease-script <absolute current script>` to re-execute the verified wrapper with the exact original request, forwarding `--wrapper-silent` when needed. An inherited descriptor is accepted only through native exact-file/actual-lock proof (`wrapper-lease-held`), never an environment boolean; copying descendants retain it until their actual exit. Windows receives a native duplicated mutex handle for the protected current-user Global kernel object, not a caller PID or handwritten ACL. Inno acquires it with WaitForSingleObject(0), retains it through PATH/seal or tracked uninstaller cleanup and releases/closes it on deinitialization. Native validates the actual launching process ancestry/birth before transfer. Concurrent producers refuse rather than copying over each other; process death does not manufacture successful setup.

Unix original-operation recovery preserves the native UTF-8 scalar for all five roots byte-for-byte, including trailing LF. Shell capture appends a fixed suffix only after native success, removes exactly that suffix and assigns through an explicit five-name POSIX case; it performs no JSON parsing or eval. A native nonzero status, even after partial stdout, propagates before any root assignment. Empty transport values are preserved by capture and remain subject to the native path contract.
